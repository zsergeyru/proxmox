# 320 — фактическое состояние

Фактическое состояние снято с Proxmox 2026-09-12 и дополнено сведением об установленном Proximo MCP.

```text
VMID: 320
Proxmox name: ai-agent
status: running
vCPU: 2
RAM: 4096 MiB
system disk: 16 GiB
QEMU Guest Agent: enabled
network bridge: vmbr0
Proxmox firewall on net0: enabled
CPU type: x86-64-v2-AES
```

Технические названия параметров оставлены в виде, близком к фактическому выводу Proxmox.

Системный диск:

```text
local-lvm:vm-320-disk-0
size: 16 GiB
controller: virtio-scsi-single
```

К VM всё ещё подключён установочный ISO:

```text
local:iso/debian-13.6.0-amd64-netinst.iso
```

В фактическом выводе `qm config 320` параметр `onboot` отсутствует, то есть текущая VM не подтверждена как настроенная на автоматический запуск.

Это отличается от требуемого `guest.yaml`, где `boot.onboot: true`. Пока настройка на сервере не изменена, это считается известным расхождением между требуемым и фактическим состоянием.

## AI Control / Proximo MCP

На VM `320-ai-control` установлен основной MCP проекта:

```text
Proximo / proximo-proxmox
```

`320` уже переведён на Proximo и больше не считается узлом со старым сервером MCP.

Для Proximo действует та же проектная граница, что и для целевого `301`: операции уровня гостевых систем разрешаются только выданными токеном и ACL Proxmox; изменение самого PVE-хоста не входит в штатную область AI Control.

Действующая архитектура и ограничения находятся в [`../../docs/50-ai-control.md`](../../docs/50-ai-control.md), а точные права PVE — в [`../../docs/25-pve-access-control.md`](../../docs/25-pve-access-control.md). ADR в `decisions/` сохраняются как история решений конкретного временного узла и не являются основным источником текущих общепроектных прав.

Архитектурное имя каталога остаётся `320-ai-control`, а текущее имя объекта в Proxmox — `ai-agent`. Переименование работающей VM не требуется только ради документации; вопрос можно решить при миграции на целевой `301-ai-control`.
