# Решения по 410 ai-control

Этот файл хранит устойчивые решения, относящиеся только к `410 ai-control`.

## AI Control размещается в отдельной VM

AI Control работает в отдельной Debian VM и не устанавливается непосредственно на PVE.

Это позволяет независимо обновлять и восстанавливать AI-среду и технически ограничивать её доступ к инфраструктуре.

## 410 не входит в managed

`410 ai-control` не должен находиться в pool `managed`.

AI-агенты, работающие внутри этой VM, не должны иметь возможность штатным контуром остановить, удалить или перенастроить собственную VM.

Поэтому `guest.yaml` явно задаёт:

```yaml
pve_management: false
```

Жизненный цикл самой VM 410 выполняется внешним контуром развёртывания.

## AI-агент является заменяемым компонентом

Основным агентом на текущем этапе является Hermes.

Архитектура 410 не должна зависеть от одного агента. Общие средства доступа к Git, Proxmox, SSH и инфраструктурным исполнителям принадлежат AI Control, а не каталогу конкретного агента.

## Инфраструктурные исполнители не дублируются в 410

OpenTofu, управляющий Ansible и Packer размещаются в `910 infra-deployer`.

410 отвечает за AI-логику, анализ и выбор действия, а повторяемое инфраструктурное выполнение передаёт специализированному контуру 910.

Это не запрещает 410 использовать SSH для диагностики и разовых действий или обращаться к разрешённому Proxmox API напрямую там, где такая операция относится к AI-контуру.

## Git read и Git write разделены

Для штатной работы 410 требуется read-only доступ к закрытому репозиторию проекта.

Право отправлять изменения в GitHub не следует автоматически из права чтения и оформляется отдельно, если оно действительно понадобится.

## Голосовые и другие общие AI-сервисы не размещаются в 410

STT, TTS и другие общие сервисы, которыми пользуются несколько систем, не являются частью AI Control.

Они должны жить в отдельном госте соответствующей функциональной области. Перезапуск 410 не должен останавливать общие голосовые функции.

## Требуемое содержимое описывает provision.yaml

`provision.yaml` фиксирует состав ОС, структуру AI Control, внешние интеграции, постоянные данные и границы гостя.

Конкретная реализация повторяемой настройки относится к Ansible или другому принятому механизму конфигурации гостевых ОС.
