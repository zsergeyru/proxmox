# ADR 001 — Ansible и Semaphore в `311-dev-services`

## Статус

Принято.

## Контекст

Для повторяемого развёртывания конфигурации из `rootfs/` нужен готовый инструмент, чтобы не писать собственный deploy-механизм с учётом копирования файлов, прав, удаления, перезапуска сервисов и проверки результата.

Ansible и Semaphore не являются AI-компонентами. Поэтому они не должны постоянно размещаться внутри `301-ai-control` или в каталоге `agents/`.

## Решение

`311-dev-services` является целевым местом для DevOps-инструментов развёртывания:

- Ansible — штатный механизм повторяемого применения конфигурации внутри VM/LXC через SSH;
- Semaphore — web-интерфейс к Ansible для ручного запуска, истории и логов;
- Gitea/Gogs, Jenkins и другие CI/CD-инструменты также относятся к этому гостю.

Ansible и Semaphore целесообразно запускать в Docker внутри `311-dev-services`. На управляемые VM/LXC отдельный Ansible-agent не устанавливается: транспортом остаётся SSH.

## Разделение ответственности

```text
301-ai-control
  Hermes / AI-агенты
  Proxmox MCP
  Git/API/SSH-клиенты
        │
        │ инициирует повторяемое развёртывание
        ▼
311-dev-services
  Ansible
  Semaphore
        │
        │ SSH
        ▼
101 / 211 / 301 / 321 / 331 / 401 / ...
```

Proxmox MCP остаётся инструментом уровня виртуализации:

- создание VM/LXC;
- CPU/RAM/disk/network;
- start/stop/reboot;
- snapshots/backups;
- lifecycle гостя.

Ansible отвечает за повторяемые изменения внутри ОС гостя:

- пакеты;
- каталоги и файлы;
- `systemd`;
- Docker/Compose;
- конфигурацию приложений;
- запуск/reload/restart;
- проверки результата.

Прямой SSH из AI Control сохраняется для bootstrap, диагностики, разовых административных действий и аварийных сценариев. Для повторяемого deploy предпочтителен Ansible.

## Кто использует Semaphore

Semaphore предназначен прежде всего для человека. Он даёт web-интерфейс для запуска тех же Ansible playbook, просмотра истории, результата и логов.

Типовой ручной путь:

```text
пользователь
→ Semaphore
→ Ansible
→ SSH
→ нужный гость
```

Semaphore не является обязательным промежуточным слоем для Hermes. Отказ или остановка Semaphore не должны мешать AI Control инициировать Ansible другим предусмотренным способом.

## Простая модель `rootfs/`

Не вводится собственная база управляемых файлов, `managed-files.txt` или отдельный deploy-MCP.

Используются простые правила.

### Каталоги, полностью принадлежащие проекту

Выделенные каталоги, созданные специально под наш сервис, можно синхронизировать целиком с удалением отсутствующих в Git файлов.

Например:

```text
rootfs/opt/app-services/
→ /opt/app-services/
```

Для такого каталога допустим эквивалент `rsync --delete`, потому что весь целевой каталог считается управляемым проектом.

### Общие системные каталоги

Файлы в `/etc`, `/usr/local/bin` и других общих системных каталогах устанавливаются только по конкретным путям.

Например:

```text
rootfs/etc/nftables.conf
→ /etc/nftables.conf

rootfs/etc/systemd/system/example.service
→ /etc/systemd/system/example.service
```

Нельзя синхронизировать целиком `/etc` или другой общий системный каталог с удалением лишних файлов.

Удаление отдельного системного файла выполняется явной Ansible-задачей только тогда, когда его действительно решили удалить.

### Запрещено

Никогда не использовать глобальную зеркальную синхронизацию вида:

```text
rootfs/ → /
```

с удалением файлов назначения. В частности запрещён эквивалент:

```bash
rsync --delete rootfs/ /
```

### Persistent data и секреты

Базы данных, Docker volumes, записи Frigate, пользовательские данные и другое runtime/persistent data не являются содержимым `rootfs/` и резервируются отдельно.

Пароли, tokens, private keys и другие секреты в Git не хранятся.

## Bootstrap до появления `311`

Пока `311-dev-services` ещё не развёрнут, текущий `320-ai-control` может продолжать выполнять необходимые bootstrap-операции напрямую по SSH. Это временный способ запуска инфраструктуры, а не целевое место размещения Ansible.

После запуска `311` Ansible и Semaphore не должны переноситься внутрь `301-ai-control`: AI Control инициирует работу, а DevOps-инструменты остаются в `311-dev-services`.
