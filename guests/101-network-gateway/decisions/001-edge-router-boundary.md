# ADR 001 — граница ответственности edge-router и 101-network-gateway

Статус: **принято**.

## Контекст

После переезда сеть квартиры будет разделена как минимум на MAIN, IOT и CAMERAS. Ранее оставалось открытым, будет ли `101-network-gateway` одновременно выполнять роль L3-шлюза локальных VLAN или эти функции останутся на физическом edge-router.

Если локальные VLAN зависят от VM 101, остановка Proxmox или этой VM лишает квартиру базовой межсетевой маршрутизации и firewall. При этом DNS/VPN/PBR удобнее реализовывать на обычном Debian-сервере, чем на домашнем роутере.

## Решение

Физический edge-router на OpenWrt является базовым L3-шлюзом локальных сегментов и владельцем их адресов `.1`:

```text
MAIN / native     → 10.0.0.1/16
IOT / VLAN 20     → 10.20.0.1/16
CAMERAS / VLAN 30 → 10.30.0.1/16
```

На edge-router остаются:

- WAN и NAT к провайдеру;
- termination локальных VLAN;
- DHCP для клиентских сегментов;
- базовая inter-VLAN routing/firewall policy;
- аварийный административный VPN/доступ при необходимости.

`101-network-gateway` остаётся специализированным сетевым сервисным узлом. На нём находятся:

- SmartDNS и `home.arpa`;
- DoH/DoT и выбор upstream DNS;
- исходящие AmneziaWG/WireGuard/другие VPN;
- policy-based routing через `nftables` + `fwmark` + `ip rule`;
- sing-box только для сценариев, где нужен proxy/outbound;
- основной remote-access VPN;
- mDNS reflector между явно разрешёнными сегментами при необходимости;
- health-check/watchdog сетевых сервисов.

`101` не является обязательным default gateway для MAIN/IOT/CAMERAS. При остановке `101` обычный интернет и базовая маршрутизация локальной сети должны продолжать работать через OpenWrt; недоступными могут стать только сервисы, которые сознательно зависят от `101` (специальный DNS/PBR/VPN).

## PBR между OpenWrt и 101

Точный механизм перенаправления выбранного трафика на `101` реализуется при развёртывании второго этапа сети. Допустимы policy route на OpenWrt, явное использование `101` отдельными клиентами/сетями или другой простой вариант без превращения Proxmox bridge в маршрутизатор.

При выборе реализации обязательны:

- отсутствие routing loop;
- понятный аварийный bypass `101`;
- один очевидный владелец default route каждого сегмента;
- сохранение доступа к Proxmox при недоступности VM 101.

## IPv6

DHCPv6-PD, Router Advertisement и базовый IPv6 firewall локальных VLAN по умолчанию принадлежат физическому edge-router. `101` обрабатывает IPv6 только в пределах собственных DNS/VPN/PBR-функций, если отдельный сценарий не потребует иного.

## Следствия

- адреса `.1` локальных VLAN больше не считаются адресами интерфейсов VM 101;
- `101` получает обычный management/service IP в MAIN, выбираемый отдельно;
- отказ Proxmox не должен отключать базовый L3 квартиры;
- сложная логика DNS/VPN/PBR остаётся на Debian и может развиваться независимо от OpenWrt.
