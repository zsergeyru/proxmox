# Host backup

## Фактическое состояние на 2026-09-12

На Proxmox уже существует storage:

```text
name: backup
type: dir
path: /mnt/pve/backup
content: backup
```

Физический носитель — USB Kingston DataTraveler около `58 GiB`, `ext4`.

На момент снимка:

```text
total: ~56.5 GiB
used: ~19.7 GiB
available: ~33.9 GiB
```

Таким образом USB backup storage уже фактически используется, но не считается единственным или окончательным backup-хранилищем.

## Что уже есть

- отдельный Proxmox storage `backup`;
- USB-носитель отделён от основного NVMe;
- у VM 100 существует snapshot `good_restore`;
- ранее создавался полноценный backup HAOS VM 100.

Snapshot не считается заменой полноценному backup.

## Принятое ближайшее решение

Планируется добавить отдельный SMB/CIFS storage на обычном компьютере и использовать его как основную внешнюю копию Proxmox backup.

Текущий USB storage при этом сохраняется как дополнительная локальная копия и аварийный вариант.

Важно: SMB storage пока только запланирован и ещё не является частью наблюдаемого состояния этого хоста. Компьютер с общей папкой должен иметь стабильный IP и быть включён во время задания backup.

Отдельный NAS и Proxmox Backup Server на этом этапе не вводятся.

## Что нужно проверить

В снятом `/etc/fstab` отсутствовала запись для USB-раздела `/mnt/pve/backup`. Нужно отдельно выяснить, каким механизмом накопитель монтируется после загрузки и гарантированно ли storage возвращается после reboot.

До проверки нельзя считать automount USB backup полностью задокументированным и воспроизводимым.

Также остаются открытыми задачи:

- создать и проверить SMB/CIFS storage на компьютере;
- определить расписание backup;
- определить retention для SMB и USB;
- определить, какие гости и persistent data копируются обязательно;
- выполнить практическую проверку восстановления из backup;
- позднее решить, нужен ли отдельный NAS или Proxmox Backup Server.

Общая backup-политика проекта находится в [`../../../docs/22-storage-and-backup.md`](../../../docs/22-storage-and-backup.md).
