# Host network

## Фактическое состояние на 2026-09-12

Основной bridge хоста:

```text
vmbr0
address: 192.168.1.11/16
gateway: 192.168.1.1
bridge-port: nic0
STP: off
forward delay: 0
```

Маршруты:

```text
default via 192.168.1.1 dev vmbr0
192.168.0.0/16 dev vmbr0 src 192.168.1.11
```

Физический uplink:

```text
interface: nic0
controller: Realtek RTL8111/8168 family
speed class: 1 GbE
driver: r8169
```

Также в системе есть Intel Wi-Fi AX101 (`wlo1`), сейчас интерфейс выключен и в bridge не используется.

В `/etc/network/interfaces` присутствует строка `iface nic1 inet manual`, но фактический интерфейс `nic1` в выводе `ip -br link` отсутствует. Перед переносом или генерацией конфигурации эту строку нужно проверить; не считать `nic1` реально существующим интерфейсом только по конфигу.

## Текущая DNS-конфигурация хоста

```text
search home.arpa
nameserver 192.168.1.1
```

Сейчас DNS-запросы хоста идут на Keenetic `192.168.1.1`. `home.arpa` уже используется как DNS search suffix.

Архитектура внутреннего DNS и mDNS зафиксирована в [`../../../docs/dns.md`](../../../docs/dns.md).

## Целевая миграция

Текущая сеть `192.168.0.0/16` пока остаётся рабочей. Целевая MAIN-сеть новой архитектуры — `10.0.0.0/16`, а постоянный целевой адрес PVE планируется как:

```text
10.0.0.10/16
```

Переход выполняется по плану из [`../../../docs/network.md`](../../../docs/network.md): текущая `192.168.*` адресация сохраняется на переходный период, а новые `10.0.*` адреса вводятся параллельно без резкой замены всей сети.

Фактический текущий management IP до отдельного изменения остаётся:

```text
192.168.1.11
```
