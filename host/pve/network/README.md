# Host network

## Фактическое состояние на 2026-09-12

Основной bridge хоста:

```text
vmbr0
address: 192.168.1.11/16
gateway: 192.168.1.1
bridge-port: nic0
STP: off
forward delay: 0
```

Маршруты:

```text
default via 192.168.1.1 dev vmbr0
192.168.0.0/16 dev vmbr0 src 192.168.1.11
```

Физический uplink:

```text
interface: nic0
controller: Realtek RTL8111/8168 family
speed class: 1 GbE
driver: r8169
```

На сервере используется одна физическая Ethernet-карта. Текущая архитектура и будущая VLAN-схема специально рассчитываются на этот единственный Ethernet-порт; добавление второй сетевой карты не является частью принятого плана.

Сейчас `nic0` одним обычным Ethernet-соединением без VLAN подключён к LAN-порту Keenetic. Компьютеры и Proxmox подключены к разным физическим LAN-портам Keenetic, но находятся в одной и той же локальной сети/L2-сегменте. Отдельной серверной подсети или маршрутизации между компьютерами и сервером сейчас нет. Отдельно существует WAN-интерфейс Keenetic для выхода в интернет.

Также в системе есть Intel Wi-Fi AX101 (`wlo1`), сейчас интерфейс выключен и в bridge не используется.

В `/etc/network/interfaces` присутствует строка `iface nic1 inet manual`, но фактический интерфейс `nic1` в выводе `ip -br link` отсутствует. С учётом подтверждённой однопортовой схемы `nic1` не считается частью архитектуры. Перед удалением строки из рабочего конфига достаточно контрольной проверки фактических интерфейсов; после неё запись можно считать остаточной.

## Текущая DNS-конфигурация хоста

```text
search home.arpa
nameserver 192.168.1.1
```

Сейчас DNS-запросы хоста идут на Keenetic `192.168.1.1`. `home.arpa` уже используется как DNS search suffix.

Архитектура внутреннего DNS и mDNS зафиксирована в [`../../../docs/dns.md`](../../../docs/dns.md).

## Два этапа сетевой архитектуры

### Этап 1 — до переезда

Proxmox работает по одному физическому Ethernet-порту в общей домашней LAN Keenetic. VLAN на этом этапе не требуются.

`101-network-gateway` разворачивается уже на этом этапе и находится в той же LAN, что компьютеры и другие доверенные устройства. Он предоставляет сетевые сервисы: DNS, исходящие VPN, remote-access VPN, PBR, firewall и связанные функции. Keenetic остаётся физическим edge-router и WAN-шлюзом.

### Этап 2 — после переезда

Тот же единственный `nic0` используется для будущей VLAN-схемы. По одному физическому соединению может передаваться VLAN trunk, а `vmbr0` становится VLAN-aware для подключения нужных VM/LXC к MAIN/IOT/CAMERAS и другим сегментам.

Вероятный edge-router после переезда — OpenWrt, но это пока не окончательное решение. Точное разделение функций между OpenWrt и `101-network-gateway` определяется отдельно перед миграцией. Вторая физическая NIC для этой схемы не требуется.

## Целевая миграция

Текущая плоская LAN `192.168.0.0/16` пока остаётся рабочей. Целевая MAIN-сеть новой архитектуры — `10.0.0.0/16`, а постоянный целевой адрес PVE планируется как:

```text
10.0.0.10/16
```

Переход выполняется по плану из [`../../../docs/network.md`](../../../docs/network.md): до переезда сохраняется одна общая LAN без VLAN, сетевые сервисы подготавливаются заранее, а после переезда поверх того же единственного Ethernet-порта вводится целевая VLAN-архитектура.

Фактический текущий management IP до отдельного изменения остаётся:

```text
192.168.1.11
```
