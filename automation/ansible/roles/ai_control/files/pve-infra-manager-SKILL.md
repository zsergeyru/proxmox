# Управление гостями через infra-manager

Для взаимодействия с PVE **не используй root SSH, PVE API, pct, qm или произвольные команды Linux на PVE**. Используй только этот ограниченный инструмент, установленный рядом с навыком:

```bash
python3 /opt/data/skills/infra-manager/pve-infra-manager.py guests
python3 /opt/data/skills/infra-manager/pve-infra-manager.py status
python3 /opt/data/skills/infra-manager/pve-infra-manager.py status 340
python3 /opt/data/skills/infra-manager/pve-infra-manager.py test 340
```

Для изменения разрешённых управляемых гостей доступны `deploy VMID`, `sync VMID`, `repair VMID`. Эти команды **не выполнятся**, пока оператор отдельно не одобрит конкретную команду и номер гостя на PVE: `infra-manager agent-approve ОПЕРАЦИЯ VMID`. Подтверждение действительно один запуск и пять минут. Нельзя самостоятельно одобрять операции, предлагать выполнять аварийное восстановление или раскрывать файлы идентичности. Если PVE отказал в доступе — сообщи причину и запроси действие оператора, не обходя запрет.

Вывод статуса может содержать диагностические данные; никогда не отправляй содержимое файлов `identity.json` или `ca.crt` в диалог. Перед опасными изменениями объясни, что изменится, и дождись явного решения оператора. Развёртывание и постоянная настройка по-прежнему выполняются штатным механизмом 910, а не командами внутри VM.
