# Home Proxmox Infrastructure

Репозиторий конфигурации, кода и документации домашней серверной инфраструктуры на Proxmox VE.

## Аппаратная платформа

- Intel N150 mini-PC
- 16 GB RAM
- M.2 SSD 512 GB
- Proxmox VE

## Основной принцип

Репозиторий организован вокруг гостей Proxmox: всё, что относится к конкретной VM/LXC, хранится в `guests/<VMID>-<name>/`. Общие решения, правила и архитектура находятся в `docs/`.

По умолчанию используется **один monorepo `proxmox`**. Конфигурация гостя, Docker Compose, системные файлы, скрипты и собственный программный код сервисов, предназначенных только для этой инфраструктуры, хранятся в этом репозитории рядом с соответствующим гостем.

Отдельный Git-репозиторий создаётся только тогда, когда компонент действительно становится самостоятельным продуктом: используется несколькими независимыми проектами, имеет отдельный жизненный цикл и релизы, публикуется отдельно или должен развиваться независимо от домашней Proxmox-инфраструктуры.

VM/LXC не обязаны клонировать весь этот репозиторий. Управляющий контур разворачивает на конкретного гостя только относящиеся к нему файлы и сервисы.

## Структура репозитория

```text
proxmox/
├── README.md
├── docs/                 # общая архитектура и решения
├── host/pve/             # конфигурация самого Proxmox-хоста
├── guests/               # VM/LXC: документация, конфигурация и локальный код
├── ansible/              # inventory, roles, playbooks и deploy
├── scripts/              # повторяемые служебные операции
├── templates/            # шаблоны VM/LXC и конфигураций
└── archive/              # устаревшие материалы, оставленные для истории
```

Типовая структура конкретного гостя:

```text
guests/<VMID>-<name>/
├── README.md
├── guest.yaml            # описание гостя и правила deploy, когда будет введён формат
├── files/                # файлы, разворачиваемые в системные пути гостя
└── services/             # код и файлы сервисов, относящихся к этому гостю
```

`files/` используется для файлов, которые должны попадать в конкретные пути файловой системы гостя. Например `files/etc/example.conf` разворачивается как `/etc/example.conf`.

`services/` используется для собственного программного кода и файлов отдельных сервисов этого гостя. Например `guests/320-ai-control/services/deploy-mcp/` может содержать исходники, `Dockerfile`, зависимости и тесты `deploy-mcp`.

## Правило для конфигурации и кода

Git должен быть источником истины для повторяемой конфигурации и собственного инфраструктурного кода.

Основные правила:

- не клонировать весь `proxmox` на каждую VM/LXC только ради deploy;
- разворачивать на гостя только его файлы и сервисы;
- код, относящийся только к конкретному гостю/сервису, по умолчанию хранить в этом monorepo;
- отдельные репозитории создавать только при появлении реальной независимости компонента;
- секреты, токены и пароли в репозиторий не добавлять.
