# Восстановление 310 Gogs

**Тип:** локальная инструкция. **Статус:** целевое состояние.

## Источники и границы

В GitHub хранятся манифест гостя, Ansible-роль, образ с закреплённым
digest, шаблон Compose и проверка. Секреты, SQLite, репозитории,
вложения и пользовательские настройки находятся исключительно на
постоянном томе `gogs_data` размером 30 ГиБ.

`infra-manager deploy 310` никогда не должен:
- очищать или форматировать **существующий** том;
- создавать пользователей либо пустую базу вместо утраченной;
- сбрасывать существующий `SECRET_KEY`, пароли и SSH-идентичности;
- переключаться на новую сборку Gogs без изменения закреплённого digest.

Проверять подключение тома до запуска службы; одного каталога
`/var/lib/gogs` недостаточно.

## Сценарии

| Сбой | Действие |
|---|---|
| Упал контейнер или сломалась воспроизводимая настройка | `infra-manager deploy 310` повторно готовит Docker, проверяет данные и поднимает Gogs |
| Удалён LXC, постоянный том сохранился | `recreate_if_missing: true` допускает безопасное пересоздание, повторное подключение тома, настройку и запуск |
| Потерян том или повреждена SQLite | **Не запускать Gogs**. Восстановить сохранённый каталог `/data` согласованным комплектом с независимого носителя; повторить подготовку и `deploy 310` |
| Пропал `app.ini` вместе с секретом | Остановиться, восстановить файл из независимой копии; не создавать новый ключ |
| Перенос на другой образ | Только отдельное тестирование на копии и явное изменение закреплённого digest; перед понижением версии сохранять исходную SQLite и проверять схему |

При исчезновении существующего тома общий механизм PVE может создать
новый пустой том с тем же именем, **но** роль Gogs не примет его как
восстановленный и не запустит пустое приложение. Новую базу разрешено
создавать только в отдельной явной процедуре новой установки, не в
аварийном развёртывании 310.

Для копирования SQLite резервный комплект должен быть согласованным:
остановить Gogs на время копии либо использовать штатную копию SQLite
совместно со снимком репозиториев. Не копировать один лишь `gogs.db`,
оставив несовместимое содержимое репозиториев. Резервировать
`/mnt/bindmounts/gogs-data/310-gogs` с учётом файлов SQLite WAL,
секретов и прав. Резервная копия — вне физического SSD PVE;
ориентир: ежедневно, семь ежедневных и четыре еженедельных копии.

Проверить восстановление на чистой машине отдельно. Сценарий
`infra-manager deploy 310` **не выбирает автоматически** резервные
копии при потере тома и не заменяет операцию восстановления данных.
