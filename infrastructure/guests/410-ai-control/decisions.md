# Решения по 410 ai-control

Этот файл хранит устойчивые решения, относящиеся только к `410 ai-control`.

## 410 является центральным AI-контуром квартиры

410 используется не только для работы с Proxmox.

Его назначение — быть центральной рабочей средой AI-агентов, которые помогают жильцам и пользователям квартиры, наблюдают за состоянием систем, анализируют события и используют разрешённые механизмы управления.

410 может координировать работу с Home Assistant, инфраструктурой, домашней сетью, мониторингом и другими сервисами, но не заменяет их внутренние механизмы.

## AI Control размещается в отдельной VM

AI Control работает в отдельной Debian VM и не устанавливается непосредственно на PVE.

Это позволяет независимо обновлять и восстанавливать AI-среду и отдельно ограничивать её полномочия.

## 410 не входит в managed

`410 ai-control` не должен находиться в pool `managed`.

AI-агенты внутри 410 не должны иметь возможность обычным инфраструктурным контуром остановить, удалить или перенастроить собственную VM.

Поэтому `guest.yaml` явно задаёт:

```yaml
pve_management: false
```

Жизненный цикл самой VM 410 выполняется внешним контуром.

## Один основной агент вместо набора специализированных

В штатной конфигурации 410 работает один основной универсальный агент.

Home Assistant, инфраструктура, сеть, мониторинг и другие функциональные области подключаются к нему как инструменты и интеграции. Для каждой области не создаётся отдельный агент.

Основным агентом на текущем этапе является Hermes. Архитектура не должна зависеть от Hermes, поэтому его можно заменить другим программным агентом.

Дополнительные агенты допускаются только тогда, когда появляется реальная необходимость в независимой параллельной работе или в другом специализированном программном движке.

## Web-интерфейс является обязательным

410 должен иметь Web-интерфейс как основную точку взаимодействия пользователя с AI Control.

Через него выполняется диалог с основным агентом, просмотр задач, событий, уведомлений, состояния интеграций и подтверждение действий.

Web-интерфейс не должен иметь отдельный набор полномочий и логики управления. Он использует то же ядро AI Control, что и другие будущие интерфейсы.

## AI-модель является заменяемым ресурсом

AI Control не привязывается к одной модели или одному поставщику.

Он должен уметь использовать:

- локальную модель на другом компьютере или сервере квартиры;
- внешнюю модель через API;
- разные модели для разных типов задач.

Выбор модели учитывает качество, скорость, стоимость, доступность и требования к конфиденциальности.

Полномочия определяются инструментами и техническими идентичностями, а не выбранной моделью.

## Специализированные сервисы остаются отдельными

Home Assistant, сетевые сервисы, мониторинг, STT/TTS, NVR, серверы моделей и другие самостоятельные системы не должны переноситься в 410 только ради удобства AI.

AI Control взаимодействует с ними через разрешённые интерфейсы.

Это позволяет сохранить базовую работу квартиры даже при остановке или обновлении 410.

## Инфраструктурные исполнители не дублируются в 410

OpenTofu, управляющий Ansible, Packer и Semaphore находятся в `910 infra-manager`.

410 отвечает за понимание задачи, анализ, выбор действия и проверку результата.

Повторяемые инфраструктурные операции передаются 910.

410 не получает штатный root SSH к физическому PVE и не должен иметь прямой PVE API token для выполнения инфраструктурных изменений.

## AI не является универсальным root-доступом

Доступ AI к системам должен предоставляться по назначению.

Предпочтение отдаётся ограниченным инструментам и профильным интерфейсам.

Наличие технической возможности выполнить произвольную команду не означает, что такой путь является штатным.

Критичные границы должны обеспечиваться ACL, ролями, техническими идентичностями и другими внешними средствами.

## События сначала обрабатываются обычными правилами

AI Control должен наблюдать за важными событиями квартиры и сервисов, но модель не должна обрабатывать каждый технический сигнал.

Предпочтительная последовательность:

```text
событие
→ фильтр
→ обычное правило
→ при необходимости AI-анализ
→ действие или уведомление
```

Базовые функции дома не должны зависеть от постоянной доступности AI-модели.

## Git read и Git write разделены

Для штатной работы 410 требуется доступ к репозиторию проекта на чтение.

Право отправлять изменения в Git является отдельным полномочием и предоставляется только при наличии конкретной необходимости.

## Требуемое содержимое описывает provision.yaml

`provision.yaml` фиксирует состав ОС, структуру AI Control, постоянные данные и границы гостя.

Права на внешние системы задаются через `infrastructure/security/access.yaml`.

Повторяемая настройка реализуется принятыми средствами конфигурации гостевых систем.
