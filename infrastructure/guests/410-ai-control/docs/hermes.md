# Hermes на 410

**Тип:** локальная спецификация службы  
**Статус:** целевое состояние  
**Назначение:** определить Hermes как основной агент и агентную среду 410.

## 1. Роль и версия

### 1.1. Назначение

Hermes выполняет функции, для которых ранее рассматривалось отдельное самописное ядро AI Control:

- агентный цикл;
- OpenAI-совместимый API;
- сессии и память;
- cron;
- skills;
- MCP;
- инструменты;
- вызов локальных и внешних моделей;
- делегирование подзадач;
- механизмы подтверждения опасных операций.

Поэтому отдельный оркестратор между Open WebUI и Hermes не создаётся.

### 1.2. Развёртывание

Используется официальный Docker-образ:

```text
nousresearch/hermes-agent:v2026.9.14
```

Контейнер:

```text
name: hermes
command: gateway run
restart: unless-stopped
network: host
shm_size: 1g
runtime UID/GID: 10000:10000
```

Тег закреплён в `provision.yaml` и меняется только через проект.
У исследованного образа ревизия исходного кода
`345cd2b057a452236de401d3534b8502a7465e8d`, digest
`sha256:99641e57ec762c59e54cb44aa6746b7fc68c18b3c5ddb088af54234c613d9294`.

## 2. API и пользовательский интерфейс

### 2.1. API

Для связи с Open WebUI включается встроенный API Hermes:

```text
API_SERVER_ENABLED=true
API_SERVER_HOST=127.0.0.1
API_SERVER_PORT=8642
API_SERVER_MODEL_NAME=hermes-agent
API_SERVER_KEY=<локальный секрет>
AWS_EC2_METADATA_DISABLED=true
```

Open WebUI подключается к:

```text
http://127.0.0.1:8642/v1
```

Ключ создаётся при первом применении Ansible и хранится в:

```text
/etc/ai-control/hermes.env
```

API Hermes не публикуется в домашнюю сеть.

`AWS_EC2_METADATA_DISABLED=true` задаётся Ansible в том же файле окружения при каждом
развёртывании. 410 не является EC2 instance и не получает AWS credentials через
службу метаданных. Явные AWS credentials и профили SDK этот параметр не отключает.
При изменении файла окружения `docker compose up -d` пересоздаёт контейнер с новым
окружением, сохраняя подключённый каталог данных и существующий ключ API.

### 2.2. Dashboard

Встроенный Hermes Dashboard в базовой конфигурации выключен.

Если он понадобится для администрирования Hermes, используется штатный порт `9119` и обязательная аутентификация. Его не следует путать с основным пользовательским интерфейсом Open WebUI.

## 3. Постоянное состояние

### 3.1. Каталог

На хосте:

```text
/opt/ai-control/state/hermes/
```

В контейнере:

```text
/opt/data
```

Этот каталог является источником постоянного состояния Hermes. На хосте он принадлежит UID/GID `10000:10000`, совпадающим со штатным пользователем Hermes внутри контейнера.

В нём Hermes хранит, в частности:

- конфигурацию;
- сессии;
- память;
- skills;
- cron;
- hooks;
- журналы;
- данные профилей.

Не допускается одновременно запускать два контейнера Hermes с одним и тем же каталогом данных.

### 3.2. Программа и обновление

Код Hermes находится внутри образа и не резервируется.

Обновление:

```text
изменить image tag в provision.yaml
→ применить Ansible
→ docker compose pull
→ docker compose up -d
→ проверить /health и Open WebUI
```

## 4. Модели и инструменты

### 4.1. Модели

Hermes должен поддерживать как локальные, так и внешние модели.

Поставщик модели является отдельной настройкой Hermes и не должен быть зашит в Open WebUI.

Open WebUI всегда обращается к логической модели `hermes-agent`, а Hermes уже использует настроенного поставщика.

Первый реальный поставщик модели ещё должен быть выбран и настроен.

### 4.2. Инструменты

Инструменты Hermes делятся на два класса:

- собственные возможности Hermes;
- интеграции проекта.

Для проекта предполагаются:

```text
Hermes
├── встроенные возможности
├── Home Assistant
├── MCP infra-manager → 910
├── MCP/интерфейс сети
└── мониторинг
```

Новые внешние права выдаются только вместе с реализацией соответствующего инструмента.

Контейнеру Hermes не передаётся `/var/run/docker.sock`.

## 5. Проверка и восстановление

### 5.1. Проверка

Минимально проверяются:

- контейнер `hermes` запущен;
- `GET /health` отвечает `200`;
- `GET /v1/models` с Bearer token возвращает `hermes-agent`;
- каталог `/opt/data` постоянный;
- Open WebUI получает список моделей;
- после настройки поставщика модель отвечает через Hermes.

### 5.2. Восстановление

При потере VM:

1. восстановить `/opt/ai-control/state/hermes/`;
2. восстановить или заново материализовать `/etc/ai-control/hermes.env`;
3. применить Ansible;
4. получить закреплённый образ;
5. запустить Compose;
6. проверить состояние Hermes.

### 5.3. Gateway работает, но API не слушает порт

В `v2026.9.14` HTTP API запускается адаптером `api_server` внутри Gateway.
Загрузчик включает его по пригодному `API_SERVER_KEY`; одного
`API_SERVER_ENABLED=true` недостаточно. Проверка поставщиков моделей при запуске
завершается до подключения адаптеров. Сочетание `model.provider: auto` и
`model.base_url` в начальной конфигурации вызывает повторное разрешение поставщика
в коде Hermes; при отсутствии credentials оно доходит до цепочки AWS SDK.
Запросы к недоступному `169.254.169.254:80` задерживают запуск API.

Признаки: `gateway.log` заканчивается перед `Connecting to api_server`, процесс
Gateway остаётся жив, а `ss -ntp` показывает его соединение к службе метаданных.
Нужно проверить `AWS_EC2_METADATA_DISABLED=true` именно у Gateway, затем повторить
развёртывание. Увеличение числа повторов `/health` не устраняет причину.

Конфигурация Gateway объединяет `gateway.json`, `config.yaml` и окружение;
окружение дополняет параметры API, но явное `platforms.api_server.enabled: false`
сохраняет запрет. При загрузке `.env` Hermes может перекрывать переменные Docker.
Журналы Gateway находятся в `/opt/data/logs/gateway.log` и
`/opt/data/logs/gateways/default/current`, ошибки — в `logs/errors.log`.

Отсутствие `_config_version` у начального `config.yaml` вызывает предупреждение
об автоматической миграции ниже поддерживаемой версии 12. Оно не блокирует API.
Нельзя устранять это предупреждение удалением конфигурации или запуском
`hermes setup` поверх пользовательских настроек без отдельной проверки и копии.

Перед изменением окружения нужно сохранить `hermes.env` в закрытый каталог
резервной копии. Для отката восстановить этот файл и выполнить
`docker compose -f /opt/ai-control/compose/docker-compose.yml up -d`.
Восстанавливать базы или удалять каталоги состояния для отката этой настройки
не требуется. При следующем развёртывании исправленная роль снова применит
целевой параметр.
