# Решения по 410 ai-control

**Тип:** локальные решения  
**Статус:** действующий  
**Назначение:** зафиксировать причины устойчивых решений 410.

## 1. Состав системы

### 1.1. Почему AI Control не является отдельной программой

**Проблема.**  
Самописное ядро между Open WebUI и Hermes дублировало бы уже имеющиеся в Hermes API, память, сессии, cron, инструменты и агентный цикл.

**Рассмотренные варианты.**

- собственный оркестратор AI Control;
- использовать Hermes только как один из исполнителей;
- считать AI Control названием системы 410, а Hermes — её основной агентной средой.

**Принятое решение.**  
AI Control — название всей системы `410 ai-control`. Отдельная программа AI Control не создаётся.

**Почему.**

- меньше собственного кода;
- не дублируются возможности Hermes;
- обновления агентной среды приходят из upstream;
- Open WebUI подключается к официальному API Hermes напрямую.

**Последствия и ограничения.**

- часть внутренней архитектуры зависит от возможностей Hermes;
- заменяемость Hermes обеспечивается внешними границами и данными проекта, а не собственным универсальным оркестратором.

**Когда пересматривать.**  
Если Hermes перестанет удовлетворять требованиям или появится функция, которую невозможно безопасно реализовать его штатными расширениями.

### 1.2. Почему Hermes запускается в Docker

**Проблема.**  
Hermes имеет большой набор зависимостей и инструментов, которые не должны засорять базовую Debian VM.

**Принятое решение.**  
Использовать официальный закреплённый Docker-образ Hermes.

**Почему.**

- зависимости изолированы;
- программа отделена от состояния;
- обновление сводится к смене image tag;
- официальный образ рассчитан на постоянный каталог `/opt/data`.

**Последствия и ограничения.**

- Docker становится обязательной частью 410;
- нужно резервировать каталог состояния Hermes.

**Когда пересматривать.**  
Если контейнерный вариант перестанет поддерживаться upstream.

## 2. Интерфейс пользователя

### 2.1. Почему выбран Open WebUI

**Проблема.**  
Самописный интерфейс требует отдельно реализовывать пользователей, диалоги, историю, мобильную вёрстку и настройки.

**Принятое решение.**  
Использовать Open WebUI и подключать его напрямую к OpenAI-совместимому API Hermes.

**Почему.**

- готовый пользовательский интерфейс;
- штатно поддерживаемый Hermes сценарий;
- нет промежуточного самописного API;
- пользовательский слой можно обновлять независимо.

**Последствия и ограничения.**

- постоянные данные Open WebUI нужно резервировать;
- настройки подключения после первого запуска могут храниться в базе Open WebUI.

**Когда пересматривать.**  
Если Open WebUI перестанет удовлетворять требованиям.

## 3. Полномочия и интеграции

### 3.1. Почему Hermes не получает универсальный root-доступ

**Проблема.**  
Встроенные terminal/file tools делают Hermes мощным агентом. Прямой root ко всем системам резко увеличил бы последствия ошибки.

**Принятое решение.**  
Hermes работает внутри собственного контейнера и получает внешние возможности только через явно подключённые интеграции.

**Почему.**

- ошибка агента ограничена доступными интерфейсами;
- права можно выдавать и отзывать отдельно;
- для инфраструктуры сохраняется 910 как детерминированный исполнитель.

**Последствия и ограничения.**

- для каждой новой системы требуется отдельный контролируемый инструмент;
- некоторые диагностические задачи могут потребовать специально выданный доступ.

**Когда пересматривать.**  
Только при появлении более сильной технической модели делегирования.

### 3.2. Почему инфраструктура выполняется через 910

410 понимает задачу и инициирует разрешённую операцию, а `910 infra-manager` выполняет OpenTofu, Ansible и другие повторяемые инфраструктурные действия.

Hermes не получает прямой PVE API token и не дублирует инфраструктурный исполнитель.

## 4. Данные и восстановление

### 4.1. Почему сохраняются каталоги продуктов

Hermes и Open WebUI уже имеют собственные модели хранения.

Поэтому проект не создаёт параллельную самописную базу памяти или задач.

Сохраняются:

```text
/opt/ai-control/state/hermes
/opt/ai-control/state/open-webui
```

Программы восстанавливаются из закреплённых контейнерных образов.
