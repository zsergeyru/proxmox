# Open WebUI на 410

**Тип:** локальная спецификация службы  
**Статус:** целевое состояние  
**Назначение:** описать Open WebUI как основной пользовательский интерфейс 410.

## 1. Роль и размещение

### 1.1. Назначение

Open WebUI отвечает только за пользовательский слой:

- вход пользователей;
- диалог;
- историю;
- пользовательские настройки;
- отправку запросов Hermes.

Управляющая цепочка:

```text
браузер
↓
Open WebUI :4100
↓
Hermes :8642/v1
↓
модель + инструменты Hermes
```

Open WebUI не является агентом и не получает прямых административных прав к системам квартиры.

### 1.2. Контейнер

Используется образ:

```text
ghcr.io/open-webui/open-webui:0.11.4-slim
```

Контейнер работает в `network_mode: host` и слушает порт `4100`.

Встроенный Ollama в этой схеме не используется.

## 2. Связь с Hermes

### 2.1. OpenAI-совместимое подключение

Open WebUI получает:

```text
OPENAI_API_BASE_URL=http://127.0.0.1:8642/v1
OPENAI_API_KEY=<тот же секрет, что API_SERVER_KEY Hermes>
```

Hermes публикует модель:

```text
hermes-agent
```

Настройки подключения Open WebUI могут сохраняться в его собственной базе. Поэтому смена адреса Hermes после первого запуска должна выполняться осознанно через административные настройки или миграцию состояния.

### 2.2. Учётная запись администратора

Для пустой базы Open WebUI Ansible создаёт начальную учётную запись:

```text
admin@ai-control.local
```

Начальный пароль и `WEBUI_SECRET_KEY` находятся только на 410:

```text
/etc/ai-control/open-webui.env
```

Регистрация пользователей по умолчанию выключена.

## 3. Данные и безопасность

### 3.1. Постоянное состояние

На хосте:

```text
/opt/ai-control/state/open-webui/
```

В контейнере:

```text
/app/backend/data
```

Каталог входит в резервирование 410.

### 3.2. Сетевая граница

Open WebUI доступен из разрешённой внутренней сети на порту `4100`.

Прямая публикация в Интернет не является штатной схемой. Для внешнего доступа требуется отдельный защищённый контур TLS/VPN/reverse proxy.

Hermes API остаётся на loopback и снаружи VM не доступен.

## 4. Развёртывание и обновление

### 4.1. Развёртывание

Роль `ai_control`:

1. создаёт постоянный каталог;
2. создаёт секреты;
3. формирует общий Compose Hermes + Open WebUI;
4. проверяет Compose;
5. получает закреплённый образ;
6. запускает контейнер;
7. ждёт успешный ответ `/health`.

### 4.2. Обновление

Версия меняется только в `provision.yaml`.

```text
изменить image tag
→ применить Ansible
→ docker compose pull
→ docker compose up -d
→ проверить /health
```

## 5. Проверка и восстановление

### 5.1. Проверка

Проверяются:

- контейнер `open-webui` работает;
- `GET http://127.0.0.1:4100/health` возвращает `200`;
- вход администратора работает;
- модель `hermes-agent` видна;
- после перезапуска сохраняются учётная запись и диалоги.

### 5.2. Восстановление

При потере VM:

1. восстановить `/opt/ai-control/state/open-webui/`;
2. восстановить `/etc/ai-control/open-webui.env`;
3. применить Ansible;
4. запустить Compose;
5. проверить вход и соединение с Hermes.
