# Состояние реализации 410 ai-control

**Тип:** состояние реализации  
**Статус:** разрабатывается  
**Назначение:** показать расхождение между целевой спецификацией и текущим кодом.

## 1. Что уже реализовано

На текущей ветке реализованы:

- системная роль гостя `ai-control`;
- `pve_management: false`;
- Debian 13 и базовая настройка Linux;
- Docker из официального репозитория;
- специализированная роль Ansible `ai_control`;
- закреплённый образ Hermes `nousresearch/hermes-agent:v2026.9.14`;
- закреплённый Open WebUI `0.11.4-slim`;
- постоянные каталоги Hermes и Open WebUI;
- локальный API key Hermes;
- начальная учётная запись Open WebUI;
- Compose для двух контейнеров;
- Hermes API только на `127.0.0.1:8642`;
- Open WebUI на порту `4100`;
- автоматическая проверка `/health` обоих сервисов;
- отключение EC2 metadata в окружении Hermes для локальной VM Proxmox;
- контрактная проверка, запрещающая возврат самописного ядра AI Control.

Самописные Python API, SQLite, `ai-control.service`, `models.json` и `tools.json` удалены.

### 1.1. Проверка запуска Hermes 9 октября 2026 года

На VM 410 исследован закреплённый образ с digest
`sha256:99641e57ec762c59e54cb44aa6746b7fc68c18b3c5ddb088af54234c613d9294`.
До исправления Gateway оставался жив под s6, но API не слушал порт.
Переменные API присутствовали у самого процесса; работал только профиль
`default`, `multiplex_profiles` был выключен.

В отдельном диагностическом процессе с существующей конфигурацией получен стек:
`free_tier_bootstrap → resolve_provider → _config_model_provider →
_config_base_url_trustworthy_for_bare_custom → resolve_provider`.
Повторное разрешение `auto` с `base_url` доходило до Bedrock и цепочки AWS SDK,
ожидавшей EC2 metadata. У рабочего Gateway наблюдался `SYN-SENT` к
`169.254.169.254:80`. При отключении metadata проверка поставщиков завершилась
примерно за 5 секунд, весь bootstrap — за 10 секунд, без изменения `config.yaml`.

Роль `ai_control` идемпотентно добавляет `AWS_EC2_METADATA_DISABLED=true`
в существующий `hermes.env`. Первый полный deploy и повторный deploy из
`fix/410-hermes-api` завершились с кодом 0. При повторном применении контейнер
Hermes сохранил идентификатор. После перезапуска Hermes и Open WebUI проверены:

- `/health` обеих служб: HTTP 200;
- `/v1/models`: HTTP 200 с правильным ключом, 401 без ключа и с неверным ключом;
- вход в Open WebUI и получение `hermes-agent` через его `/api/models`;
- прослушивание только `127.0.0.1:8642`, отказ соединения с PVE к адресу VM;
- неизменность `config.yaml`, внутреннего `.env` и секретов Open WebUI;
- сохранение исходного API key: в `hermes.env` добавлена только строка metadata;
- исходные подключения постоянных каталогов и `quick_check: ok` обеих SQLite-баз;
- неизменная контрольная сумма постоянного OpenTofu state.

Копия конфигурации сохранена в закрытом каталоге VM
`/opt/ai-control/backups/hermes-api-20261009/`. Предупреждение о версии
`config.yaml` ниже 12 сохранено; оно не препятствует работе HTTP API.
Поставщик модели не настроен, поэтому успешный агентный диалог пока не подтверждён.
Обычная команда `infra-manager deploy 410` с PVE также завершилась с кодом 0.
При завершающей проверке удалённый `main` и рабочая копия 910 уже содержали
`963f5d3f`; перемещение `main` произошло отдельно от команд этой диагностики,
которые отправляли только `fix/410-hermes-api`. Полный исправленный контракт
обеспечивает роль с параметром metadata; старая роль лишь сохраняет уже
исправленный существующий файл окружения.

## 2. Что реализовано частично

### 2.1. Hermes

Контейнер, постоянное состояние и API-конфигурация описаны и разворачиваются автоматически.

Но поставщик AI-модели ещё не настроен. Поэтому полноценный ответ агента появится после следующего этапа настройки Hermes.

### 2.2. Open WebUI

Open WebUI подключён напрямую к Hermes через его штатный OpenAI-совместимый API.

Фактическая проверка полноценного диалога зависит от настройки модели Hermes.

### 2.3. Инфраструктурный доступ

В `access.yaml` уже есть разрешённые операции Semaphore для 410, но MCP/другой инструмент Hermes для вызова 910 ещё не реализован.

## 3. Что ещё не реализовано

Остаётся:

- выбрать и подключить первый поставщик модели;
- настроить основную модель Hermes;
- проверить полноценный диалог Open WebUI → Hermes → модель;
- подключить Home Assistant;
- реализовать ограниченный инструмент/MCP к 910;
- подключить сеть;
- подключить мониторинг;
- определить правила подтверждения критичных действий;
- настроить полезные cron-задачи;
- настроить уведомления;
- оформить итоговую страницу состояния 410.

## 4. Текущие ограничения

### 4.1. Внешнего AI ещё нет

Интерфейс и агентная среда разворачиваются, но без настроенного поставщика модели Hermes не может выполнять полноценный агентный цикл.

### 4.2. Open WebUI работает по HTTP

Порт `4100` предназначен для доверенной внутренней сети.

Для внешнего доступа нужен отдельный защищённый канал.

### 4.3. Секреты пока локальные

`hermes.env` и `open-webui.env` сохраняются вместе с резервной копией 410.

Позже их целесообразно материализовать из OpenBao.

## 5. Критерий завершения

410 считается рабочей базовой AI-системой, когда:

- Hermes и Open WebUI автоматически разворачиваются;
- настроен хотя бы один поставщик модели;
- диалог через Open WebUI даёт реальный ответ Hermes;
- состояние переживает перезапуск;
- внешний API Hermes не опубликован;
- дальнейшие интеграции добавляются через ограниченные инструменты, а не через неограниченный root-доступ.
