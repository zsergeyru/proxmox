## 1. Что уже реализовано

На текущей ветке проекта уже есть:

- `guest.yaml` с `role: ai-control`;
- `pve_management: false`;
- `provision.yaml` с Debian 13 amd64 и базовыми пакетами;
- логическая связь с инфраструктурным исполнителем по `role: infra-manager`, без привязки к VMID 910;
- машинное описание пользователя, каталогов, основного агента и службы AI Control;
- разделение данных на `backup_required`, `reproducible` и `ephemeral`;
- общий Ansible playbook `configure-guest.yml`;
- роль `linux_base`;
- специализированная роль `ai_control`, подключаемая по системной роли, а не по VMID;
- системный пользователь и группа `ai-control`;
- подготовка `/opt/ai-control/`, `/etc/ai-control/`, `/run/ai-control/` и `/var/cache/ai-control/`;
- подготовка постоянных каталогов памяти, диалогов, задач, событий, наблюдений и состояния Hermes;
- несекретный `/etc/ai-control/ai-control.env`;
- воспроизводимый `rootfs/etc/systemd/system/ai-control.service`;
- минимальное ядро AI Control версии `0.1.0` на стандартном Python 3;
- рабочий веб-интерфейс на порту `4100`;
- локальная аутентификация веб-интерфейса с автоматически созданным паролем;
- HTTP API состояния, задач, памяти, моделей, инструментов и журнала действий;
- постоянное хранение задач, памяти, истории диалога и журнала в SQLite;
- реестр моделей и минимальный механизм выбора разрешённой модели;
- реестр внутренних и будущих внешних инструментов;
- включение и запуск `ai-control.service`;
- настройка SSH-доверия и машинной идентичности OpenBao общим Linux-контуром;
- управляемый доступ чтения к проектному Git;
- в `access.yaml` для 410 определены получение SSH identity, чтение репозитория и запуск ограниченного набора инфраструктурных задач Semaphore;
- отдельная контрактная проверка базовой реализации 410 в CI.

## 2. Что реализовано частично

### 2.1. Основной агент и модели

Ядро AI Control и веб-интерфейс работают независимо от Hermes.

Веб-диалог уже принимает и сохраняет сообщение, но до установки адаптера Hermes возвращает состояние `agent_unavailable`. Это намеренно: ядро не имитирует ответ AI, если реальный агент не подключён.

Реестр моделей и функция выбора модели уже существуют, но поставщики моделей пока не настроены, поэтому список активных моделей пуст.

### 2.2. Инфраструктурный доступ

В `access.yaml` разрешены логические операции Semaphore:

- `opentofu-plan`;
- `deploy-managed-guest`;
- `verify-managed-guest`.

Но ещё требуется реализовать прикладной клиент AI Control, который будет вызывать этот контракт.

### 2.3. SSH

У 410 есть право получить собственную SSH identity через OpenBao.

При этом в текущем `access.yaml` нет правила `connect-root` от 410 к конкретным Linux-гостям или группе управляемых гостей.

Поэтому прямая диагностика других Linux-гостей пока не считается доступной функцией 410.

- машинная конфигурация конкретных поставщиков моделей;
- материализация секретов моделей;

## 4. Текущие ограничения

### 4.1. Веб-доступ первой версии

Первая версия слушает `0.0.0.0:4100` и использует HTTP Basic Authentication.

Имя пользователя задаётся в `provision.yaml`, а случайный пароль создаётся на самом госте при первом применении Ansible и сохраняется только в:

```text
/etc/ai-control/web.env
```

Получить его администратор может на 410 командой:

```bash
cat /etc/ai-control/web.env
```

Эта схема предназначена только для доверенной внутренней сети. До публикации интерфейса за пределами внутренней сети требуется TLS либо защищённый обратный прокси.

### 4.2. Hermes ещё не подключён

Сейчас веб-интерфейс, задачи, память, журнал и API работают, но AI-ответы не генерируются.

Подключение Hermes относится к следующему этапу.

### 4.3. Внешние инструменты пока только зарегистрированы

В реестре уже видны Git, инфраструктура, Home Assistant, сеть и мониторинг, но реальный вызов этих систем будет добавляться по одному вместе с машинными правами.

## 5. Критерий завершения

410 можно считать реализованным по текущей спецификации, когда:

- после чистого развёртывания автоматически появляется рабочий AI Control;
- веб-интерфейс доступен и защищён;
- Hermes установлен как основной агент;
- доступна хотя бы одна локальная или внешняя модель;
- работают разрешённые инструменты;
- задачи и подтверждения переживают перезапуск;
- постоянное состояние корректно резервируется и восстанавливается;
- итоговая проверка подтверждает все обязательные функции;
- этот документ больше не содержит незакрытых расхождений.
