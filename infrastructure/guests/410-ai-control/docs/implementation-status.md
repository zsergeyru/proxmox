# Состояние реализации 410 ai-control

**Тип:** состояние реализации  
**Статус:** разрабатывается  
**Назначение:** показать расхождение между целевой локальной спецификацией 410 и текущим кодом.

Этот файл не определяет целевую архитектуру. Требования находятся в `ai-control.md`, `open-webui.md` и `hermes.md`.

## 1. Что уже реализовано

На текущей ветке проекта уже есть:

- `guest.yaml` с `role: ai-control`;
- `pve_management: false`;
- Debian 13 amd64 и базовые системные пакеты;
- Docker из официального репозитория Docker;
- логическая связь с инфраструктурным исполнителем по `role: infra-manager`;
- специализированная Ansible-роль `ai_control`, подключаемая по роли, а не по VMID;
- системный пользователь и группа `ai-control`;
- каталоги программы, состояния, конфигурации, кэша и временных данных;
- `ai-control.service`;
- минимальное ядро AI Control версии `0.2.0`;
- внутренний API на `127.0.0.1:4110`;
- OpenAI-совместимый `GET /v1/models`;
- OpenAI-совместимый `POST /v1/chat/completions`;
- внутренний Bearer token между Open WebUI и AI Control;
- постоянное хранение задач, памяти, истории диалога и журнала действий в SQLite;
- реестр моделей и механизм выбора модели;
- реестр инструментов;
- Open WebUI как единственный пользовательский веб-интерфейс;
- закреплённый образ `ghcr.io/open-webui/open-webui:v0.11.4-slim`;
- Open WebUI на порту `4100`;
- автоматическое создание начального администратора Open WebUI;
- постоянные данные Open WebUI в `/opt/ai-control/state/open-webui/`;
- локальные секреты `/etc/ai-control/api.env` и `/etc/ai-control/open-webui.env`;
- воспроизводимый Compose-файл Open WebUI;
- контрактная и дымовая проверка ядра AI Control.

## 2. Что реализовано частично

### 2.1. Основной агент

Open WebUI уже получает модель `hermes-agent` из AI Control.

До установки адаптера Hermes запрос к `POST /v1/chat/completions` возвращает `agent_unavailable`.

Это намеренное состояние: интерфейс и внутренняя связь работают, но ядро не имитирует AI-ответ без реального агента.

### 2.2. Модели

Реестр моделей и алгоритм выбора модели существуют.

Конкретные локальные и внешние поставщики пока не настроены, поэтому Hermes ещё не может получить реальный inference endpoint.

### 2.3. Инфраструктурный доступ

В `access.yaml` разрешены логические операции Semaphore:

- `opentofu-plan`;
- `deploy-managed-guest`;
- `verify-managed-guest`.

Но прикладной инструмент AI Control для вызова этих операций ещё не реализован.

### 2.4. SSH

У 410 есть право получить собственную SSH identity через OpenBao.

В текущем `access.yaml` нет правила `connect-root` от 410 к конкретным Linux-гостям или группе управляемых гостей.

Поэтому прямая диагностика других Linux-гостей пока не считается доступной функцией.

## 3. Что ещё не реализовано

Отсутствуют:

- установка Hermes;
- адаптер Hermes;
- закреплённый источник и версия Hermes;
- реальные поставщики локальной или внешней AI-модели;
- секреты конкретных поставщиков моделей;
- интеграция Home Assistant;
- интеграция с домашней сетью;
- интеграция мониторинга;
- внешний инструмент инфраструктуры через 910;
- исполнитель очереди задач;
- расписание;
- обработка событий;
- система подтверждений;
- прикладная долговременная память агента;
- внешние уведомления;
- итоговая машинная страница состояния 410.

## 4. Текущие ограничения

### 4.1. Open WebUI доступен только по HTTP

Open WebUI слушает `0.0.0.0:4100`.

Это предназначено для доверенной внутренней сети. Прямой доступ из Интернета не считается допустимой штатной схемой.

Для внешнего доступа потребуется отдельный TLS/VPN/reverse-proxy контур.

### 4.2. Hermes ещё не подключён

Пользователь может войти в Open WebUI и увидеть `hermes-agent`, но отправка сообщения завершится понятной ошибкой `agent_unavailable` до следующего этапа.

### 4.3. Локальные секреты пока резервируются файлами

`/etc/ai-control/api.env` и `/etc/ai-control/open-webui.env` не находятся в Git и создаются на госте.

Пока для них не реализовано внешнее хранилище секретов, эти два файла входят в обязательное резервирование вместе с `/opt/ai-control/state/`.

### 4.4. Внешние инструменты пока только зарегистрированы

Git, инфраструктура, Home Assistant, сеть и мониторинг уже представлены в архитектуре и реестре, но фактические вызовы будут добавляться по одному вместе с машинными правами.

## 5. Критерий завершения

410 можно считать реализованным по текущей спецификации, когда:

- после чистого развёртывания автоматически появляются рабочие AI Control и Open WebUI;
- Open WebUI доступен и защищён в принятой сетевой схеме;
- Hermes установлен как основной агент;
- доступна хотя бы одна локальная или внешняя модель;
- работают разрешённые внешние инструменты;
- задачи и подтверждения переживают перезапуск;
- постоянное состояние и локальные секреты корректно резервируются и восстанавливаются;
- итоговая проверка подтверждает все обязательные функции;
- этот документ больше не содержит незакрытых расхождений.
