# 410 ai-control

`410 ai-control` — центральная VM интеллектуального управляющего контура квартиры.

Она предназначена для работы AI-агентов, взаимодействия с жильцами, анализа состояния дома и координации разрешённых действий в Home Assistant, инфраструктуре, домашней сети и других сервисах.

AI Control не заменяет специализированные системы. Он понимает задачу, выбирает подходящий механизм, передаёт выполнение владельцу функции и проверяет результат.

## Назначение

410 должен обеспечивать:

- работу одного основного универсального AI-агента;
- взаимодействие с жильцами и пользователями сервисов;
- использование локальных и внешних AI-моделей;
- анализ состояния квартиры, инфраструктуры и сервисов;
- обработку значимых событий;
- работу с Home Assistant через его штатный интерфейс;
- работу с домашней сетью через разрешённые средства;
- диагностику разрешённых Linux-гостей;
- передачу повторяемых инфраструктурных изменений в `910 infra-manager`;
- рабочую копию репозитория проекта;
- инструкции, инструменты и постоянное рабочее состояние AI.

Текущим основным агентом считается Hermes. Дополнительные агенты не требуются для базовой работы и подключаются только при реальной необходимости.

## Объект Proxmox

Требуемые параметры определяются `guest.yaml`.

На текущем этапе:

```text
VMID:          410
name:          ai-control
тип:           VM
профиль:       debian-vm
CPU:           2
RAM:           4096 MB
диск:          24 GB
managed pool:  нет
```

`pve_management: false` задан специально: AI Control не должен через обычный управляемый контур остановить, удалить или пересоздать собственную VM.

## Роль в системе

Основное разделение ответственности:

```text
410 ai-control
→ взаимодействие с человеком
→ анализ и рассуждение
→ рабочая память
→ наблюдение за событиями
→ выбор AI-модели
→ выбор разрешённого инструмента
→ координация действий
→ проверка результата

910 infra-manager
→ OpenTofu
→ Ansible
→ Packer
→ Semaphore
→ повторяемое инфраструктурное выполнение

Home Assistant
→ домашние сущности
→ события
→ сценарии
→ автоматизации

сетевые системы
→ DNS
→ маршрутизация
→ VPN
→ сетевые клиенты
```

410 является интеллектуальным слоем над этими системами, а не заменой каждой из них.

## Модели и агенты

AI Control использует один основной универсальный агент и должен поддерживать:

- локальные модели на другом компьютере или сервере квартиры;
- внешние модели через API;
- выбор модели по задаче;
- замену основного агента без изменения базовой архитектуры.

Конкретная модель не получает дополнительные полномочия автоматически.

Home Assistant, сеть, инфраструктура, мониторинг и другие функции предоставляются основному агенту как инструменты, а не как отдельные обязательные агенты.

Инструменты, доступы и правила должны быть отделены от Hermes и других конкретных программ-агентов.

## Web-интерфейс

Web-интерфейс обязателен и является основной пользовательской точкой входа в AI Control.

Он должен позволять вести диалог с основным агентом, видеть задачи, события и уведомления, подтверждать опасные действия, просматривать состояние моделей и интеграций и видеть историю выполненных операций.

Web-интерфейс работает через общее ядро AI Control и не должен содержать отдельную логику управления системами.

## Рабочая структура


Текущая целевая основа:

```text
/opt/ai-control/
├── agents/
├── repos/
│   └── proxmox/
├── instructions/
├── tools/
└── state/
```

Логически инструменты должны разделяться по областям:

```text
infrastructure
home_assistant
network
monitoring
git
knowledge
notifications
models
```

Точная файловая структура будет определяться вместе с реализацией службы AI Control.

## Состояние и память

`/opt/ai-control/state/` предназначен для постоянного рабочего состояния AI.

Логически в нём могут находиться:

```text
memory/
conversations/
events/
tasks/
observations/
cache/
```

Документация и конфигурация проекта не должны дублироваться здесь как отдельный источник истины. Воспроизводимые знания берутся из Git и других нормативных систем.

## Доступы

Права 410 определяются `infrastructure/security/access.yaml`.

Основные принципы:

- нет штатного root SSH к физическому PVE;
- нет штатного прямого PVE API token для инфраструктурных изменений;
- повторяемые инфраструктурные операции передаются 910;
- прямой SSH к гостям используется только там, где он явно разрешён;
- Home Assistant, сеть и другие сервисы получают отдельные ограниченные интеграции;
- критичные границы обеспечиваются техническими правами, а не только инструкцией для AI.

## Что не размещается в 410

В 410 не следует переносить самостоятельные сервисы только ради удобства AI:

- Home Assistant;
- сервер локальной модели, если ему требуется отдельное оборудование;
- STT/TTS общего назначения;
- NVR и видеонаблюдение;
- DNS/VPN;
- общее файловое хранилище;
- мониторинг;
- другие независимые прикладные сервисы.

Перезапуск 410 не должен останавливать базовую работу квартиры, сети или Home Assistant.

## Текущее состояние реализации

Сейчас общий контур развёртывания уже умеет подготовить Debian 13, базовые пакеты, доверие SSH/OpenBao, Git и рабочие каталоги 410.

Специализированная роль AI Control, установка Hermes, выбор локальной или внешней модели, интеграция с Home Assistant, сетью, событиями и памятью ещё должны быть спроектированы и реализованы.
