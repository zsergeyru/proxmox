# Администрирование гостя 140

**Тип:** локальная спецификация службы  
**Статус:** реализовано в отдельной ветке; испытания на настоящем PVE ещё не выполнены.

## 1. Состав

Адрес: `https://home.zsergey.ru/admin`. Административные действия находятся **на отдельной странице**, а не в Homarr. Она содержит три раздела:

| Раздел | Возможности |
|---|---|
| Пользователи Authelia | Список, создание, новый пароль, изменение групп, включение/отключение входа, сброс второго фактора и проверочный код |
| Домены Caddy | Просмотр и подтверждённое включение/отключение разрешённых маршрутов |
| Гости Proxmox | Просмотр перечня из Git без изменяющих команд |

Данные пользователей находятся в `/var/lib/web-gateway/authelia/users_database.yml`, действующие маршруты — в `/var/lib/web-gateway/management/routes.yaml`. Оба файла сохраняются при повторном `deploy 140`. Программы гостя изменяют их через отдельный закрытый обработчик; браузер не получает доступа к диску или системным ключам.

## 2. Права и границы сети

Публичные 80/443 обслуживает Caddy. Authelia проверяет пароль и второй фактор каждого пользователя. Доступ к `/admin` и `/api/admin/*` требует **одновременно** группу `admins` и IP из списка `web_gateway.caddy.private_networks`; сейчас это домашняя сеть `192.168.0.0/16`. Сети VPN включаются только после указания подтверждённой подсети.

В правилах Authelia за разрешением для `admins` стоит явный запрет всех остальных групп на те же адреса. Нельзя считать скрытие ссылки на административную страницу достаточной проверкой доступа.

Браузер передаёт только действия и параметры. Caddy выдаёт проверенный внутренний признак обращения к административному адресу; закрытая служба проверяет источник изменяющего запроса (`Origin`), тип JSON и ограничение размера. Только она передаёт запрос действующему обработчику с ключом из закрытого файла. Закрытый ключ не помещается в HTML, JavaScript, HTTP-ответ или заголовок, доступный браузеру.

**Публикацию нужно проверять с внешнего подключения**, в том числе в случае перенаправления портов Keenetic. Подмена исходного IP через NAT, при которой любой внешний клиент выглядит как локальный, нарушает сетевое ограничение.

## 3. Пользователи

Создание пользователя выдаёт новый случайный пароль. Сохранить его нужно в доверенном месте: позднее он не восстанавливается из хеша. Для пользователей допускаются только группы `admins`, `family`, `guests`. Первоначальный перечень имён и групп объявляется в [общем файле проекта](../../../users.yaml), но реальная база Authelia сохраняется на постоянном томе.

Изменения через административную страницу имеют силу для действующих учётных записей: повторный `deploy 140` не должен восстанавливать удалённых пользователей из Git, сбрасывать пароли или менять группы. Автоматическая двусторонняя синхронизация пока не реализована. Последнего действующего администратора запрещено отключать или лишать его группы.

Новый пароль, сброс TOTP и отключение входа требуют подтверждения. Проверочный код доступен только администратору на защищённой странице. Административные действия не заменяют самообслуживание пользователя Authelia.

## 4. Домены

Разрешены только заранее утверждённые в Git имена и назначения. Любое изменение сначала проверяется Caddy; при ошибке применяется прежняя конфигурация. Нельзя отключить `home.zsergey.ru` и `auth.zsergey.ru` или сделать другие приложения открытыми без предусмотренного входа.

Immich, Home Assistant и Open WebUI остаются выключенными до проверки их готовности и авторизации. После успешного включения маршрут появляется на обычной странице приложений автоматически.

## 5. Гости Proxmox

Каталог `management/catalog/guests.json` формируется из Git при `deploy 140` и `sync 140`. Он показывает имена и номера гостей, но **не** подтверждает их работоспособность. Кнопки изменения состояния PVE не добавляются без независимой проверки полномочий через гостя 910.

## 6. Приёмка

После развёртывания с PVE:

1. Проверить отказ обычному пользователю на `/admin` и `/api/admin/*`, даже при действующем входе Authelia.
2. Проверить отказ администратору из внешней сети.
3. Проверить работу из LAN/VPN администратора: просмотр пользователей, создание испытательной записи и смена группы.
4. Проверить пробный маршрут `check.zsergey.ru` и возврат предыдущих правил при ошибке Caddy.
5. Убедиться, что пароль и код не появляются в журналах и в публичных файлах.
6. Повторить `infra-manager deploy 140` и проверить сохранность пользователей, доменов и сертификатов.

[Описание страниц и входа](portal.md) содержит схему доступа и порядок обновления.
