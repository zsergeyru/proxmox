## 1. Условия и подготовка

### 1.1. Гость и сеть

Гость — LXC с Debian 13 и Docker Compose, CTID 140, имя `web-gateway`. Адрес по действующему правилу VMID — `192.168.1.40`; IP гостя берётся из `guest.yaml` и общих настроек, а не вручную повторяется в нескольких независимых файлах.

Ориентир начальных ресурсов: 2 виртуальных процессора, 1 ГиБ ОЗУ и 16 ГиБ диска. После первого запуска измерить потребление и при необходимости увеличить ОЗУ. Docker внутри LXC требует правильной настройки контейнера и поддержки нужных возможностей ядра; согласовать с общими правилами развёртывания, не создавать особый ручной путь только для 140.

На Keenetic есть динамический публичный IPv4 и действующее имя KeenDNS `isergey.netcraze.link`; DNS домена `zsergey.ru` обслуживает Beget. Для публикации 140 должны работать CNAME поддоменов, доступ извне к TCP 80/443 и внутренний путь к прикладным гостям.

Маршрутизация домашней сети, DHCP, DNS и VPN относятся к 109. 140 не является запасным или дополнительным сетевым шлюзом.

### 1.2. Исходные файлы

При реализации создать `guest.yaml`, `provision.yaml` и при необходимости `status.yaml` по общим договорам проекта. Отдельные службы описать в одном повторяемом развёртывании (Docker Compose) с закреплёнными версиями образов. Файлы конфигурации должны устанавливаться явными задачами Ansible с проверенными владельцами и правами; дерево `rootfs/` целиком не копируется.

Целевой набор путей на госте:

~~~text
/opt/web-gateway/compose/                 # запуск Docker Compose
/etc/web-gateway/caddy/Caddyfile         # правила прокси
/etc/web-gateway/authelia/configuration.yml
/etc/web-gateway/authelia/users_database.yml
/etc/web-gateway/secrets/                # локальные служебные секреты
/var/lib/web-gateway/caddy/              # сертификаты и рабочие данные
/var/lib/web-gateway/authelia/           # SQLite и второй фактор
/var/lib/web-gateway/homarr/             # домашние страницы и настройки
/var/lib/web-gateway/management/         # изменения доменов и пользователей из Homarr
~~~

Несекретные файлы воспроизводятся из машинной конфигурации. Рабочие секреты и хеши паролей получают из OpenBao на 910 при развёртывании; в публичном Git их нет. Для каталога секретов требуются ограниченные права. Файлы с хешами и секретами — `0600`, с учётом UID/GID процессов контейнеров.

## 2. Первый запуск

1. По общему механизму создать LXC 140, настроить сеть и проверить доступ к 910, Keenetic и внутренним гостям.
2. Установить Docker и средство Compose средствами общей автоматизации.
3. Создать каталоги и постоянные тома; подготовить несекретные файлы конфигурации.
4. Через 910 получить необходимые значения из OpenBao: Argon2id-хеши паролей, ключи Authelia и секреты OIDC-клиентов; создать локальные рабочие файлы с безопасными правами.
5. Развернуть Authelia и её SQLite, проверить адрес авторизации.
6. Запустить Homarr и подключить к OIDC. Включить вход с паролем и вторым фактором.
7. Поднять Caddy, проверить конфигурацию и доступ к Authelia/Homarr из домашней сети.
8. Настроить CNAME в Beget и переадресацию портов на Keenetic; проверить внешнее HTTPS и сертификаты.
9. Подключить Immich и Open WebUI к OIDC по одному и проверить мобильный Immich. Для Home Assistant оставить собственный вход до принятой рабочей интеграции.
10. Проверить разрешения всех групп, отсутствие прямого внешнего доступа к внутренним портам и возможность восстановления из резервной копии.

Порядок может технически потребовать запустить Caddy перед первоначальной проверкой внешнего адреса Authelia, но готовность входа должна быть подтверждена **до** публикации остальных приложений.

### 2.1. Административная страница Homarr

После запуска основных служб создать закрытую страницу «Администрирование» только для `admins` и разместить два пользовательских виджета Custom Widgets v2: управление Caddy и управление пользователями Authelia. Внутренний обработчик выполняет ограниченные операции и не публикуется через Caddy. Закрепить версию Homarr, поддерживающую виджеты и нужные права.

Настройки, изменяемые через формы, сохраняются в `/var/lib/web-gateway/management/`, а рабочие файлы формируются отдельно. Повторное применение Ansible не должно уничтожать изменения. Перед включением панели проверить права, отказ в прямых запросах без полномочий, проверку конфигурации перед применением и восстановление предыдущего варианта. Полная спецификация — [administration.md](administration.md).

## 3. Проверка и обновление

### 3.1. Приёмочные проверки

- Из внешней сети открываются `home.zsergey.ru` и `auth.zsergey.ru` с действительными сертификатами.
- Вход без второго фактора отклоняется; повторный вход на том же доверенном устройстве использует действующий сеанс.
- Пользователи разных групп получают только разрешённый доступ; сокрытие плитки не заменяет запрета в приложении.
- Мобильный Immich входит через OIDC, загружает фотографии и крупные видео без дополнительной прокси-формы авторизации.
- После перезапуска 140 остаются данные Homarr, SQLite, настройки второго фактора и сертификаты.
- После остановки 910 существующие пользователи продолжают входить с локальными рабочими данными.
- После остановки веб-служб 140 домашние DHCP, DNS, Интернет и VPN продолжают работать через 109.
- Через страницу Homarr администратор может изменить тестовый маршрут и пользователя; ошибочная настройка отклоняется без нарушения действующей службы.
- Пользователи `family` и `guests` не видят административную страницу и не могут вызвать её действия напрямую.
- После повторного развёртывания и восстановления из копии сохранены настройки, введённые через панель.

### 3.2. Обновление

Сначала проверить свободное место и сохранность резервной копии. Затем обновлять по одной службе, закрепляя новую версию образа в управляемой конфигурации; для Authelia проверить совместимость структуры SQLite. После каждого обновления проверить вход, сертификаты, доступ приложений и постоянные данные. Не обновлять Caddy, Authelia и Homarr одним непроверяемым изменением.

## 4. Резервирование и восстановление

### 4.1. Что сохранять

Обязательно сохранять `/var/lib/web-gateway/` (особенно SQLite Authelia, Homarr и `management/` с изменениями из панели), рабочие конфигурации с учётом возможных изменений через веб-интерфейс и сведения, необходимые для восстановления HTTPS. База SQLite должна резервироваться согласованно. Исходные секреты OpenBao и его постоянное состояние резервируются по правилам 910; хранение секретов в Git запрещено.

Сам образ LXC или каталоги контейнерных образов не являются заменой резервной копии постоянных данных.

### 4.2. Полное восстановление

1. Восстановить LXC с тем же CTID, сетевым адресом и доступом к постоянному хранилищу.
2. Воспроизвести Docker Compose и несекретные файлы из проекта.
3. Восстановить каталоги Caddy, Authelia/SQLite и Homarr из резервной копии; при необходимости сформировать локальные рабочие секреты из OpenBao.
4. Запустить службы, проверить HTTPS и вход существующего пользователя с сохранённым вторым фактором.
5. Проверить OIDC для Immich и Open WebUI, страницы Homarr и ограничения групп.
6. Отдельно проверить отсутствие воздействия на маршрутизацию, DNS и VPN гостя 109.

Если нет резервной копии SQLite, регистрацию второго фактора придётся выполнить повторно. Если отсутствует и резервная копия OpenBao с секретами OIDC, прежние подключения приложений нельзя считать восстановленными без повторной выдачи секретов и перенастройки клиентов.
