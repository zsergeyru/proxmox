# Homarr — домашняя страница

**Тип:** локальная спецификация службы  
**Статус:** целевое состояние

Homarr является домашней страницей, с которой пользователь открывает разрешённые ему приложения. Homarr не подменяет авторизацию самих приложений.

## 1. Назначение и доступ

### 1.1. Адрес и содержание

Домашняя страница открывается по `https://home.zsergey.ru` через Caddy. На первом этапе на ней предусмотрены ссылки:

| Раздел | Служба | Условие публикации |
|---|---|---|
| Фотографии | Immich, `photos.zsergey.ru` | Настроена авторизация Immich |
| Умный дом | Home Assistant, `ha.zsergey.ru` | Проверен способ входа Home Assistant |
| ИИ-помощник | Open WebUI, `ai.zsergey.ru` | Настроена авторизация Open WebUI |
| Администрирование | Proxmox и другие инструменты | Только ссылки, работающие из доверенной сети |

Состав ссылок расширяется по мере появления готовых служб. Пустые или неработающие адреса не публикуются. На домашней странице можно показывать состояние приложений и полезные показатели, но для первого запуска такие интеграции не обязательны.

### 1.2. Вход и группы

Homarr использует OIDC-клиента Authelia. Первичный вход требует пароль и второй фактор. Homarr получает сведения о пользователе и разрешённые группы. Участники `admins`, `family` и `guests` видят только разрешённые им страницы и ссылки.

Ограничение видимости плиток — удобство интерфейса, а не защита внутренних адресов. Защита соответствующего приложения должна быть настроена отдельно. Не включать одновременно независимую публичную регистрацию пользователей Homarr и Authelia.

Homarr получает группы из OIDC по признаку `groups`. При первоначальной настройке Homarr необходимо создать одноимённые группы `admins`, `family`, `guests` и назначить им права. На первом запуске Homarr может потребовать пройти мастер создания административной группы `admins`. Наличие групп в токене само по себе не создаёт правила доступа и не означает, что административная страница уже защищена. До проверки группа `family` и `guests` не должна получать административных разрешений.

### 1.3. Встроенное администрирование

В Homarr размещается **закрытая страница «Администрирование»** с тремя пользовательскими виджетами Custom Widgets v2: «Домены Caddy», «Пользователи Authelia» и «Гости Proxmox». Это не публичная страница, и она не заменяет встроенные средства управления самой Homarr.

Виджеты Caddy и Authelia отображают формы и обращаются к отдельному внутреннему обработчику 140. Виджет гостей запрашивает список машин и запускает штатные действия через 910 infra-manager. Они **не редактируют файлы напрямую** и не получают доступ к Docker-сокету или ключам OpenBao. Страница предоставляется только администраторам; права должны проверяться также обработчиком запросов. Спецификация действий Caddy/Authelia и защита от перезаписи Ansible описаны в [administration.md](administration.md); список машин, команды и проверки — в [guest-management.md](guest-management.md).

Используются возможности Custom Widgets v2 закреплённой версии Homarr. Перед реализацией проверить поддержку форм, действий и разграничения доступа на выбранном образе.

## 2. Размещение и настройка

### 2.1. Контейнер и файлы

Homarr работает в отдельном контейнере Docker внутри гостя 140. Его внутренний порт (ориентир для настройки — TCP 7575, проверить по закреплённой версии) доступен только Caddy по внутренней сети Docker. Напрямую в Интернет порт не публикуется.

Целевые пути гостя:

| Путь | Назначение |
|---|---|
| `/var/lib/web-gateway/homarr/` | Постоянные настройки и база Homarr |
| `/opt/web-gateway/compose/` | Воспроизводимый запуск |
| `/var/lib/web-gateway/secrets/` | Локально полученные секреты OIDC и шифрования, если требуются выбранной версией |

`/var/lib/web-gateway/homarr/` должен физически находиться на PVE в `/mnt/bindmounts/infra-state/140-web-gateway/homarr/` через подключение LXC `mp0`. В Compose нужно явно подключить его к тому каталогу внутри образа, где выбранная версия Homarr хранит базу, доски, плитки, роли и пользовательские виджеты. Не создавать безымянный том Docker с единственным экземпляром этих данных и не запускать Homarr без `mp0`.

Закреплённую версию образа, фактические каталоги внутри контейнера, обязательные переменные и подключённые тома нужно описать в машинном развёртывании. Не использовать незакреплённые версии. Git должен содержать воспроизводимые определения административных виджетов, а изменения пользователей Homarr сохраняются в его постоянной базе. Для гостей Proxmox подготовлен импортируемый файл `../widgets/proxmox-guests.json`: один раз добавить его в Homarr, далее список гостей получается от 910 и не требует повторного развёртывания 140. Действия до проверки доступа отключены. Подробнее — [storage.md](storage.md).

### 2.2. Первоначальная настройка

1. Создать постоянный каталог Homarr и задать владельца и права для используемого процесса.
2. Подготовить отдельного OIDC-клиента в Authelia, его адрес возврата взять из конфигурации установленной версии Homarr.
3. Использовать однократно созданный на постоянном томе секрет клиента; не раскрывать его в Compose-файле или журнале.
4. Запустить Homarr через Docker Compose и проверить вход через `home.zsergey.ru`.
5. Создать страницы и плитки, назначить доступ группам; проверить пользователя каждой группы.
6. Сохранить согласованную резервную копию `homarr/` на PVE и проверить восстановление, включая созданные пользователями страницы, права и административные виджеты.

## 3. Проверка и сопровождение

### 3.1. Критерии готовности

Должны выполняться проверки:

- без авторизации домашняя страница не показывает личные приложения;
- при входе используется Authelia и срабатывает второй фактор;
- пользователь `family` не получает административную страницу, `guests` — закрытые семейные ссылки;
- ссылки открывают нужные приложения по HTTPS;
- после перезапуска контейнера сохраняются страницы, плитки и настройки;
- отказ Homarr не влияет на DNS, DHCP, VPN и маршрутизацию гостя 109.

### 3.2. Обновление и восстановление

Перед обновлением создать резервную копию каталога Homarr и закрепить текущую версию образа. После обновления проверить вход, группы, сохранение плиток и работу интеграций.

Для восстановления из Git создать чистый контейнер, подключить прежний `homarr/` на `mp0`, вернуть постоянные данные из независимой копии при необходимости, подключить прежний OIDC-клиент с секретами из `/var/lib/web-gateway/secrets/` и проверить страницы, права и виджеты. Не переносить настройки Homarr в Git как единственный источник, если они изменяются через веб-интерфейс; в Git остаётся воспроизводимое описание запуска.
