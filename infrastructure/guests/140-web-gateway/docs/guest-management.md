# Каталог гостей в Homarr

**Состояние:** машинное описание и код подготовлены; подключение на действующем госте 140 требует проверки.

## 1. Назначение

Homarr на 140 отображает единый список гостей и опубликованных приложений проекта. Состав списка не хранится в настройках Homarr: его формирует штатная команда 910 при `infra-manager sync 140` из `guest.yaml` и `provision.yaml`.

Добавление нового гостя требует обновления Git и выполнения `sync 140`, но **не повторного развёртывания 140**. Homepage и Semaphore сохраняются до завершения испытаний.

Для фактического состояния объектов PVE использовать штатную интеграцию Homarr с Proxmox. Данные Git не могут подтвердить, что приложение действительно установлено или запущено.

## 2. Формирование и хранение

Команда `infra-manager homarr-catalog --repo-root <путь>` читает рабочую копию проекта без сетевых обращений и возвращает один JSON-объект. Она не устанавливает программы и не вызывает Proxmox.

При `sync 140` управляющий контур:

1. Получает свежую выбранную ветку Git.
2. Проверяет существование 140 и его постоянного тома.
3. Формирует `guests.json` через общий Python-модуль.
4. Атомарно обновляет `/var/lib/web-gateway/management/catalog/guests.json` с правами чтения, не изменяя Docker-образы.

Этот каталог расположен на `mp0` гостя 140. При полном развёртывании он формируется точно так же. Содержимое воспроизводимо из Git и не является резервной копией фактического состояния машин.

Поля `configured_image` означают **требуемые версии из Git**. Значения `installed_version` и `available_version` неизвестны и не должны подменяться требуемой версией. Показатель `state` также не является проверкой PVE.

## 3. Чтение из Homarr

Уже установленный Caddy на 140 обслуживает JSON-файл по внутреннему адресу `http://caddy:8081/guests.json`. Порт `8081` доступен только в сети контейнеров Docker, не публикуется в `ports`, не включается в публичные маршруты Caddy.

Caddy получает каталог через подключённый только для чтения том:

`/var/lib/web-gateway/management/catalog → /srv/homarr-catalog:ro`

Импортируемое определение виджета: `../widgets/proxmox-guests.json`. Оно содержит единственный запрос `GET /guests.json`, без служебных ключей и кнопок изменения состояния. Страница с гостями доступна только администраторам Homarr; ограничения страницы и сами приложения необходимо проверять отдельно.

При новом `sync 140` меняется лишь содержимое JSON-файла. Ни Caddy, ни Homarr для этого перезапускать не требуется; достаточно обновить данные виджета.

**Состояние на 17.10.2026:** каталог гостей и описание виджета готовы в Git, но импорт и загрузка в работающем Homarr ещё не проверены. На первоначальном снимке пользовательской доски один встроенный блок Homarr сообщает об ошибке; без журнала нельзя установить её причину. Автоматическое удаление или изменение доски для скрытия ошибки запрещено.

## 4. Граница полномочий

JSON предназначен **исключительно для чтения**. Он не запускает команды. Пользовательские действия `status`, `sync`, `repair` и `deploy` выполняются отдельно через штатный механизм `infra-manager` на 910 или PVE, а не через публичный адрес каталога.

Существующие Homepage и их посредник `portal_gateway.py` остаются действовать до переноса и проверки команд управления. Для кнопок Homarr потребуется отдельно выбрать безопасный способ подтверждённого запуска штатных команд. Не размещать токены PVE, Docker-сокет или закрытые ключи в Homarr.

## 5. Первое подключение и проверки

1. Обновить 910 обычной установкой управляющего контура, чтобы появилась команда формирования каталога и обновления Git при `sync`.
2. Один раз применить изменения 140 штатным `deploy 140`: он подготовит внутренний Caddy-сайт и подключение каталога. Проверить, что существующие данные Homarr и Authelia сохранились.
3. Проверить наличие файла `/var/lib/web-gateway/management/catalog/guests.json` и внутренний ответ Caddy `http://caddy:8081/guests.json` из сети контейнеров.
4. Импортировать `../widgets/proxmox-guests.json` в Homarr на закрытую страницу «Администрирование»; убедиться, что список отображается и версии подписаны как требуемые.
5. Добавить гостя в Git, выполнить **только** `infra-manager sync 140`, перечитать виджет и убедиться, что новый гость появился без пересоздания 140.
6. Проверить, что адрес каталога недоступен снаружи, а при отказе в `sync` прежний корректный файл не повреждён.
7. После приёмки перенести управляющие кнопки и лишь затем обсуждать удаление Homepage.

Для проверки непосредственно из LXC 140 можно использовать `docker exec web-gateway-caddy wget -qO- http://127.0.0.1:8081/guests.json` при наличии `wget` в образе Caddy; иначе выполнить HTTP-запрос с Homarr или временного диагностического контейнера во внутренней сети.
