**Тип:** состояние реализации  
**Статус:** документация, машинные описания и базовая роль Ansible подготовлены; запуск 140 не подтверждён.

## 1. Принято

- Отдельный LXC 140 — `web-gateway`, Debian 13, адрес по VMID `192.168.1.40`.
- Caddy, Authelia и Homarr; для Authelia — SQLite.
- Около 3–4 пользователей и группы `admins`, `family`, `guests`.
- Единый вход с паролем и вторым фактором; OIDC для совместимых приложений.
- Несекретная конфигурация в Git; хеши Argon2id и секреты OIDC на постоянном `mp0`, без связи с OpenBao.
- Постоянные данные Authelia/2FA, Homarr, Caddy и административной панели на существующем томе PVE `infra_state`: `/mnt/bindmounts/infra-state/140-web-gateway` → `mp0` → `/var/lib/web-gateway`; резервируются независимо от LXC.
- Воспроизводимые файлы и установки — из Git; постоянные секреты, хеши и данные — из сохранённого `mp0`. Запуск без действительного подключения запрещён.
- Доступ по поддоменам `zsergey.ru` через прямой публичный IPv4 Keenetic с KeenDNS.
- Отсутствие зависимости сетевых функций 109 от состояния веб-служб 140.
- Закрытая страница «Администрирование» в Homarr с тремя виджетами Custom Widgets v2 для Caddy, Authelia и гостей Proxmox; внутренний обработчик изменений Caddy/Authelia не публикуется наружу, а операции с машинами выполняются через 910.

## 2. Подготовлено

Есть локальный паспорт гостя, оглавление, спецификации Caddy, Authelia, Homarr, [административной страницы](administration.md), [управления гостями](guest-management.md) и [отдельного хранения](storage.md), инструкция развёртывания и документ решений. Созданы машинные описания `../guest.yaml`, `../provision.yaml` и `../status.yaml`. Они описывают целевое состояние и **не подтверждают** существование LXC в Proxmox.

## 3. Осталось реализовать

1. Подключение роли `web_gateway` к общему сценарию Ansible, Compose и шаблоны Caddy/Authelia/Homarr подготовлены в ветке разработки; требуется проверка выполнения на настоящем LXC.
2. Проверить на настоящем LXC первоначальное создание секретов и `admin` на постоянном `mp0`, сохранение при повторном запуске и безопасный просмотр первичного пароля из терминала PVE.
3. Проверить безопасное подключение существующего тома `infra_state` через `pve_storage`, работу `mp0`, запрет запуска без него и отсутствие форматирования/очистки данных при повторном развёртывании.
4. Проверить самостоятельную смену пароля Authelia и извещения по SMTP; файловый извещатель пока только для проверки.
5. Развернуть и проверить Caddy, Authelia, Homarr и постоянное состояние SQLite после создания секретов; подтвердить в работающем контейнере правильность OIDC и путей данных. Все уникальные данные контейнеров должны находиться на явно подключённых каталогах `/var/lib/web-gateway/`.
6. Подготовить DNS-записи Beget, перенаправление портов Keenetic и локальное разрешение имён.
7. Проверить подготовленного OIDC-клиента Immich; включать OAuth на стороне Immich только через `deploy 340`. Позднее подключить Open WebUI, проверить поддержку Home Assistant.
8. Проверить ограничения групп, 2FA, работу мобильного Immich и **пересоздание чистого LXC с сохранённым `mp0`**, восстанавливающим прежних пользователей, домены, сертификаты, страницы Homarr и виджеты.
9. Измерить потребление ресурсов 140 и уточнить выделенную память.
10. Реализовать и проверить виджеты Caddy и Authelia с ограничением прав и внутренний обработчик изменений; обеспечить проверку настроек до применения, сохранение состояния и откат ошибочной конфигурации.
11. Подготовлены формирование каталога из Git при `sync 140`, внутренний маршрут Caddy для чтения JSON и импортируемый виджет Homarr. Нужно один раз проверить новое описание Caddy на 140, импорт виджета и обновление списка новым гостем без повторного `deploy 140`. Отдельный HTTPS API 910 исключён из целевого решения.
12. Проверить, что каталог доступен только во внутренней сети Docker и не содержит секретов, а список пополняется после `sync 140`. Управляющие кнопки пока не входят в виджет: их безопасное перенесение с Homepage будет отдельным этапом; до проверки роль `portal` и её службы сохраняются.
13. Создать и испытать отдельное резервное копирование папки `140-web-gateway` на SMB и USB с согласованной копией SQLite, проверкой подключения и восстановлением. Сам факт записи `persistence.backup_required` не создаёт задания.

## 4. Признаки готовности

Работа считается завершённой только после успешных проверок из [operations.md](operations.md): внешний HTTPS, второй фактор, запреты групп, мобильный Immich, управление Caddy, Authelia и гостями Proxmox только администраторами, физическое отделение данных от корневой файловой системы LXC, отказ запуска без `mp0`, сохранение постоянного состояния после повторного `deploy/sync`, восстановление из независимой резервной копии и отсутствие воздействия на домашнюю сеть при остановке 140.
