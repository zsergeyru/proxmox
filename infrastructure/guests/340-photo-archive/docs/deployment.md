# Подготовка развёртывания 340

## Требуемое состояние

Создать LXC 340 обычным механизмом гостевого контура на основе `guest.yaml`. Профиль `debian-lxc-docker` предусматривает вложенную контейнерную среду.

Перед запуском Immich **обязательно** подготовить на PVE два независимых от rootfs каталога: `/mnt/bindmounts/photo-archive/data` и `/mnt/bindmounts/photo-archive/state`. Подключить их к LXC как `/srv/photo-archive` (`mp0`) и `/mnt/persistent-state` (`mp1`) соответственно. Наличие каталога в госте само по себе недостаточно: требуется проверка, что это именно отдельное постоянное подключение. Исходные снимки доступны Immich только для чтения; служебные данные `/srv/photo-archive/immich` должны быть доступны для записи. Каталог PostgreSQL `/mnt/persistent-state/postgres` размещается на локальной Linux-файловой системе PVE (не SMB). В `/mnt/persistent-state/immich` лежат производные медиаданные, а в `/mnt/persistent-state/secrets/immich.env` — защищённые параметры.

Адрес интерфейса определяется общей адресацией гостей проекта. Пользовательский порт Immich: 2283.

## Ограничения текущей подготовки

Машинные требования заданы в `guest.yaml` и `provision.yaml`. Общий playbook подключает роль `photo_archive`, которая проверяет постоянное подключение хранилища и наличие `originals`, создаёт локальный секрет базы при первом запуске, формирует Docker Compose и запускает Immich API, PostgreSQL и Redis. **Развёртывание на настоящем Proxmox ещё не проверено.** Без готовых `mp0` и `mp1` роль должна завершиться ошибкой до запуска приложения.

До первого развёртывания необходимо:
- заменить текущий канал версии Immich `v3` на конкретную проверенную версию перед производственным запуском;
- подключить восстановление секретов из OpenBao: сейчас пароль генерируется один раз и сохраняется на внешнем постоянном томе, но его источник пока не OpenBao;
- автоматизировать создание PVE-каталогов, их права и два bind-mount; текущая роль проверяет уже подключённые точки и не создаёт их;
- проверить Compose, API-only режим и отсутствие публикации PostgreSQL/Redis в сеть;
- согласовать сетевой доступ Windows к общей очереди, базе и медиаданным **без публикации этих служб в интернет**; до этой настройки удалённый работник не подключится;
- предусмотреть первый запуск сервера без Windows и последующую настройку внешней библиотеки;
- установить и проверить резервирование базы, затем проверить восстановление.

Предварительный лимит памяти LXC — 4 ГБ для первого запуска без машинного обучения. Это проверяемая гипотеза, а не гарантированное потребление. При необходимости увеличить память после измерений.

Важно: модуль `mount_point` в OpenTofu-провайдере bpg/proxmox требует для привязки каталога PVE полномочий `root@pam`; обычный API-токен 910 не подходит. Подключение каталогов нужно выполнить через согласованный PVE-only шаг с минимальными полномочиями, а не через обход этого ограничения.

## Проверки при вводе

Сначала испытать 100–200 фотографий, затем подтвердить доступ по API и просмотр, запуск и перезапуск PostgreSQL, Redis, создание индексов, сетевой доступ с Windows, остановку фонового работника без потери галереи, реальное потребление памяти и процесс обновления.
