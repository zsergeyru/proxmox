# Подготовка развёртывания 340

## Требуемое состояние

До появления NAS хранилища размещаются **внутри существующего `local-lvm`
на основном NVMe 512 ГБ**, без изменения разметки диска:

| Логический том | Предел | Подключение на PVE | Содержимое |
| --- | ---: | --- | --- |
| `photo_archive` | 240 ГиБ | `/mnt/bindmounts/photo-archive` | Оригиналы и крупные медиаданные |
| `infra_state` | 40 ГиБ | `/mnt/bindmounts/infra-state` | Постоянные состояния LXC |

Оба тома — LVM-thin в группе `pve`, пул `data`, с файловой системой ext4.
Размеры задают верхний предел, а реальное физическое место в `local-lvm`
занимается по мере записи. **40 ГиБ — общий том состояний разных
контейнеров**, а не отдельный диск для каждого гостя.

```text
/mnt/bindmounts/
├── photo-archive/                 ← том 240 ГиБ
│   ├── data/
│   │   └── originals/            ← исходные фотографии
│   └── immich-media/              ← миниатюры, видео, другие медиа
│
└── infra-state/                   ← том 40 ГиБ
    └── 340-photo-archive/
        ├── postgres/              ← база Immich
        └── secrets/               ← параметры доступа
```

При `infra-manager deploy 340` на LXC настраиваются три подключения:

| PVE | Внутри 340 | Доступ |
| --- | --- | --- |
| `photo-archive/data` | `mp0: /srv/photo-archive` | Только чтение |
| `infra-state/340-photo-archive` | `mp1: /mnt/persistent-state` | Чтение/запись |
| `photo-archive/immich-media` | `mp2: /srv/photo-archive-media` | Чтение/запись |

Существующий системный диск LXC 340 (16 ГиБ) не меняется.
PostgreSQL и секреты не размещаются вместе с большими фотографиями.

Общий сценарий подготовки на PVE сначала проверяет имеющиеся `mp0/mp1/mp2`,
затем создаёт только отсутствующие тома, форматирует ext4 **только при их
первом создании**, записывает подключения по UUID в `/etc/fstab`,
монтирует тома, создаёт нужные каталоги и подключает их к LXC.
На PVE также устанавливается сценарий `pre-start`: перед **каждым**
запуском 340 он проверяет оба реально подключённых тома. Если том не
подключён, запуск 340 отменяется; остальные VM/LXC не затрагиваются.
Если для добавления подключений нужен перезапуск 340, он выполняется.

Если у LXC включена защита `protection: 1`, она временно снимается
только для изменения `mp0/mp1/mp2` и `hookscript`. После этого
защита **обязательно восстанавливается**, в том числе при ошибке.
Если настройка оборвалась, повторный `infra-manager deploy 340`
продолжит работу с уже созданными томами без их удаления и форматирования.
Не оставлять LXC без защиты вручную.

**Повторное развёртывание не форматирует и не удаляет существующие тома.**
Если том был впервые создан этим сценарием и форматирование оборвалось,
маркер незавершённой подготовки разрешает повторить его только при отсутствии
файловой системы. Неизвестные тома не форматируются. При повреждении
уже созданной ext4 процедура останавливается без исправления данных.
Если существующий том имеет неподходящую файловую систему, принадлежит
другому пулу или меньше указанного размера, автоматизация останавливается.
Ручное увеличение тома допускается и не откатывается развёртыванием.
Уменьшение и перенос данных не выполняются автоматически.

Существующее состояние 910 (OpenBao, Semaphore) **пока остаётся на
прежнем подключении**. Переход 910 или других LXC на `infra_state` —
отдельная операция с резервированием, остановкой служб, копированием и
проверкой содержимого. Полноценные VM остаются на собственных дисках
и резервируются целиком.

## Первый запуск и проверки

1. Проверить свободное место PVE: `pvesm status` и `lvs`.
2. Выполнить `infra-manager deploy 340`.
3. На PVE проверить `findmnt /mnt/bindmounts/photo-archive` и
   `findmnt /mnt/bindmounts/infra-state`.
4. Убедиться в наличии `mp0/mp1/mp2` через `pct config 340`.
5. Внутри 340 проверить `mountpoint /srv/photo-archive`,
   `mountpoint /mnt/persistent-state` и
   `mountpoint /srv/photo-archive-media`.
6. Проверить запуск Immich/PostgreSQL и резервное копирование.
7. Перезапустить 340 и проверить, что при отключённом томе
   сценарий `pre-start` запрещает его запуск; не выполнять этот тест
   без резервной копии и согласованной остановки приложений.

Рекомендуется контролировать не только свободное место в ext4, но и
заполнение общего тонкого пула `pve/data`, где находятся диски остальных
VM/LXC. Если заполнить весь пул, пострадают и другие гости. Объём
снимков и скорость освобождения места после удаления файлов также
требуют учёта (TRIM).

**Резервные копии:** данные подключений `mp0/mp1/mp2` не входят
автоматически в резервную копию LXC. Отдельно резервируются PostgreSQL,
параметры и фотоархив; хранилище `backup` сейчас почти заполнено.

## Перенос фотоархива на NAS

После появления NAS оригиналы и большие медиаданные могут быть перенесены
туда с сохранением путей внутри 340. Перенос выполняется только после
проверки целостности и резервных копий. Затем том 240 ГиБ можно удалить
отдельным осознанным действием. Том состояний 40 ГиБ остаётся на NVMe;
NAS для работающей базы PostgreSQL и OpenBao не используется.

## Ограничения текущей подготовки

Сценарий подготовки тома, каталогов и подключений внесён в проект;
его выполнение на реальном PVE необходимо проверить отдельно.
Начальный запуск использует закреплённый Immich `v3.3.1` и выполняет
API и фоновые задания непосредственно в 340, поэтому он может работать
до настройки Windows. Пароль Redis хранится вместе с параметрами
PostgreSQL на томе 40 ГиБ. Порты PostgreSQL/Redis извне Docker не
открываются.

Когда Windows-обработчик будет готов и получит доступ к тем же файлам,
флаг `photo_archive.remote_worker.enabled` переводится в `true`.
Тогда на 340 остаётся API, а сетевые порты PostgreSQL/Redis открываются
на административном адресе 340. До этого нужно ограничить доступ к
портам с остальных устройств и настроить тот же пароль Redis на Windows.
Подробности — в `services.md`. Без Windows этот флаг включать нельзя:
новые фотографии останутся без фоновой обработки.

Остаются проверки на действующем PVE: сеть Docker внутри LXC,
доступность образов, разрешения файловой системы, работа Compose,
реальное потребление памяти и восстановление из резервной копии.

Предварительная память LXC — 4 ГБ; достаточность подтвердить измерениями.
Для подготовки хранилища необходим действующий отдельный root SSH-доступ
из 910 к PVE: обычный API-токен OpenTofu не может выполнить такую
привязку каталогов.

## Проверки при вводе

Сначала испытать 100–200 фотографий, затем подтвердить просмотр,
работу API, PostgreSQL, Redis, индексов, связь с Windows,
работу без фонового работника, потребление памяти и обновления.
