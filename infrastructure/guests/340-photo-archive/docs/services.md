# Службы и устройство 340

## Назначение и размещение

340 — LXC Debian с постоянно доступным веб-интерфейсом Immich. Исходные снимки остаются неизменными, каталогизация выполняется в базе.

| Место | Состав | Ответственность |
| --- | --- | --- |
| LXC 340, Proxmox | Immich с `api` и `microservices` до подключения Windows, PostgreSQL и Redis | Просмотр, API, сканирование, миниатюры и каталог |
| Основной компьютер Windows | Планируемый второй экземпляр `immich-server` без `api`, `immich-machine-learning`, LM Studio/Qwen | После подключения — фоновые задания, распознавание и описание |
| Proxmox | Постоянное файловое хранилище | Оригиналы, миниатюры и служебные медиаданные |
| Windows | Яндекс Диск и средство односторонней передачи | Приём фотографий из облака, независимая локальная копия |

После настройки Windows два экземпляра `immich-server` образуют **одну установку**. У них должны совпадать версии, настройки доступа к PostgreSQL/Redis и внутренние пути к общим файлам. Только экземпляр на 340 обслуживает пользовательские API-запросы. Применение разделения работников настраивается средствами Immich; точные переменные сверяются с документацией закреплённой версии перед внедрением. Не допускаются два независимых сервера, изменяющих одну базу без согласованной конфигурации.

В начальном режиме `remote_worker.enabled: false` сервер 340 сам выполняет
обработку и сканирование. Внешние порты базы и Redis не опубликованы.
После включения `remote_worker.enabled: true` на 340 остаётся только `api`,
а фоновые задания переходят на подготовленный Windows-обработчик.
При отключении Windows новые задачи будут ждать его возвращения.

## Ресурсы и ограничения

Текущая опытная конфигурация LXC: 2 vCPU, 4 ГБ ОЗУ, системный диск 16 ГБ. Это **не подтверждённая производственная норма**: официальные рекомендации Immich для полного развёртывания выше. Потребление памяти и устойчивость проверяются на тестовой библиотеке, затем лимиты корректируются. Суммарные ресурсы PVE не должны мешать 100 и 910.

Использование Docker внутри LXC допускается в рамках проекта только после испытаний; это менее поддерживаемый Immich способ по сравнению с VM. Перед внедрением проверить nesting, права томов, работу Docker, обновления и восстановление LXC. При несовместимости вернуться к выбору VM без изменения роли 340.

PostgreSQL обязателен для Immich; SQLite не поддерживается в качестве его замены. Данные PostgreSQL держать на локальной файловой системе PVE, подключённой в LXC отдельно от rootfs через `/mnt/persistent-state`, не на SMB. Redis обслуживает общую очередь. По умолчанию сетевые порты PostgreSQL и Redis за пределы Docker не опубликованы.
В режиме Windows-работника они публикуются на адресе LXC 340, с паролями;
доступ необходимо **дополнительно ограничить сетевыми правилами только
с адреса основного компьютера**, исключив интернет. Включать режим до
настройки правил нельзя.

## Обработка и поиск

Специализированная служба Immich ML на Windows обрабатывает изображения для поиска и лиц. После переключения Windows второй `immich-server` выполняет задания,
включая формирование миниатюр и извлечение метаданных. На Windows эти службы запускаются последовательно либо с ограничением ресурсов, чтобы не конфликтовать за видеопамять.

Qwen через LM Studio создаёт короткие описания, метки и предложения о качестве. Результаты сохраняются отдельно с идентификатором файла, версией модели и временем анализа. Интеграцию с Immich выполнять только через поддерживаемый API или штатный механизм метаданных, без прямого изменения его таблиц. До доказанной интеграции описания Qwen **не считаются доступными в поиске Immich**.

Никаких автоматических удалений, перемещений и изменения оригиналов по выводам моделей.

## Дополнения Immich

В составе гостя 340 предусмотрены Immich Memories Notify для ежедневных
воспоминаний, Immich Power Tools для ручного управления архивом и Immich Analyze
для описания новых снимков локальной моделью. Они используют API Immich;
Power Tools также имеет доступ к PostgreSQL только по внутренней сети Docker.
Подробные настройки и условия включения изложены в [дополнениях](addons.md).
