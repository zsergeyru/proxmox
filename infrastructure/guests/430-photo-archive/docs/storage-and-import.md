# Хранение и пополнение фотоархива

## Исходные данные

Источник: автоматическая загрузка с телефонов в Яндекс Диск и скачивание на основной компьютер Windows. Исходный архив — приблизительно 125 ГБ. Существуют три логически раздельных экземпляра: облачный, Windows и Proxmox. Это не заменяет отдельной проверенной резервной копии базы и защиты от ошибочного удаления.

На Proxmox фотографии хранятся в одном логическом каталоге без тематического разбиения. Альбомы, люди и категории существуют в Immich. Файлы не переименовываются и не перемещаются при классификации. Коллизии одинаковых имён при передаче разрешаются без потери содержимого (например, присвоением уникального технического имени **до** включения в библиотеку).

Внутри 430 должен оставаться постоянный путь к оригиналам, например `/srv/photo-archive/originals`. Для фонового работника Windows доступ к тем же файлам и к записываемым служебным данным Immich организуется через сетевое хранилище с **теми же путями внутри контейнеров**. PostgreSQL в общую сетевую папку не выносить. Проверить работу прав, создания миниатюр и одновременного доступа до полного импорта.

На первом этапе источник данных — существующий SSD PVE 512 ГБ, при условии проверки реального свободного места и общего объёма PVE. Через 1–2 месяца предполагается отдельный SSD 1 ТБ. Путь библиотеки внутри 430 при переносе не меняется; до переключения сверяются контрольные суммы и наличие резервной копии. Для LXC предпочтителен выделенный каталог на хосте и подключение `mp0` с управляемыми правами. Точный путь на хосте и способ монтирования уточняются до реализации.

## Доставка файлов

Передача только Windows → Proxmox, без зеркального удаления. Приёмник не получает административного доступа к PVE. Передавать файлы лишь после завершения скачивания Яндекс Диском; использовать промежуточный каталог вне видимости Immich и атомарную публикацию после проверки размера/контрольной суммы. Повторные запуски не создают повторных файлов; ошибки фиксируются в журнале.

По окончании передачи вызывается или планируется штатное сканирование внешней библиотеки Immich. Каталог оригиналов подключать как External Library только для чтения со стороны приложения; обработчику Immich предоставлять запись в отдельные служебные каталоги для миниатюр и других производных файлов.

Обратная синхронизация, автоматическое удаление и физическая сортировка не предусмотрены. Исключение исходного файла из Windows или Яндекс Диска не вызывает его удаление на Proxmox.

## Переход на новый SSD

Остановить передачу и сканирование; сделать резервную копию и зафиксировать контрольные суммы. Скопировать архив на новый SSD, проверить файлы, переключить источник постоянного пути, проверить доступ на 430 и Windows, затем запустить выборочное сканирование. Старую копию удалять только после отдельного подтверждения успешного перехода.
