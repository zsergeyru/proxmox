# Решения по гостю 430

## Принятые решения

1. **Immich сохраняем.** Богатый поиск, лица, альбомы, мобильный доступ важнее минимального потребления ресурсов.
2. **Одна установка, два сервера приложения.** На постоянно включённом LXC 430 — API, PostgreSQL, Redis и веб-интерфейс. На Windows — фоновые работники, Immich ML и LM Studio/Qwen. Общая база и общие медиаданные; два независимо управляемых фотокаталога не создаются.
3. **LXC вместо VM на первом этапе.** Приоритет — меньшие расходы памяти и прямое подключение каталога PVE. Компромисс: Docker в LXC не является рекомендуемой конфигурацией Immich. Перед вводом обязательно испытание.
4. **PostgreSQL остаётся.** Это обязательный компонент выбранной галереи; замена на SQLite не предусматривается.
5. **Физической сортировки нет.** Оригиналы остаются в одном каталоге, категории и альбомы — в базе. Дубликаты и сомнительное качество показывать для проверки, без удаления.
6. **Три места хранения.** Яндекс Диск → Windows → Proxmox, односторонняя передача без удаления. Резервирование базы отдельно.
7. **Поэтапная смена SSD.** Сейчас существующий SSD PVE 512 ГБ после проверки места; позднее отдельный SSD 1 ТБ, сохраняя внутренние пути библиотеки.
8. **Первоначальные ресурсы — только гипотеза.** 2 vCPU и 2 ГБ ОЗУ для пробного LXC; итоговый размер определяется испытаниями.
9. **Без специального развёртывания 430.** Использовать единый механизм 910/990 и документационные правила 000.

## Что проверить до реализации

- Совместимость версии Immich с разделением работников между двумя узлами, общими путями и доступом по сети.
- Работа Docker в LXC, права к файлам и обмен медиаданными через Windows/WSL2.
- Память и свободное место существующего PVE.
- Способ подключения нового SSD и неизменность путей.
- Допустимый механизм записи результатов Qwen в доступный пользователю поиск.
- План резервного копирования и тест восстановления PostgreSQL.

Это утверждение архитектуры, а не запись о выполненном развёртывании.
