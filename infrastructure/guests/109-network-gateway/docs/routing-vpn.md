## 1. Основная модель

109 является маршрутизатором между HOME и доступными выходами:

~~~text
WAN → Keenetic 10.0.0.1
VPN1 → AmneziaWG
VPN2 → другой WireGuard/AmneziaWG при необходимости
proxy → sing-box только для специальных сценариев
~~~

Маршрут выбирается централизованно через связку SmartDNS, nftables sets, fwmark, ip rule и отдельные таблицы маршрутизации.

## 2. nftables и PBR

nftables отвечает за:

- межсетевой экран;
- forwarding;
- классификацию трафика;
- наборы адресов;
- fwmark;
- только необходимый NAT для отдельных VPN-сценариев.

Для обычного WAN через Keenetic SNAT/MASQUERADE на 109 не применяется.

Пример:

~~~text
HOME packet
  ↓
nftables
  ├── destination in vpn set → mark VPN
  ├── source in vpn clients  → mark VPN
  └── otherwise              → no mark
  ↓
ip rule
  ├── VPN mark → VPN table
  └── default  → main
~~~

Номера меток и таблиц должны быть единообразно определены в конфигурации.

## 3. Обычный WAN

~~~text
109 WAN: 10.0.0.2/30
gateway: 10.0.0.1
~~~

Keenetic выполняет NAT к провайдеру и имеет маршрут к HOME через 10.0.0.2.

Это даёт симметричный путь без двойного NAT.

## 4. VPN

Основной вариант — AmneziaWG/WireGuard.

Каждый туннель является отдельным выходом и получает собственную таблицу маршрутизации, если через него проходит выборочный трафик.

VPN не должен самостоятельно менять глобальный default route без контроля общей PBR-схемы.

Маршрут через VPN может зависеть от доменной группы, IP назначения, клиента, сегмента или явного служебного правила.

sing-box используется только там, где нужен прокси или транспорт, который нельзя выразить обычным L3 VPN.

## 5. Запуск и контроль

После загрузки VM:

1. поднимаются интерфейсы;
2. включается IP forwarding;
3. загружается nftables;
4. создаются таблицы маршрутизации и ip rule;
5. поднимаются VPN;
6. запускается SmartDNS;
7. выполняются проверки.

Сбой одного VPN не должен ломать обычный WAN, если для конкретного правила не задан режим fail-closed.

## 6. Проверка и восстановление

Проверяются:

- прямой WAN;
- отсутствие двойного NAT;
- каждый VPN;
- тестовая доменная группа VPN;
- правило по клиенту;
- возврат к обычному WAN после отключения VPN;
- восстановление после перезапуска VM.

Для восстановления нужны nftables-конфигурация, таблицы и ip rule, конфигурация WireGuard/AmneziaWG, systemd-службы, Ansible-роли и VPN-секреты из внешнего хранилища.
