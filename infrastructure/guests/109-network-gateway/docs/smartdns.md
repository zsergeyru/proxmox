## 1. Назначение

SmartDNS является внутренним DNS-слоем политики маршрутизации VM 109. Клиенты HOME обращаются к AdGuard Home, а AdGuard Home передаёт внешние запросы в SmartDNS.

Он должен:

- получать внешние DNS-запросы от AdGuard Home;
- кэшировать ответы;
- использовать несколько внешних DNS;
- поддерживать обычный DNS, DoH и DoT;
- разделять домены на группы direct, vpn1, vpn2 и другие при необходимости;
- передавать адреса выбранных групп в соответствующие nftables sets;
- не принимать самостоятельных решений о маршруте пакетов.

## 2. Требуемая конфигурация

### 2.1. Размещение

Допускается запуск SmartDNS в Docker.

Целевой каталог:

~~~text
/opt/network-gateway/smartdns/
~~~

Постоянные файлы конфигурации формируются из проекта через Ansible.

Docker-сеть не становится частью общей маршрутизации квартиры.

### 2.2. Доступ

SmartDNS не является клиентской точкой входа DNS. Он должен быть доступен AdGuard Home локально на 109. Прямой доступ клиентов HOME, TRANSIT и внешних интерфейсов к SmartDNS не требуется.

### 2.3. Внешние DNS

Требуется несколько upstream-серверов:

- хотя бы два независимых upstream;
- шифрованный DNS для основных запросов;
- резерв при отказе одного upstream;
- отдельные группы допускаются для специальных доменов.

Конкретные поставщики DNS могут меняться без изменения архитектуры.

## 3. Локальные имена и DHCP

### 3.1. home.arpa

Постоянный внутренний домен — home.arpa.

Устройства с DHCP-резервациями могут получать понятные имена, например:

~~~text
nas.home.arpa
printer.home.arpa
tv-living.home.arpa
~~~

### 3.2. Согласованность с DHCP

Основной DHCP HOME и локальные имена home.arpa принадлежат AdGuard Home. Он хранит DHCP-аренды, постоянные привязки и понятные имена клиентов.

SmartDNS не является источником назначения IP-адреса и не ведёт локальный реестр домашних устройств. Отдельный список клиентов в Git для синхронизации DHCP и DNS не требуется.

## 4. Связь с маршрутизацией

SmartDNS может добавлять IP-адреса выбранных доменных групп в именованные nftables sets.

~~~text
domain group direct / vpn1 / vpn2
  ↓
SmartDNS resolves IP
  ↓
соответствующий nftables set
  ↓
fwmark
  ↓
ip rule
  ↓
WAN / VPN1 / VPN2
~~~

SmartDNS не меняет default route, не управляет WireGuard/AmneziaWG, не заменяет nftables и не выполняет NAT.

## 5. Запуск и проверка

После перезапуска VM SmartDNS запускается автоматически.

До перевода всей HOME на DNS 109 проверяются:

- синтаксис конфигурации;
- доступность upstream;
- запрос AdGuard Home к SmartDNS;
- обычный внешний домен через direct;
- заполнение nftables set для тестового домена;
- сохранение DNS при отказе одного upstream.

## 6. Восстановление

Для восстановления нужны:

- декларативная конфигурация из Git;
- образ или пакет SmartDNS;
- Ansible-роль;
- группы доменов;
- правила связи групп с nftables sets.

Секреты внешних DNS, если они появятся, хранятся вне Git.
