# AdGuard Home на 109

**Тип:** локальная спецификация службы

## 1. Назначение

AdGuard Home выполняет на 109 четыре функции:

- основной DHCP для HOME;
- клиентская точка входа DNS;
- реестр обнаруженных домашних клиентов;
- локальные имена в домене `home.arpa`.

AdGuard Home не выбирает WAN/VPN и не заменяет SmartDNS, nftables или `nfqws2`.

## 2. DHCP и клиенты

### 2.1. Основной DHCP

DHCP работает только на LAN/HOME.

Целевой динамический диапазон:

~~~text
192.168.1.100–192.168.1.250
~~~

Клиенты получают:

- адрес и маску HOME;
- gateway `192.168.1.9`;
- DNS `192.168.1.9`;
- локальный домен `home.arpa`.

DHCP на TRANSIT не включается.

### 2.2. Регистрация устройства

Новое устройство не обязано заранее присутствовать в Git.

При первом подключении:

~~~text
устройство
  ↓
DHCP lease
  ↓
AdGuard Home видит клиента
  ↓
имя клиента
  ↓
<name>.home.arpa
~~~

Если устройство передало понятное имя, оно может использоваться сразу.

Если имя отсутствует или неудобно, оператор один раз назначает понятное имя в AdGuard Home, например:

~~~text
pc-sergey
pc-sveta
phone-sergey
phone-sveta
laptop-sergey
laptop-sveta
~~~

После этого имя должно быть доступно через DNS как `<name>.home.arpa`.

### 2.3. Постоянные адреса

Для устройства, которому нужен постоянный адрес, используется DHCP-резервация в AdGuard Home.

Отдельный полный реестр домашних устройств в Git не требуется.

Инфраструктурные и постоянные адреса рекомендуется выделять вне динамического диапазона.

## 3. DNS и home.arpa

### 3.1. Клиентская точка входа

Клиенты HOME используют DNS на адресе 109:

~~~text
192.168.1.9
~~~

AdGuard Home отвечает локально за имена `home.arpa`.

Внешние запросы передаются в SmartDNS.

### 3.2. Локальные имена

Локальные имена не должны зависеть от внешнего DNS.

Примеры:

~~~text
pc-sergey.home.arpa
phone-sveta.home.arpa
nas.home.arpa
~~~

Домен `.local` для этой задачи не используется, потому что он оставлен для mDNS.

## 4. Связь со SmartDNS

Рабочая цепочка:

~~~text
клиент HOME
  ↓
AdGuard Home
  ├── home.arpa → локальный ответ
  └── внешний домен
          ↓
       SmartDNS
          ↓
       upstream DNS
~~~

SmartDNS дополнительно классифицирует внешние домены по группам маршрутизации и заполняет nftables sets.

AdGuard Home не должен дублировать эти правила маршрутизации.

## 5. Развёртывание и данные

### 5.1. Размещение

AdGuard Home может работать в Docker на 109.

Маршрутизация HOME не должна зависеть от Docker bridge. DHCP и DNS должны быть доступны с LAN-интерфейса 109.

Точный образ, версия, каталоги и способ подключения сети должны быть закреплены в `provision.yaml` и файлах развёртывания до реализации.

### 5.2. Постоянные данные

Нужно сохранять:

- настройки AdGuard Home;
- DHCP-резервации;
- назначенные пользователем имена клиентов;
- остальные локальные настройки, которые нельзя восстановить только из Git.

Кэш и временные журналы не являются критичными данными.

Пароли и другие секреты в Git не помещаются.

## 6. Проверка и восстановление

### 6.1. Проверка

Должны подтверждаться:

- выдача DHCP только на HOME;
- получение клиентом gateway и DNS `192.168.1.9`;
- появление нового клиента;
- назначение понятного имени;
- разрешение `<name>.home.arpa`;
- передача внешнего DNS-запроса в SmartDNS;
- отсутствие DHCP на TRANSIT;
- восстановление после перезапуска.

### 6.2. Восстановление

Для восстановления нужны:

- машинное описание службы;
- файлы развёртывания;
- постоянное состояние AdGuard Home либо его резервная копия;
- доступ к SmartDNS;
- сетевые параметры 109 из `guest.yaml`.

После восстановления сначала проверяются DHCP и локальный DNS, затем внешний DNS через SmartDNS.
