# ADR 001 — граница ответственности пограничного маршрутизатора и `109-network-gateway`

Статус: **принято**.

## Контекст

После переезда сеть квартиры будет разделена как минимум на MAIN, IOT и CAMERAS. Ранее оставалось открытым, будет ли `109-network-gateway` одновременно выполнять роль L3-шлюза локальных VLAN или эти функции останутся на физическом пограничном маршрутизаторе.

Если локальные VLAN зависят от VM `109`, остановка Proxmox или этой VM лишает квартиру базовой межсетевой маршрутизации и межсетевого экрана. При этом DNS/VPN/PBR удобнее реализовывать на обычном Debian-сервере, чем на домашнем маршрутизаторе.

## Решение

Физический пограничный маршрутизатор на OpenWrt является базовым L3-шлюзом локальных сегментов и владельцем их адресов `.1`:

```text
MAIN / основная сеть → 10.0.0.1/16
IOT / VLAN 20       → 10.20.0.1/16
CAMERAS / VLAN 30   → 10.30.0.1/16
```

На физическом маршрутизаторе остаются:

- WAN и NAT к провайдеру;
- завершение локальных VLAN;
- DHCP для клиентских сегментов;
- базовая межсегментная маршрутизация и правила межсетевого экрана;
- аварийный административный VPN или другой доступ при необходимости.

`109-network-gateway` остаётся специализированным сетевым сервисным узлом. На нём находятся:

- SmartDNS и `home.arpa`;
- DoH/DoT и выбор внешних DNS-серверов;
- исходящие AmneziaWG/WireGuard и другие VPN;
- маршрутизация по правилам PBR через `nftables` + `fwmark` + `ip rule`;
- sing-box только для сценариев, где нужен прокси или сложное исходящее соединение;
- основной VPN для удалённого доступа;
- отражение mDNS между явно разрешёнными сегментами при необходимости;
- контроль работоспособности и автоматическое восстановление сетевых сервисов при сбое.

`109` не является обязательным шлюзом по умолчанию для MAIN/IOT/CAMERAS. При остановке `109` обычный интернет и базовая маршрутизация локальной сети должны продолжать работать через OpenWrt; недоступными могут стать только сервисы, которые сознательно зависят от `109` — специальный DNS, PBR и VPN.

## PBR между OpenWrt и 109

Точный механизм перенаправления выбранного трафика на `109` реализуется при развёртывании второго этапа сети. Допустимы маршрут по правилам на OpenWrt, явное использование `109` отдельными клиентами или сетями либо другой простой вариант без превращения сетевого моста Proxmox в маршрутизатор.

При выборе реализации обязательны:

- отсутствие петли маршрутизации;
- понятный аварийный обход `109`;
- один очевидный владелец маршрута по умолчанию каждого сегмента;
- сохранение доступа к Proxmox при недоступности VM `109`.

## IPv6

DHCPv6-PD, объявления маршрутизатора RA и базовый межсетевой экран IPv6 локальных VLAN по умолчанию принадлежат физическому пограничному маршрутизатору. `109` обрабатывает IPv6 только в пределах собственных функций DNS/VPN/PBR, если отдельный сценарий не потребует иного.

## Следствия

- адреса `.1` локальных VLAN не являются адресами интерфейсов VM `109`;
- VM `109` использует обычную общую адресацию по VMID: `192.168.1.9/16` в переходной сети и `10.0.1.9/16` в целевой;
- отказ Proxmox не должен отключать базовую L3-маршрутизацию квартиры;
- сложная логика DNS/VPN/PBR остаётся на Debian и может развиваться независимо от OpenWrt.
