# 109 — network-gateway

**Тип:** VM  
**ОС:** Debian 13  
**Назначение:** DNS, исходящие VPN, маршрутизация по правилам PBR, VPN для удалённого доступа и сетевые сервисы, которые удобнее держать на Linux-сервере.

Общая сеть и VLAN описаны в [`../../docs/40-network.md`](../../docs/40-network.md). Граница ответственности физического OpenWrt и этой VM зафиксирована в [`decisions/001-edge-router-boundary.md`](decisions/001-edge-router-boundary.md).

## Что делает 109

На уровне ОС VM:

- `nftables`;
- `ip rule` и отдельные таблицы маршрутизации;
- `fwmark` и PBR;
- AmneziaWG/WireGuard и другие исходящие VPN;
- основной VPN для удалённого доступа;
- контроль работоспособности и автоматическое восстановление сервиса при сбое;
- при необходимости отражение mDNS между явно разрешёнными сегментами.

В Docker допускаются:

- SmartDNS — основной DNS-сервис;
- AdGuard Home — только необязательный веб-интерфейс для статистики и фильтрации;
- sing-box — только для прокси и сложных исходящих соединений, где обычной L3-маршрутизации недостаточно.

Маршрутизация VPN/PBR принадлежит ОС VM, а не внутренней сети Docker.

## DNS/PBR

Принятая схема:

```text
SmartDNS
   ↓
адреса назначения / наборы nftables
   ↓
fwmark
   ↓
ip rule / таблицы маршрутизации
   ├── обычный WAN
   ├── AmneziaWG
   └── другие VPN и выходы
```

SmartDNS поддерживает обычные внешние DNS-серверы, DoH/DoT и группы доменов. `keen-pbr` внутри VM не используется.

Постоянный внутренний домен — `home.arpa`. `.local` используется только для mDNS. Полная модель DNS: [`../../docs/41-dns.md`](../../docs/41-dns.md).

## Адресация

VM подчиняется тому же правилу VMID → IP, что и остальные серверы:

```text
текущий: 192.168.1.9/16
шлюз:    192.168.1.1

целевой: 10.0.1.9/16
шлюз:    10.0.0.1

bridge: vmbr0
```

`bridge` оставлен без перевода в техническом блоке как имя параметра Proxmox.

До переезда Keenetic остаётся обычным пограничным маршрутизатором и шлюзом по умолчанию. После переезда физический OpenWrt владеет локальными L3-шлюзами VLAN, а `109` остаётся специализированным узлом DNS/VPN/PBR.

Остановка `109` не должна отключать обычный WAN и базовую маршрутизацию квартиры.

## VPN для удалённого доступа

Основная туннельная сеть:

```text
10.60.0.0/16
```

Удалённые доверенные клиенты получают домашний DNS и доступ только к разрешённым сегментам. Поддерживаются профили с маршрутизацией только домашней сети и всего трафика через VPN.

Ограниченный аварийный VPN на физическом пограничном маршрутизаторе допускается отдельно, чтобы доступ к инфраструктуре не зависел от VM `109`.

## IPv6

Базовые DHCPv6-PD, объявления маршрутизатора RA и межсетевой экран локальных VLAN принадлежат OpenWrt. VM `109` обрабатывает IPv6 только в пределах собственных функций DNS/VPN/PBR, если отдельный сценарий не потребует иного.

## Ресурсы

```text
vCPU: 2
RAM: 2 GiB
Disk: 16 GiB начально
NIC: VirtIO
QEMU Guest Agent: enabled
Ballooning: пока не использовать
```

Технические названия параметров в блоке оставлены без перевода там, где они соответствуют настройкам Proxmox.

## Размещение конфигурации

Все файлы гостевой ОС хранятся только под `rootfs/` по реальному пути назначения:

```text
rootfs/etc/nftables.conf
rootfs/etc/systemd/system/...
rootfs/etc/wireguard/...
rootfs/opt/network-gateway/smartdns/...
```

Секреты VPN, закрытые ключи, предварительно согласованные ключи и пароли в Git не добавляются.
