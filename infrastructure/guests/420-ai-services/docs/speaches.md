## 1. Назначение и версия

### 1.1. Роль Speaches

Speaches предоставляет один готовый OpenAI-совместимый API для:

- распознавания речи;
- синтеза речи;
- загрузки и выгрузки моделей по требованию.

Не создаётся собственный STT/TTS API поверх Speaches.

### 1.2. Базовый образ

Для первой CPU-реализации фиксируется:

```text
ghcr.io/speaches-ai/speaches:0.8.3-cpu
```

Порт службы:

```text
8000/tcp
```

При появлении отдельного GPU допускается переход на официальный GPU-образ Speaches, но это отдельное решение и не меняет API потребителей.

## 2. API и модели

### 2.1. Основные точки API

Используются штатные OpenAI-совместимые вызовы:

```text
POST /v1/audio/transcriptions
POST /v1/audio/speech
GET  /v1/models
GET  /health
```

Потребители не должны зависеть от внутренней реализации faster-whisper или Piper.

### 2.2. Начальная STT-модель

Для первой проверки русского языка используется:

```text
Systran/faster-whisper-small
```

Модель является многоязычной и подходит как начальный компромисс для CPU.

После развёртывания обязательно выполняется замер:

- задержки короткой команды;
- задержки фразы 10–20 секунд;
- качества русского распознавания;
- потребления памяти.

Если результат неудовлетворителен, меняется модель, а не архитектура сервиса.

### 2.3. Начальная русская TTS-модель

Для первой русской озвучки используется готовая Piper-модель:

```text
speaches-ai/piper-ru_RU-irina-medium
```

Дополнительная русская модель может быть добавлена после сравнения голосов, например:

```text
speaches-ai/piper-ru_RU-ruslan-medium
```

Kokoro поддерживается самим Speaches и может использоваться позже для подходящих языков или сценариев, но не является обязательной частью первой русской конфигурации.

### 2.4. Логические имена

Для потребителей желательно использовать устойчивые логические имена через штатный `model_aliases.json` Speaches:

```json
{
  "stt-default": "Systran/faster-whisper-small",
  "tts-default-ru": "speaches-ai/piper-ru_RU-irina-medium"
}
```

Это позволяет менять фактическую модель без изменения каждой интеграции.

## 3. Размещение и данные

### 3.1. Конфигурация

Файл:

```text
/etc/ai-services/speaches/model_aliases.json
```

монтируется в штатный путь Speaches:

```text
/home/ubuntu/speaches/model_aliases.json
```

Конфигурация создаётся повторяемо из Git.

### 3.2. Кэш моделей

Кэш Hugging Face:

```text
/var/cache/ai-services/speaches/huggingface/
→ /home/ubuntu/.cache/huggingface/hub
```

Кэш не резервируется по умолчанию.

После полного восстановления модели повторно скачиваются из исходных репозиториев.

## 4. Безопасность

### 4.1. Доступ

Speaches не публикуется в Интернет.

Если используемая версия не предоставляет нужную встроенную аутентификацию, доступ ограничивается сетью и межмашинными правилами проекта.

На первом этапе разрешёнными потребителями считаются:

- 410 ai-control;
- локальный Wyoming OpenAI на 420.

Другие потребители добавляются явно.

### 4.2. Секреты

Для локального Speaches не создаётся фиктивный секрет только ради сходства с облачным OpenAI API.

Если клиентская библиотека требует непустой `api_key`, используется техническое непустое значение на стороне клиента, если это допускается библиотекой.

Это значение не считается механизмом безопасности 420.

## 5. Развёртывание и обновление

### 5.1. Первый запуск

Порядок:

1. получить закреплённый CPU-образ;
2. подключить `model_aliases.json`;
3. подключить каталог кэша;
4. запустить контейнер;
5. дождаться `/health`;
6. загрузить или вызвать STT-модель;
7. загрузить или вызвать TTS-модель;
8. выполнить сквозную проверку.

Speaches умеет динамически загружать и выгружать модели. Поэтому постоянное удержание всех моделей в памяти не требуется.

### 5.2. Обновление

Тег образа меняется только через машинную конфигурацию проекта.

После обновления обязательно повторяются:

- `/health`;
- STT на русском примере;
- TTS на русском примере;
- проверка Home Assistant через Wyoming OpenAI;
- проверка 410.

## 6. Проверка

### 6.1. STT

Проверяется запрос к:

```text
/v1/audio/transcriptions
```

с моделью `stt-default`.

Результат должен содержать распознанный русский текст без ручного исправления для обычной короткой команды.

### 6.2. TTS

Проверяется запрос к:

```text
/v1/audio/speech
```

с моделью `tts-default-ru`.

Ответ должен быть корректным аудиофайлом и воспроизводиться обычным клиентом.

### 6.3. Сквозная проверка

Сгенерированное TTS-аудио можно передать обратно в STT.

Цель такой проверки — убедиться, что обе функции работают после чистого развёртывания без ручной настройки контейнера.
