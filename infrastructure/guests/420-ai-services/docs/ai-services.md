## 1. Назначение и состав

### 1.1. Роль 420

`420 ai-services` предоставляет общие готовые AI-функции, которые нужны нескольким системам.

Базовый состав:

```text
420 ai-services
├── Speaches
│   ├── STT
│   └── TTS
└── Wyoming OpenAI
    └── Home Assistant ↔ Speaches
```

420 не принимает пользовательские решения, не планирует действия и не является AI-агентом.

Интеллектуальный агент находится на 410.

### 1.2. Техническая основа

Целевой тип гостя:

```text
LXC
Debian
Docker
Docker Compose
```

Начальная оценка ресурсов:

```text
CPU: 2 ядра
RAM: 4 ГБ
swap: 1 ГБ
диск: 32 ГБ
```

Это стартовые значения. Перед фиксацией машинного `guest.yaml` они должны быть подтверждены замерами на реальном N150.

## 2. Сеть и потребители

### 2.1. Порты

Базовые службы:

| Служба | Порт | Назначение |
|---|---:|---|
| Speaches | `8000/tcp` | OpenAI-совместимый STT/TTS API |
| Wyoming OpenAI | `10300/tcp` | Wyoming для Home Assistant |

Порты не публикуются в Интернет.

Speaches должен быть доступен только разрешённым внутренним потребителям, прежде всего 410.

Wyoming OpenAI должен быть доступен Home Assistant.

### 2.2. Потребители

Целевая схема:

```text
Open WebUI ───────► Speaches :8000
Hermes ───────────► Speaches :8000

Home Assistant ───► Wyoming OpenAI :10300
                         │
                         └──► Speaches :8000
```

Home Assistant не должен запускать отдельную копию Whisper/Piper, если 420 доступен и удовлетворяет требованиям по задержке.

## 3. Каталоги и данные

### 3.1. Целевая структура

```text
/opt/ai-services/
└── compose/
    └── docker-compose.yml

/etc/ai-services/
├── speaches/
│   └── model_aliases.json
└── wyoming-openai.env

/var/cache/ai-services/
└── speaches/
    └── huggingface/
```

Compose и конфигурация являются воспроизводимыми и должны создаваться из Git через Ansible.

### 3.2. Кэш моделей

Модели Speaches хранятся в кэше:

```text
/var/cache/ai-services/speaches/huggingface/
```

В контейнер он подключается как кэш Hugging Face.

Кэш:

- может занимать значительный объём;
- может быть повторно скачан;
- не считается единственным источником данных;
- по умолчанию не входит в обязательную резервную копию.

На 420 не должно быть уникальной памяти пользователя или агента.

## 4. Развёртывание и обновление

### 4.1. Порядок развёртывания

Штатный порядок:

1. подготовить Debian LXC;
2. установить Docker;
3. создать каталоги конфигурации и кэша;
4. установить конфигурацию Speaches;
5. сформировать Compose;
6. получить закреплённые образы;
7. запустить Speaches;
8. проверить STT и TTS;
9. запустить Wyoming OpenAI;
10. проверить Wyoming из Home Assistant;
11. проверить обращения от 410.

Не допускается использование плавающего `:latest` в принятой машинной конфигурации.

### 4.2. Обновление

Каждая служба обновляется сменой закреплённого тега образа в машинной конфигурации.

Перед обновлением:

- проверить примечания upstream;
- проверить совместимость API;
- сохранить действующую конфигурацию;
- после обновления выполнить STT/TTS-проверку.

## 5. Проверка и восстановление

### 5.1. Минимальная проверка

После развёртывания должны выполняться:

```text
GET  Speaches /health
POST Speaches /v1/audio/transcriptions
POST Speaches /v1/audio/speech
TCP  Wyoming OpenAI :10300
```

Дополнительно проверяются:

- русская речь корректно распознаётся;
- русский TTS возвращает воспроизводимое аудио;
- Home Assistant видит Wyoming-службу;
- 410 может обращаться к Speaches;
- перезапуск контейнеров не требует ручной настройки.

### 5.2. Восстановление

При потере 420:

1. создать LXC заново;
2. применить машинную конфигурацию;
3. получить Docker-образы;
4. повторно скачать модели;
5. проверить Speaches;
6. проверить Wyoming OpenAI;
7. проверить потребителей.

Если все настройки находятся в Git, резервная копия кэша моделей для восстановления не требуется.

## 6. Правила расширения

### 6.1. Что можно добавлять

На 420 можно добавить готовый сервис, если одновременно выполняются условия:

- функция относится к AI/голосу;
- ею пользуются несколько систем;
- сервис имеет самостоятельный API или стандартный протокол;
- его полезно обслуживать независимо от Hermes;
- существует готовое поддерживаемое решение.

Возможные будущие кандидаты:

- openWakeWord;
- Speech-to-Phrase;
- общий embeddings-сервис;
- общий reranker.

Это не означает, что они должны быть установлены заранее.

### 6.2. Что не добавляется

На 420 не размещаются функции только потому, что они связаны с AI.

Не относятся к 420:

- Hermes;
- Open WebUI;
- память и задачи агента;
- инфраструктурный MCP к 910;
- Home Assistant;
- видеонаблюдение;
- мониторинг;
- сетевые службы.
