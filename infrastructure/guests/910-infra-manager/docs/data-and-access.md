# Данные и доступы 910 infra-manager

**Назначение:** объяснить, какие внешние каталоги подключены к 910, какие данные остаются только на PVE и где находятся временные рабочие представления.

Общие правила безопасности, резервирования и восстановления здесь не повторяются. Они находятся в разделах `600`, `700` и `800` основной документации.

## 1. Три области на PVE

Штатная схема задаётся в `provision.yaml:persistence.target_layout`.

Все внешние данные 910 находятся под единым корнем:

~~~text
/mnt/bindmounts/infra-manager/
├── pve-only/
├── access/
└── state/
~~~

### 1.1. pve-only

Эта область доступна только физическому PVE и внутрь 910 не подключается.

Здесь находятся данные аварийного и первоначального контура, например:

- ключ снятия блокировки OpenBao;
- служебные данные ограниченных OpenBao AppRole для операций PVE;
- аварийная копия read-only Git Deploy Key проекта.

Точные канонические пути определяет [`230-host-layout.md`](../../../../docs/200-pve/230-host-layout.md).

### 1.2. access

Эта область подключается в 910 только для чтения:

~~~text
/mnt/bindmounts/infra-manager/access
        ↓
/mnt/pve-access
~~~

Сейчас через неё доступны:

- отдельный SSH-ключ пользователя `root` для предусмотренных операций 910 на PVE;
- `known_hosts` для проверки PVE;
- корневой сертификат PVE.

Рабочий секрет PVE API и штатный Git Deploy Key в этой области не хранятся.

### 1.3. state

Эта область подключается в 910 на чтение и запись:

~~~text
/mnt/bindmounts/infra-manager/state
        ↓
/mnt/persistent-state
~~~

Основные подкаталоги:

| Подкаталог | Назначение |
|---|---|
| `ansible/` | постоянная переходная идентичность Ansible |
| `semaphore/` | база и служебные данные Semaphore |
| `opentofu/` | состояние OpenTofu и рабочие данные |
| `openbao/` | Raft-состояние OpenBao |

Эти каталоги не должны зависеть от корневой файловой системы LXC 910.

## 2. Пути внутри 910

Постоянные каталоги подключаются к привычным путям внутри 910.

Основные соответствия:

~~~text
/mnt/persistent-state/ansible
    → /etc/infra-manager/ansible

/mnt/persistent-state/semaphore
    → /var/lib/infra-manager/semaphore

/mnt/persistent-state/opentofu
    → /var/lib/infra-manager/opentofu

/mnt/persistent-state/openbao
    → /var/lib/persistent/openbao
~~~

Перед заменой старого пути Ansible проверяет, нет ли там неизвестных данных. Если такие данные обнаружены, автоматическая замена не выполняется.

### 2.1. Воспроизводимые локальные данные

В корневой файловой системе 910 остаются данные, которые можно получить заново из проекта:

- рабочая копия Git в `/var/lib/infra-manager/bootstrap-repo/`;
- Compose-файлы в `/opt/infra-manager/compose/`;
- установленный код `infra_manager`;
- Docker-образы;
- кэши и временные файлы.

Их исходники находятся в Git; файлы конкретного 910 устанавливаются из [`../rootfs/`](../rootfs/).

## 3. Временные рабочие секреты

После инициализации постоянным источником рабочих секретов является OpenBao.

Для работы 910 значения материализуются во временную область:

~~~text
/run/infra-manager/secrets/
~~~

Сейчас там используются, в частности:

~~~text
pve-api.env
github_proxmox_repo_ed25519
semaphore-server.env
initial-admin-password
semaphore-api-token
~~~

`infra-runtime` получает эту область только для чтения.

До первой инициализации используется отдельная временная область:

~~~text
/run/infra-manager/bootstrap-secrets/
~~~

После успешного переноса данных в OpenBao эта область больше не является штатным источником.

Нормативные правила хранения и доступа к этим секретам определены в [`740-openbao.md`](../../../../docs/700-security/740-openbao.md).

## 4. Доступ 910 к внешним системам

Этот раздел фиксирует конкретные точки подключения 910. Само право на доступ определяется общими документами безопасности.

### 4.1. PVE API

Рабочие программы 910 используют API-идентичность:

~~~text
root@pam!infra-manager
~~~

Секрет во время работы доступен через временно материализованные данные OpenBao. Общий контракт прав находится в [`710-pve-access.md`](../../../../docs/700-security/710-pve-access.md).

### 4.2. SSH пользователя root к PVE

Отдельная SSH-идентичность подключена только для чтения через:

~~~text
/mnt/pve-access/pve-host/
~~~

Она используется предусмотренными операциями, которым нужны полномочия самого PVE-хоста. Назначение этого канала определено в [`710-pve-access.md`](../../../../docs/700-security/710-pve-access.md).

### 4.3. GitHub

Штатный read-only Deploy Key во время работы материализуется из OpenBao.

Отдельная аварийная копия находится в PVE-only области. Её точный путь задаёт [`230-host-layout.md`](../../../../docs/200-pve/230-host-layout.md), а назначение — [`730-git-access.md`](../../../../docs/700-security/730-git-access.md).

### 4.4. Ansible

Переходная постоянная идентичность Ansible хранится в `state/ansible` и подключается к рабочей среде только для чтения.

Целевая модель административного SSH и текущее переходное состояние описаны в [`720-ssh-access.md`](../../../../docs/700-security/720-ssh-access.md) и [`780-implementation-status.md`](../../../../docs/700-security/780-implementation-status.md).

## 5. Владельцы и права локальных каталогов

Службы внутри `infra-runtime` используют числового пользователя `1001` и группу `0`.

Для Semaphore постоянный каталог приводится к `1001:0`; каталоги имеют режим `0770`, обычные файлы — `0660`.

Каталог OpenTofu принадлежит `1001:0` и имеет ограниченные права, заданные Ansible.

Каталог переходной идентичности Ansible также принадлежит служебному пользователю и подключается в `infra-runtime` только для чтения.

Постоянный каталог OpenBao на уровне 910 доступен только `root`.

Точные значения владельцев и режимов задаются машинной конфигурацией и Ansible, а не этим документом.

## 6. Что относится к резервированию

Для 910 важны несколько связанных частей, находящихся в разных областях: состояние OpenBao, Semaphore, OpenTofu, необходимые идентичности и PVE-only данные.

Этот файл только показывает их физическое размещение. Какие из них резервируются, с какой периодичностью и как согласовываются между собой, определяет [`610-backup.md`](../../../../docs/600-storage/610-backup.md).

Порядок аварийного восстановления находится в [`830-recovery.md`](../../../../docs/800-operations/830-recovery.md).

## 7. Проверка

При полной проверке 910 нужно подтвердить как минимум:

- подключения `access/` и `state/` присутствуют;
- ожидаемые постоянные каталоги доступны по своим путям;
- временные рабочие секреты материализованы после разблокировки OpenBao;
- данные PVE CA и SSH-доступа к PVE читаются;
- OpenBao использует постоянный Raft;
- Semaphore видит постоянную базу;
- OpenTofu использует постоянный каталог состояния.

Общая команда:

~~~bash
infra-manager-status --full
~~~
