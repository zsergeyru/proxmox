# Сведения о гостях для Homarr

**Статус:** код подготовлен в ветке `feature/safe-guest-sync`; развёртывание и проверки доступа на действующем PVE не выполнены.

## 1. Назначение

Гость 910 предоставляет единую защищённую точку для отображения гостей в Homarr 140. Список формируется из `guest.yaml`, `provision.yaml` и одного запроса к PVE. В Homarr номера гостей не перечисляются.

Существующие локальные Homepage, посредник `portal_gateway.py` и Semaphore сохраняются без изменений, пока новый способ не пройдёт испытания.

## 2. Интерфейс

Служба `infra-manager-homarr-api.service` слушает `https://192.168.9.10:3003`. HTTPS использует существующий серверный сертификат управляющего гостя, выданный TLS-центром OpenBao; проверять подлинность сервера обязательно.

| Запрос | Ответ |
|---|---|
| `GET /v1/guests` | Список проекта и фактических объектов PVE, состояние, ссылки и требуемые версии |
| `POST /v1/guests/{vmid}/actions` | Назначение одной штатной операции `deploy/status/sync/repair` |
| `GET /v1/jobs/{id}` | Состояние и ограниченный журнал назначенного задания |

Список гостей содержит `pve_available`: при недоступности PVE состояние объектов становится `unknown`, а не прежним успешным. Номер, не описанный в Git, допускает только просмотр. Отсутствующий объект, объявленный в Git, остаётся в списке.

Раздел `versions` **пока показывает только требуемый образ из Git** (`configured_image`). Поля `installed_version` и `available_version` возвращают `null`, пока не реализованы независимые проверки фактических версий и выпусков. Нельзя подписывать эти значения как установленную версию.

## 3. Доступ

API использует два раздельных случайных ключа:

- `/mnt/persistent-state/homarr-api/read-token` — чтение списка и заданий;
- `/mnt/persistent-state/homarr-api/action-token` — запросы на изменение.

Ключи создаются один раз после установки службы 910, сохраняются на `mp1`, права каталогов `0700`, файлов `0600`. Повторное развёртывание их не заменяет. Значения **не записывать в Git и журналы**. Просматривать только в доверенном терминале PVE, например через `pct exec 910`; затем вносить в настройки источников Homarr. Homarr хранит их зашифрованно на стороне сервера.

API также сверяет адрес клиента: доступ разрешён только IP гостя 140 из проекта и локальному адресу 910. Два ключа не дают прав PVE и OpenBao. Получение доступа к 140 само по себе не должно выдавать доступ к управляющим ключам.

**По умолчанию действия отключены:** `INFRA_HOMARR_ACTIONS_ENABLED=0` в системной службе. Это намеренный безопасный режим подготовки. Включать только после проверки авторизации Homarr, закрытой административной страницы, запрета действий из Интернета, защиты соединения TLS и отдельного испытания отказов.

Признак `actions_enabled` в ответе `GET /v1/guests` позволяет виджету скрывать кнопки, пока проверка не закончена. Недостаточно просто скрыть страницу: гостевой API сам проверяет ключ, источник, действие, VMID и подтверждение вида `VMID имя`. Повторная операция над тем же гостем не должна стартовать, пока предыдущая не завершилась; исполнитель использует собственные блокировки.

## 4. Задания

Изменяющие команды назначаются системным управляющим заданием на 910, а не выполняются Homarr или 140. Закрытие браузера не является командой остановки задания. Состояние проверяется через `systemctl`, журнал сохраняется в `/mnt/persistent-state/homarr-api/jobs/`; ответы ограничены последними 8 КиБ. При исчезнувшем системном задании состояние считается неизвестным, а не успешным.

Временная история заданий должна дополнительно получить процедуру очистки и восстановления после аварии; до проверки этого механизма включение изменяющих действий запрещено.

Служба `infra-manager-homarr-api` и её данные независимы от Homepage. Обслуживание или удаление старого портала не должно влиять на API.

## 5. Первое подключение

1. Развернуть 910 из новой ветки и убедиться, что `infra-manager-homarr-api.service` запущен.
2. Развернуть или один раз обновить 140, чтобы Homarr доверял публичному TLS CA 910 через `NODE_EXTRA_CA_CERTS`. Сертификат передаётся из управляющей среды Ansible; закрытый ключ при этом не передаётся.
3. Импортировать `infrastructure/guests/140-web-gateway/widgets/proxmox-guests.json` через Homarr → Management → Custom Widgets.
4. Настроить источники `default` (ключ чтения) и `actions` (отдельный ключ операций) в защищённых настройках Homarr. Для первоначальной проверки ключ операций можно не указывать.
5. Поместить виджет на закрытую страницу «Администрирование» и проверить группы `admins/family/guests`.
6. Проверить динамический список, отсутствующих и неизвестных гостей, отсутствие ложных версий и сетевые ограничения.
7. Только после отдельной проверки безопасности и долгих заданий можно рассматривать включение кнопок.

При добавлении следующего гостя достаточно добавить его машинные описания в Git и обновить рабочую копию проекта 910 обычным механизмом. **Повторно развертывать 140 не требуется.** Виджет перечитывает источник без статических номеров.

## 6. Восстановление

Резервировать каталог `/mnt/persistent-state/homarr-api` как часть постоянного состояния 910. После восстановления сохранять прежние ключи; их неожиданная замена потребует повторной настройки источников Homarr. Для аварийного восстановления использовать доверенный терминал PVE, а не веб-панель.

Справка по формату виджетов:

- https://homarr.dev/docs/management/custom-widgets/requests-and-security/
