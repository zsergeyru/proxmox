# Proxmox-хост: `pve`

Этот каталог относится только к конфигурации самого гипервизора.

Прикладные сервисы непосредственно на Proxmox-хост не устанавливать. Home Assistant, DNS/VPN, AI, мониторинг, Frigate и обычные Docker-приложения должны жить в VM/LXC.

**СТРОГОЕ ПРАВИЛО: НА PVE НИЧЕГО НЕ УСТАНАВЛИВАТЬ БЕЗ КРАЙНЕЙ НЕОБХОДИМОСТИ.** Ни APT-пакеты (`acl` включительно), ни Python-пакеты, ни Docker, ни новые службы/таймеры, ни дополнительные хостовые скрипты и агенты не ставить «на всякий случай» или автоматически при `deploy`. Весь управляющий код, расписания и интерфейс — в 910. Прежде всего использовать штатный Proxmox API, затем уже имеющиеся штатные команды PVE по защищённому SSH. Если новая установка действительно необходима и заменить её штатным механизмом нельзя — только после отдельного согласия владельца и фиксации обоснования. Уже существующие узкие PVE-only механизмы для недоступных 910 закрытых секретов и аварийного восстановления не расширяются автоматически.

После создания 910 его обычный `infra-manager deploy 910` должен безопасно сверять все общие тома `infrastructure/hosts/pve/storage.yaml` (в том числе `infra_state`, `gogs_data`, `photo_archive`), создавать отсутствующие LVM-тома при достаточной ёмкости, а существующие лишь проверять и подключать. Первичная разметка физического резервного SSD — только по отдельно подтверждённому плану, повторные запуски не форматируют носители. **Эта новая общая сверка пока не реализована, см. локальную спецификацию 910.**

## Фактическое состояние

Снимок состояния снят с работающего сервера 2026-09-12.

### Система

```text
hostname: pve
Proxmox VE: 9.2.18
proxmox-ve package: 9.2.0
Debian: 13 (trixie)
kernel: 7.0.14-16-pve
architecture: x86-64
```

Названия системных полей оставлены без перевода там, где они соответствуют фактическому выводу ОС.

### Аппаратная платформа

```text
model: Guangdong BuerTech BREN9E
CPU: Intel N150
cores/threads: 4 / 4
RAM: 15 GiB usable
firmware: AMI 5.27, 2025-04-27
```

На момент снимка температура CPU была около `58 °C`, NVMe — около `33 °C`.

### Текущие реальные гостевые системы

На хосте фактически существуют две VM:

```text
100  HAOS      running
320  ai-agent  running
```

Состояние `running` оставлено как фактическое значение Proxmox.

LXC-контейнеров на момент снимка нет.

VM `100` описывается в [`../../guests/100-haos/`](../../guests/100-haos/) и является текущей рабочей системой Home Assistant. Исторический VMID сохраняется; отдельная миграция на `201` потребуется только при появлении практической причины.

VM `320` соответствует временному каталогу [`../../guests/320-ai-control/`](../../guests/320-ai-control/). Имя объекта в Proxmox сейчас `ai-agent`, хотя архитектурное имя каталога — `ai-control`.

## Принцип

Здесь фиксируется наблюдаемое состояние самого PVE-хоста. Требуемые параметры VM/LXC и индивидуальные требования к их ОС принадлежат каталогам `infrastructure/guests/`, а применяет их общий гостевой контур через OpenTofu и Ansible.
