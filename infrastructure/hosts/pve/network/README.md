# Сеть PVE-хоста

## Фактическое состояние на 2026-09-12

~~~text
vmbr0
address: 192.168.1.11/16
gateway: 192.168.1.1
bridge-port: nic0
STP: off
forward delay: 0
~~~

Названия полей оставлены без перевода, поскольку соответствуют фактической сетевой конфигурации.

Маршруты:

~~~text
default via 192.168.1.1 dev vmbr0
192.168.0.0/16 dev vmbr0 src 192.168.1.11
~~~

Физическое подключение:

~~~text
interface: nic0
controller: Realtek RTL8111/8168 family
speed class: 1 GbE
driver: r8169
~~~

На сервере используется одна физическая Ethernet-карта. Intel Wi-Fi AX101 (wlo1) выключен и в сетевом мосте не используется.

В /etc/network/interfaces пока присутствует остаточная строка iface nic1 inet manual, но интерфейс nic1 фактически отсутствует. После контрольной проверки её нужно удалить.

## DNS хоста

~~~text
search home.arpa
nameserver 192.168.1.1
~~~

Сейчас PVE использует Keenetic как DNS. Общая архитектура DNS описана в [../../../../docs/400-network/420-dns.md](../../../../docs/400-network/420-dns.md).

## Текущее подключение

Сейчас PVE подключён одним nic0 к обычной LAN Keenetic без VLAN. Компьютеры, PVE и VM/LXC находятся в одном L2-сегменте.

До перехода на целевую схему Keenetic остаётся шлюзом по умолчанию и DNS для PVE и клиентов.

## Целевая схема

Тот же единственный nic0 используется как trunk через VLAN-aware vmbr0.

VM 109-network-gateway получает через него два логических интерфейса:

- WAN / TRANSIT — отдельная сеть 10.0.0.0/30 между Keenetic и 109;
- LAN — домашняя сеть 192.168.0.0/16.

~~~text
Keenetic
   │
   │ один физический кабель к PVE
   │ VLAN TRANSIT + VLAN LAN
   ▼
vmbr0
   │
   ├── WAN 109 → 10.0.0.2/30
   └── LAN 109 → домашняя сеть
~~~

PVE остаётся L2-узлом для этих VLAN и не маршрутизирует пользовательский трафик.

В штатном режиме VM 109 является основным шлюзом и DNS внутренней сети. Keenetic остаётся пограничным маршрутизатором к провайдеру и выполняет внешний NAT.

Подробности находятся в [../../../../docs/400-network/410-network-layout.md](../../../../docs/400-network/410-network-layout.md).

## Административный доступ к PVE

Административный адрес PVE должен оставаться в домашней сети 192.168.0.0/16 и быть доступен независимо от прикладных сервисов внутри гостевых систем.

Точный целевой шлюз PVE будет зафиксирован одновременно с LAN-адресом 109 и настройкой VLAN. До этого фактические параметры 192.168.1.11/16 и шлюз 192.168.1.1 считаются текущим состоянием, а не целевой схемой.

При переходе нельзя удалять действующий путь управления PVE до проверки доступа через новую схему.

## Принцип отказоустойчивости

PVE не должен сам становиться маршрутизатором квартиры.

В штатном режиме обычный Интернет зависит от VM 109, потому что она является основным шлюзом клиентов.

Для аварии сохраняется прямое физическое подключение Keenetic к внутренней сети. При недоступности PVE или 109 оператор вручную возвращает Keenetic в роль шлюза и DNS через его DHCP-настройки.

Автоматическое переключение на первом этапе не требуется.
