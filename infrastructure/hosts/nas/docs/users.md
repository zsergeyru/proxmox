# Именные учётные записи Samba на NAS

**Целевой режим:** авторизованный SMB-доступ с одинаковыми правами чтения и записи для пользователей из [infrastructure/users.yaml](../../../users.yaml).

## Пользователи

Для SMB используются имена `sergey`, `sveta`, `danya`. У каждого — отдельная запись Samba и общая группа файлового доступа `nas-smb`. Для всех четырёх сетевых ресурсов действуют одинаковые права чтения/записи. Гостевой вход **выключен**: в OMV `guest: no`, `readonly: false`.

Linux-пользователи создаются только при отсутствии; им запрещён интерактивный вход. Существующие пользователи Linux не пересоздаются, их системные пароли и оболочки не сбрасываются; к ним лишь добавляется группа `nas-smb`. Пароль Samba настраивается отдельно от системного пароля.

## Декларация и хранение пароля

[../access.yaml](../access.yaml) описывает режим `named_users`, источник секрета и права на ресурсы. Сами имена пользователей берутся только из общего `users.yaml`; пароль, его NT-хеш и другие секреты **не хранятся в Git**.

Операторский пароль находится на 910 в защищённом постоянном состоянии:

```text
/mnt/persistent-state/physical-hosts/nas-smb-password
```

У файла должны быть права `0600`, содержимое — одна строка с выбранным паролем. Управляющий модуль проверяет этот файл **до** применения базовой конфигурации NAS; если файла нет, запуск `deploy nas` останавливается, не изменив диски. Во время деплоя Ansible передаёт пароль каждому `smbpasswd -s -a` через stdin с `no_log: true`, без включения пароля в CLI-аргументы и вывод.

На PVE файл можно создать без включения пароля в историю команд, введя выбранный пароль при запросе:

```bash
install -d -m 0700 /mnt/bindmounts/infra-state/physical-hosts
umask 077
read -r -s -p 'Пароль Samba: ' NAS_SMB_PASSWORD; echo
printf '%s\\n' "$NAS_SMB_PASSWORD" > /mnt/bindmounts/infra-state/physical-hosts/nas-smb-password
unset NAS_SMB_PASSWORD
chmod 0600 /mnt/bindmounts/infra-state/physical-hosts/nas-smb-password
```

Пароль остаётся общим для трёх пользователей. Повторный `infra-manager deploy nas` приводит их Samba-пароли к значению из защищённого файла, не меняя Linux-пароли.

## Файловые права

Группа `nas-smb` получает `rwx` на **корни** опубликованных `shared`, `movies`, `music`, `data` и ACL наследования для новых файлов. Существующие вложенные каталоги/файлы не изменяются рекурсивно. Ранее созданные гостевые ACL `nobody` могут оставаться на корнях, но гостевой SMB-вход отключён. При наличии старых ACL необходимо отдельно проверить запись и удаление тестовых файлов.

Каталоги `nas-backup`, резервные копии UrBackup и системный SSD не опубликованы в SMB.

## Windows

Подключение выполняется через Проводник, например `\\\\192.168.1.12\\shared`. При первом входе нужно указать `sergey` (или другое объявленное имя) и общий пароль, затем включить **«Запомнить учётные данные»**. Windows обычно использует одну пару SMB-учётных данных на один сервер; старое гостевое подключение может помешать и требует отключения прежней сессии.

Это **очень слабая парольная схема**, выбранная для домашней сети. Не публиковать TCP 445 в Интернет; ограничивать доступ маршрутизатором/межсетевым экраном и не хранить защищённые архивы в доступных SMB-папках.

## Проверка после развертывания

Реальный NAS пока не проверялся с этой новой конфигурацией. Нужно подтвердить создание/изменение/удаление тестового файла из Windows каждым пользователем, отказ в гостевом входе и недоступность резервного пула.
