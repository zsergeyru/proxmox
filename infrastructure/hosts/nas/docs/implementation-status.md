## 1. Реализовано

- Описания `infrastructure/hosts/<name>/host.yaml` и проверка отдельной схемы.
- Распознавание физических узлов независимо от VMID и OpenTofu.
- Маршрутизация `infra-manager hosts`, `inspect nas`, `status nas`,
  `deploy nas`, `repair nas` через управляющий LXC с PVE.
- Временный снимок Git для операций физического сервера; Semaphore не требуется.
- Проверка SSH-ключа по заранее подтверждённому отпечатку. Временный
  клиентский сертификат OpenBao; непризнанный ключ сервера вызывает отказ.
- Чтение дисков через `lsblk`; поиск системного SSD по корневому тому.
  Никаких изменений дисков в этой операции.
- Автономные проверки каталога, неправильных идентификаторов и анализа дисков.

При пустых `connection.address` или `ssh_host_fingerprint` запуск
подключения останавливается. Это штатная защита, а не успешное развёртывание.

## 2. Не реализовано

- Автоматическая установка Debian 13 на физическом NAS с PVE: для неё
  требуется решение о начальной загрузке, постоянный ID системного
  носителя и параметры сетевого подключения.
- Первоначальное установление SSH-доверия на только что установленной ОС.
  Сейчас штатный вход предполагает, что NAS уже доверяет клиентскому CA.
- Автоматическая установка и проверка OpenMediaVault 8, ZFS и Docker.
- Подготовка новых пустых дисков по отдельному подтверждённому плану.
- Создание папок и SMB через интерфейсы OpenMediaVault.
- qBittorrent, снимки и передача ZFS, проверка резервных копий.
- Полная проверка служб и безопасная операция `repair nas`.

Операции `deploy nas` и `repair nas` сейчас **явно отказывают**,
не форматируют, не монтируют и не создают каталоги. `status nas`
пока проверяет SSH и набор серийных номеров, но не готовность служб.

## 3. Проверка и подготовка к следующему этапу

Проверки без физической машины:

```bash
python scripts/validate_repo.py
python scripts/tests/test-physical-hosts.py
python scripts/tests/test-physical-storage.py
ruff check scripts
python -m compileall -q scripts
```

Для испытания на реальном NAS сначала нужно записать проверенные
`connection.address`, `connection.ssh_host_fingerprint` и серийные
номера накопителей. SSH-ключ сравнивается с отпечатком, полученным
не через незаверенный сетевой запрос. На NAS должно быть установлено
доверие к пользовательскому OpenBao CA. До этого `inspect nas`
не сможет подключиться.

Эти проверки не означают, что установка Debian или настройка OMV уже
выполнялась на реальном сервере.
