# План VMID / CTID

Функциональная нумерация применяется только к новым VM/LXC. VMID не определяет startup order и не является причиной перенумеровывать уже работающие системы.

| Диапазон | Назначение |
|---|---|
| `100–199` | сеть и базовая инфраструктура |
| `200–299` | Home Assistant и автоматика |
| `300–399` | прикладные, DevOps- и AI-сервисы |
| `400–499` | мониторинг и обслуживание |
| `500–599` | видео и камеры |
| `600–699` | временные и экспериментальные VM/LXC |
| `900–999` | legacy/служебные объекты |

## Management IP обычных серверов

Целевая MAIN-сеть новой квартиры:

```text
10.0.0.0/16
```

Для обычных инфраструктурных VM/LXC основной management IP кодирует VMID:

```text
VMID XYZ → 10.0.X.YZ/16
```

Примеры:

```text
201 → 10.0.2.1/16
202 → 10.0.2.2/16
203 → 10.0.2.3/16
211 → 10.0.2.11/16
301 → 10.0.3.1/16
311 → 10.0.3.11/16
321 → 10.0.3.21/16
331 → 10.0.3.31/16
401 → 10.0.4.1/16
501 → 10.0.5.1/16
```

Proxmox host использует отдельный адрес:

```text
PVE → 10.0.0.10/16
```

`101-network-gateway` — специальный сетевой гость. Его адреса выбираются по сетевой роли и не обязаны следовать формуле VMID → IP.

## Шлюзы сегментов

В целевой новой квартире физический edge-router/OpenWrt владеет L3-шлюзами VLAN:

```text
MAIN / native     → 10.0.0.1/16
IOT / VLAN 20     → 10.20.0.1/16
CAMERAS / VLAN 30 → 10.30.0.1/16
```

`101-network-gateway` предоставляет DNS, VPN, PBR, remote-access VPN и связанные сервисы, но не является обязательным L3-шлюзом для локальных VLAN. Это сохраняет базовую маршрутизацию квартиры при остановке Proxmox/VM 101.

REMOTE-VPN использует отдельную tunnel-сеть:

```text
10.60.0.0/16
```

Подробное разделение ролей: [`../guests/101-network-gateway/decisions/001-edge-router-boundary.md`](../guests/101-network-gateway/decisions/001-edge-router-boundary.md).

## Переходный период

Текущая сеть продолжает использовать `192.168.0.0/16`. Будущая `10.0.0.0/16` может существовать параллельно на том же L2 для поэтапной миграции.

Историческое правило временных серверных адресов:

```text
VMID XYZ → 192.168.X.YZ/16
```

Постоянное правило:

```text
VMID XYZ → 10.0.X.YZ/16
```

Default gateway на сервере должен быть один. Порядок миграции описан в [`network.md`](network.md).

## Текущий план

- `100` — `haos` (VM, **active production**, исторический VMID сохраняется)
- `101` — `network-gateway` (VM)
- `201` — `ha-main` (LXC, только возможная будущая миграция с VM 100)
- `202` — `ha-test` (LXC, при необходимости)
- `203` — `ha-flat2` (LXC, при необходимости)
- `211` — `automation-services` (LXC)
- `301` — `ai-control` (VM, целевой control plane)
- `311` — `dev-services` (LXC)
- `320` — `ai-control` (VM, текущий bootstrap до перехода на 301)
- `321` — `app-services` (LXC)
- `331` — `ai-services` (LXC)
- `401` — `monitoring` (LXC, разворачивается при практической необходимости)
- `411` — резерв под `backup-services`, если появится отдельная роль
- `501` — `frigate` (VM/LXC после теста)

Запланированный VMID не означает, что гость нужно создавать заранее. Создаются только реально необходимые сервисы.
