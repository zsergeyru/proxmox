# План VMID / CTID

Функциональная нумерация применяется только к новым VM/LXC. VMID не определяет startup order и не является причиной перенумеровывать уже работающие системы.

| Диапазон | Назначение |
|---|---|
| `100–199` | сеть и базовая инфраструктура |
| `200–299` | Home Assistant и автоматика |
| `300–399` | прикладные, DevOps- и AI-сервисы |
| `400–499` | мониторинг и обслуживание |
| `500–599` | видео и камеры |
| `600–699` | временные и экспериментальные VM/LXC |
| `900–999` | legacy/служебные объекты |

## Management IP серверов

Для инфраструктурных VM/LXC адрес кодирует VMID одинаково в текущей и целевой сети.

Переходная адресация:

```text
VMID XYZ → 192.168.X.YZ/16
```

Целевая адресация:

```text
VMID XYZ → 10.0.X.YZ/16
```

Примеры:

```text
109 → 192.168.1.9/16  → 10.0.1.9/16
201 → 192.168.2.1/16  → 10.0.2.1/16
202 → 192.168.2.2/16  → 10.0.2.2/16
203 → 192.168.2.3/16  → 10.0.2.3/16
211 → 192.168.2.11/16 → 10.0.2.11/16
301 → 192.168.3.1/16  → 10.0.3.1/16
311 → 192.168.3.11/16 → 10.0.3.11/16
321 → 192.168.3.21/16 → 10.0.3.21/16
331 → 192.168.3.31/16 → 10.0.3.31/16
401 → 192.168.4.1/16  → 10.0.4.1/16
501 → 192.168.5.1/16  → 10.0.5.1/16
```

Proxmox host использует отдельный инфраструктурный адрес и не обязан следовать VMID-формуле:

```text
current observed PVE → 192.168.1.11/16
target PVE           → 10.0.0.10/16
```

## Шлюзы

До переезда основной gateway серверов:

```text
192.168.1.1
```

В целевой новой квартире физический edge-router/OpenWrt владеет L3-шлюзами VLAN:

```text
MAIN / native     → 10.0.0.1/16
IOT / VLAN 20     → 10.20.0.1/16
CAMERAS / VLAN 30 → 10.30.0.1/16
```

`109-network-gateway` предоставляет DNS, VPN, PBR, remote-access VPN и связанные сервисы, но не является обязательным L3-шлюзом для локальных VLAN. Он использует обычную VMID-адресацию, как и остальные серверы.

REMOTE-VPN использует отдельную tunnel-сеть:

```text
10.60.0.0/16
```

Подробное разделение ролей: [`../guests/109-network-gateway/decisions/001-edge-router-boundary.md`](../guests/109-network-gateway/decisions/001-edge-router-boundary.md).

## Переходный период

Текущая сеть `192.168.0.0/16` и будущая `10.0.0.0/16` могут существовать параллельно на том же L2 для поэтапной миграции.

В `guest.yaml` для planned-гостей оба состояния записываются явно:

```yaml
network:
  current:
    ipv4:
      address: 192.168.X.YZ/16
      gateway: 192.168.1.1
  target:
    ipv4:
      address: 10.0.X.YZ/16
      gateway: 10.0.0.1
```

Это описание двух этапов, а не требование одновременно иметь два default gateway. В реально работающей ОС default gateway должен быть один.

## Текущий план

- `100` — `haos` (VM, **active production**, исторический VMID сохраняется)
- `109` — `network-gateway` (VM)
- `201` — `ha-main` (LXC, только возможная будущая миграция с VM 100)
- `202` — `ha-test` (LXC, при необходимости)
- `203` — `ha-flat2` (LXC, при необходимости)
- `211` — `automation-services` (LXC)
- `301` — `ai-control` (VM, целевой control plane)
- `311` — `dev-services` (LXC)
- `320` — `ai-control` (VM, текущий bootstrap до перехода на 301)
- `321` — `app-services` (LXC)
- `331` — `ai-services` (LXC)
- `401` — `monitoring` (LXC, разворачивается при практической необходимости)
- `411` — резерв под `backup-services`, если появится отдельная роль
- `501` — `frigate` (VM/LXC после теста)

Запланированный VMID не означает, что гость нужно создавать заранее. Создаются только реально необходимые сервисы.
