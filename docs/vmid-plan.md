# План VMID / CTID

Функциональная нумерация используется для новых VM/LXC. Номер не определяет порядок запуска.

| Диапазон | Назначение |
|---|---|
| `100–199` | сеть и базовая инфраструктура |
| `200–299` | Home Assistant и автоматика |
| `300–399` | прикладные, DevOps- и AI-сервисы |
| `400–499` | мониторинг и обслуживание |
| `500–599` | видео и камеры |
| `600–699` | временные и экспериментальные VM/LXC |
| `900–999` | legacy-системы |

## Правило VMID и основного IP

Для новых VM/LXC целевой VMID/CTID не должен заканчиваться на `0`.

Основной статический management IP кодирует VMID напрямую в сети `192.168.0.0/16`:

```text
VMID XYZ
→ 192.168.X.YZ/16
```

Где:

- `X` — первая цифра трёхзначного VMID;
- `YZ` — последние две цифры VMID как число без ведущего нуля.

Примеры:

```text
101 → 192.168.1.1/16
201 → 192.168.2.1/16
202 → 192.168.2.2/16
211 → 192.168.2.11/16
301 → 192.168.3.1/16
311 → 192.168.3.11/16
321 → 192.168.3.21/16
331 → 192.168.3.31/16
401 → 192.168.4.1/16
501 → 192.168.5.1/16
```

Так VMID визуально читается в IP, а отказ от VMID, заканчивающихся на `0`, исключает основные адреса вида `192.168.X.0`.

### DHCP

Основной DHCP-пул для обычных клиентских устройств размещается в диапазоне:

```text
192.168.1.100–192.168.1.254
```

При маске `/16` эти адреса находятся в той же локальной сети `192.168.0.0/16`, что и статические адреса инфраструктуры.

Диапазон `192.168.1.1–192.168.1.99` не используется для динамической выдачи и остаётся под сетевую и базовую инфраструктуру. Целевой основной шлюз — `192.168.1.1`, что соответствует VMID `101` для `network-gateway`.

Правило соответствия VMID относится к **основному management IP** гостя. Если VM/LXC требуется несколько адресов или сетевых интерфейсов, дополнительные IP выбираются по назначению и отдельно описываются в `guest.yaml`; они не обязаны кодировать VMID.

Существующие гости и сетевые устройства не перенумеровываются автоматически только ради этого правила. Новая схема применяется при плановом переразвертывании или создании нового гостя.

## Текущий целевой план

- `101` — `network-gateway` (VM)
- `201` — `ha-main` (LXC)
- `202` — `ha-test` (LXC)
- `203` — `ha-flat2` (LXC, при необходимости)
- `211` — `automation-services` (LXC)
- `301` — `ai-control` (VM)
- `311` — `dev-services` (LXC)
- `321` — `app-services` (LXC)
- `331` — `ai-services` (LXC)
- `401` — `monitoring` (LXC)
- `411` — резерв под `backup-services`
- `501` — `frigate` (VM/LXC после теста)

Текущая `320-ai-control` рассматривается как временный bootstrap-узел до развёртывания новой `301-ai-control`. После проверки новой управляющей VM старую `320` можно вывести из эксплуатации.

Существующие legacy VM не перенумеровывать только ради унификации.
