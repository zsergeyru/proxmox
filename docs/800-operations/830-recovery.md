## 1. Предварительные условия

До восстановления должны быть доступны:

- PVE и его локальная консоль или административный доступ;
- пригодная резервная копия канонического корня `infra-manager` на PVE;
- ключ расшифрования резервной копии;
- проектный read-only GitHub доступ из recovery-области, если OpenBao недоступен.

Точный состав каталогов находится в `230-host-layout.md`. Эта инструкция не дублирует полную файловую карту.

## 2. Основной принцип

Rootfs 910 считается воспроизводимым.

Уникальное состояние должно переживать его удаление:

~~~text
PVE-only
→ ключи от OpenBao и независимые recovery credentials

access
→ PVE-owned данные для штатной работы 910

state
→ OpenBao, OpenTofu и Semaphore
~~~

Если `state/openbao/` сохранён, необходимо поднимать прежний OpenBao, а не создавать новый.

Новый пустой OpenBao допустим только при подтверждённой потере прежнего состояния и запускает отдельную процедуру смены доверия.

## 3. Потерян только 910

Если PVE-каталоги целы:

~~~text
проверить pve-only, access и state
→ создать чистый LXC 910
→ подключить access только для чтения
→ подключить state для чтения и записи
→ проверить владельцев и права
→ получить проект
→ применить provision.yaml
→ запустить Docker и infra-runtime
→ запустить OpenBao на прежнем state/openbao
→ снять блокировку прежним unseal key
→ проверить OpenTofu state
→ проверить Semaphore
→ выполнить полную проверку готовности
~~~

Рабочие PVE API, Git и сервисные credentials после запуска снова получаются из прежнего OpenBao KV.

## 4. OpenBao запечатан или повреждена его настройка

Если Raft-state сохранён, новый OpenBao не создаётся.

Порядок:

1. проверить соответствие `state/openbao/` и PVE-only unseal data;
2. запустить OpenBao на прежнем Raft;
3. снять блокировку через PVE-only механизм;
4. при необходимости восстановить policies/auth methods контролируемой административной процедурой;
5. проверить KV и оба SSH CA;
6. отозвать временные полные полномочия, если они использовались.

Потеря AppRole или другого machine credential не требует пересоздания OpenBao. Такой credential перевыпускается отдельно и старый отзывается.

## 5. Полностью потеряно состояние OpenBao

Этот сценарий означает потерю прежних SSH CA, KV secrets и policies, если нет пригодной резервной копии.

Порядок восстановления:

1. использовать PVE-only recovery Git credential, чтобы получить проект;
2. создать новый OpenBao только после явного подтверждения потери прежнего state;
3. создать новый KV, SSH CA, auth methods и policies из Git-конфигурации;
4. заново создать рабочие PVE API и другие credentials, которые нельзя восстановить из копии;
5. поместить рабочие secrets в новый OpenBao KV;
6. обновить доверие Linux-гостей к новому SSH Client CA через recovery SSH administrator key;
7. повторно выпустить SSH host certificates;
8. перевыпустить машинные identities обычных гостей;
9. выполнить проверки доступа и запретов.

Нельзя выдавать новый CA за прежний или автоматически считать такой переход обычным повторным запуском.

## 6. Восстановление SSH-доверия после смены CA

Recovery SSH private key находится только на PVE и используется явным восстановительным действием.

Для каждого управляемого Linux-гостя:

~~~text
войти recovery key
→ установить новый public SSH Client CA
→ проверить конфигурацию sshd
→ получить штатный короткоживущий сертификат нового OpenBao
→ подтвердить вход
~~~

После успешной проверки recovery public key остаётся аварийным контуром. Он не удаляется только потому, что OpenBao снова работает.

Штатный Ansible не должен молча использовать recovery key при ошибке сертификатного входа.

## 7. Проверка после восстановления

Нужно подтвердить:

- `infra-manager-status --full` без ошибок;
- `initialized=true` и `sealed=false` OpenBao;
- наличие KV и обоих SSH CA;
- чтение рабочего Git-проекта через штатный OpenBao-контур;
- доступ 910 к PVE API;
- целостность OpenTofu state без незапланированного `apply`;
- доступность Semaphore;
- штатный SSH по новому Client CA;
- запрет гостю получить доступ, которого нет в `access.yaml`;
- сохранность recovery credentials только в PVE-only области.
