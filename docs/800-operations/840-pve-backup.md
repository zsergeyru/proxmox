# Резервирование PVE и 910

**Тип:** эксплуатация

**Состояние:** программы подготовлены в Git; реальные диски, снимки OpenBao,
архивы и восстановление должны быть подтверждены на работающем оборудовании.

## 1. Единый порядок работы

Владелец использует **только штатные команды** на PVE:

```bash
infra-manager deploy 910
infra-manager status 910
```

`deploy 910` автоматически устанавливает внутренние программы резервирования,
их зависимости, безопасно сверяет `storage.yaml` и `backup.yaml`,
подготавливает **только подтверждённые** назначения и включает фоновую
проверку готовности. Отдельной публичной команды резервирования нет.

Если диски ещё неизвестны, NAS недоступен или отсутствует независимая
копия ключа, состояние **«резервирование ожидает подготовки»** видно
через `status 910`; 910 продолжает работать. После появления подтверждённых
описаний и оборудования служба автоматически продолжит работу без
дополнительной команды. Исходную Git-конфигурацию не подменяют вручную
редактируемыми сценариями.

## 2. Какие данные сохраняются

В шифрованный комплект входят настройки PVE и сети, защищённые области
`pve-only/` и `access/`, постоянные состояния Semaphore, OpenTofu и
`physical-hosts`. Для Semaphore применяется согласованное копирование
SQLite, для OpenBao — штатный снимок Raft, запрашиваемый из 910 узким
временным доступом. Работающий каталог Raft непосредственно не архивируется.

VM 100 Home Assistant сохраняется `vzdump` один раз в сутки. Состояния
PVE и 910 копируются каждые шесть часов. Копирование использует общую
блокировку с изменяющими заданиями, чтобы не получить частичное состояние.

Фотографии и большие данные NAS должны резервироваться отдельным
согласованным процессом на NAS: этот комплект их не заменяет.

## 3. Подтверждение носителей

`infrastructure/hosts/pve/storage.yaml` определяет **конкретный**
`backup_ssd`: модель, серийный номер и постоянную ссылку
`/dev/disk/by-id/...`. Система ничего не форматирует при неизвестном
серийном номере или пути, изменившихся разделах и наличии сигнатур.

Если накопитель уже размечен и имеет проверенную ext4, он
подключается по подтверждённому UUID без переформатирования.

Для создания раздела на **совершенно пустом** диске необходимо отдельное
явное разрешение: поле `initialize_blank_ssd_serial` в `backup.yaml`
должно точно совпадать с серийным номером `backup_ssd`. По умолчанию
там `null`, и разметка запрещена. Это согласование в машинном описании,
а не ещё одна команда. При наличии NTFS, других разделов или неизвестных
сигнатур форматирование запрещено даже при заполненном разрешении.

NAS должен предварительно предоставить отдельный экспорт NFSv4 из области
резервного хранения. Проверенный адрес экспорта записывается в
`backup.yaml`. При недоступном NAS запись в локальную пустую папку вместо
сети запрещена. UUID SSD и результаты фактического подключения сохраняются
в защищённом локальном состоянии PVE и переживают обычный `deploy`.
Само развёртывание 910 **не форматирует диски NAS**.

## 4. Защита ключа и расписание

После проверки обоих носителей infra-manager самостоятельно создаёт
два зашифрованных хранилища restic и один пароль для них, не перезаписывая
старые ключи. Для снимков Raft создаётся ограниченный доступ OpenBao:
временный корневой доступ отзывается; данные снимка передаются на PVE,
ключ разблокировки OpenBao никогда не попадает внутрь 910.

**Обязательное условие:** пароль расшифрования необходимо сохранить вне
PVE, 910, основного SSD и NAS. Для этого в `backup.yaml` указывается
путь `recovery_key_destination` в корне третьего отдельного
подключённого носителя. Никаких ключей в Git или чате.

Когда оба места хранения доступны, ключ надёжно сохранён и первая
проверенная копия получена, infra-manager **сам** включает расписание
systemd. До этого расписание выключено; предупреждение видно через
обычный `status 910`.

Старые точки нельзя удалять до пробного восстановления. Хранение:
на SSD не менее двух последних успешных комплектов, на NAS —
семь ежедневных и четыре еженедельных.

## 5. Проверка восстановления

В ходе отдельного испытания архива проверяются его чтение,
полнота PVE-only ключей и состояние OpenBao, Semaphore и OpenTofu
в **изолированной среде**. Тестовая VM 100 не должна управлять
реальными домашними устройствами.

Внутренний сценарий извлечения не перезаписывает рабочую систему.
Проверка архива, выполненная программой, ещё не подтверждает
успешный запуск восстановленных служб; результат фиксируется после
испытания на оборудовании.
