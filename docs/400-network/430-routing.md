## 1. Основной принцип

Маршрут определяется централизованными сетевыми правилами, а не отдельными приложениями.

Обычный трафик использует основной путь. Специальный путь применяется только при явном совпадении с правилом.

## 2. Классификация трафика

Правило может учитывать:

- источник;
- адрес назначения;
- DNS-группу назначения;
- сетевой сегмент;
- требуемый VPN-путь.

Правила не должны противоречить друг другу. Для пересекающихся условий должен быть понятен приоритет.

## 3. Выбор маршрута

Policy routing использует отдельные таблицы маршрутизации и метки только там, где обычной таблицы недостаточно.

Общая схема:

~~~text
пакет
→ классификация
→ метка при необходимости
→ правило маршрутизации
→ основная таблица или отдельный VPN-маршрут
~~~

## 4. nftables

`nftables` используется для классификации, фильтрации и технических сетевых преобразований.

Конфигурация должна быть воспроизводимой и применяться атомарно, чтобы частично загруженный набор правил не становился рабочим состоянием.

## 5. NAT

NAT применяется только на границе, где он нужен выбранной топологии.

Наличие VPN или отдельной таблицы маршрутизации само по себе не означает необходимость дополнительного NAT.

## 6. Ошибки и запасные пути

Для каждой специальной группы должно быть заранее определено поведение при недоступности её маршрута:

- запрет трафика;
- возврат к основному пути;
- другой разрешённый резервный путь.

Такое решение должно быть явным, а не зависеть от случайного состояния таблиц.

## 7. Проверка

Проверка должна подтверждать:

- основной маршрут;
- каждый специальный маршрут;
- корректность меток и таблиц;
- отсутствие обхода запрещённого пути;
- ожидаемое поведение при отключении VPN;
- отсутствие конфликтующих правил.
