## 1. Основной принцип

DNS определяет адрес ресурса. Он может дополнительно помочь классифицировать домен, но сам не выбирает сетевой маршрут.

## 2. SmartDNS

SmartDNS является основной точкой обработки DNS-запросов специализированного сетевого контура.

Он должен:

- принимать запросы от разрешённых локальных клиентов;
- использовать несколько разрешённых вышестоящих серверов;
- поддерживать безопасные DNS-транспорты, когда они выбраны;
- передавать маршрутизации только необходимую информацию о группах адресов.

## 3. Вышестоящие DNS

Архитектура допускает обычный DNS, DoH и DoT.

Конкретный сервер не должен быть единственной жёсткой зависимостью, если можно определить безопасный запасной путь.

Выбор нескольких upstream не означает случайное смешение политик: правила выбора должны быть воспроизводимыми.

## 4. Связь с маршрутизацией

Для доменных групп, которым нужен особый маршрут:

~~~text
DNS-запрос
→ определение адреса
→ адрес попадает в управляемую группу
→ nftables / policy routing выбирают сетевой путь
~~~

DNS не подменяет firewall или таблицы маршрутизации.

## 5. Отказоустойчивость

При недоступности одного upstream должен использоваться заранее разрешённый резервный вариант.

Отказ VPN не должен автоматически делать недоступным весь DNS, если запрос не требует именно VPN-зависимого пути.

## 6. Проверка

Проверка должна подтверждать:

- разрешение обычных внутренних и внешних имён;
- работу выбранных защищённых upstream;
- переключение на допустимый резервный upstream;
- корректное формирование групп для маршрутизации;
- отсутствие DNS-утечки там, где политика явно требует отдельного пути.
