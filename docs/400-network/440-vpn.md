## 1. Основной принцип

VPN предоставляет сетевой выход. Он не является самостоятельным источником правил о том, какой трафик должен его использовать.

## 2. AmneziaWG

Основным рассматриваемым VPN-механизмом является AmneziaWG.

Его интерфейс рассматривается маршрутизацией как один из доступных путей.

Секретные параметры VPN не хранятся в Git. Внутренние VPN credentials должны храниться и выдаваться через OpenBao.

## 3. Другие туннели и sing-box

Архитектура должна позволять добавить другой VPN-интерфейс без изменения общей модели классификации трафика.

`sing-box` применяется только для сценариев, где нужен прокси или иной прикладной способ исходящего соединения.

Он не заменяет SmartDNS, `nftables` или общую policy routing.

## 4. Связь с маршрутизацией

~~~text
трафик
→ общая классификация
→ выбор маршрута
├── основной выход
├── AmneziaWG
└── другой разрешённый выход
~~~

VPN-конфигурация не должна содержать вторую независимую матрицу выбора доменов, если это уже определяется общими сетевыми правилами.

## 5. Поведение при отказе

Для каждой группы трафика заранее определяется, разрешён ли fallback на обычный канал.

Трафик, для которого VPN является обязательной границей, не должен незаметно уходить напрямую после падения туннеля.

## 6. Проверка

Проверка должна подтверждать:

- состояние каждого требуемого туннеля;
- фактический внешний путь тестового трафика;
- отсутствие утечки обязательного VPN-трафика;
- ожидаемый fallback там, где он разрешён;
- восстановление маршрута после перезапуска сетевой VM.
