# Обзор хранения данных

**Тип:** обзор

**Статус:** действующий

## 1. Назначение и границы

### 1.1. Что описывает раздел

Хранение связывает конфигурацию проекта, диски гостевых систем и данные приложений. Для понимания этой связи важны два вопроса: где находятся данные и можно ли получить их заново после потери.

Один диск может одновременно содержать воспроизводимую ОС, уникальные данные приложения и временный кэш. Поэтому назначение данных не определяется только местом их размещения.

### 1.2. Где искать подробности

В этом обзоре нет расписаний копирования, сроков хранения, перечней резервируемых файлов и команд восстановления. Они находятся в политике резервного копирования и эксплуатационных инструкциях.

Точные пути и подключения хранилищ относятся к документации PVE и конкретных гостей. Причины выбора способов защиты данных собраны в файле решений раздела.

## 2. Виды данных

### 2.1. Требуемое состояние

Это описание того, какой должна быть система: манифесты гостей, настройки, код, Ansible и документация. Основной источник этих сведений — Git.

### 2.2. Рабочие данные

Это содержимое, которое возникает при работе служб: базы, история Home Assistant, пользовательские файлы, данные приложений и видеозаписи. Повторная установка программы обычно не возвращает это содержимое.

### 2.3. Служебное состояние

Это сведения, необходимые средствам управления: учёт уже созданных объектов, состояние доверия и данные выполнения. Их потеря может мешать безопасному продолжению работы даже при сохранности самих приложений.

### 2.4. Секреты и учётные данные

Ключи, токены и пароли обеспечивают доступ к системам. Они требуют защищённого хранения; их жизненный цикл определяется разделом безопасности. Создание нового ключа не всегда равнозначно восстановлению прежнего доступа.

### 2.5. Временные данные

Кэш, промежуточные результаты и файлы текущего запуска обычно можно получить заново. Журналы могут иметь другое назначение: история для расследования или аудита относится к сохраняемым данным, если её потеря недопустима.

## 3. Размещение данных

### 3.1. Git

Git хранит версионируемые описания и воспроизводимые файлы проекта. Рабочая копия репозитория внутри гостя служит для применения этих описаний и не является хранилищем рабочих баз или секретов.

### 3.2. Хранилища PVE

PVE размещает виртуальные диски, корневые файловые системы LXC и установочные образы на физических носителях. Внутри виртуального диска гостевая ОС размещает файлы приложений.

PVE управляет диском как объектом виртуализации. Назначение отдельных файлов и требования приложения к их сохранению определяются на уровне службы.

### 3.3. Гостевые системы

Внутри гостя находятся ОС, конфигурация, приложения и их данные. Linux-каталоги выбираются по назначению файлов согласно профильной политике файловой структуры.

Часть данных может находиться вне корневой файловой системы и подключаться отдельно. В постоянном управляющем контуре это позволяет пересоздать ОС и подключить сохранённое состояние. Такое подключение относится к рабочему хранению.

### 3.4. Внешние хранилища

Внешнее хранилище может содержать рабочие данные или резервные копии. Это разные роли: само слово «внешнее» не означает, что размещённые там данные имеют независимую копию.

Места резервного копирования выбираются по политике резервирования. Фактические носители, доступность и подключения фиксируются в документации PVE-хоста.

## 4. Воспроизводимость и защита данных

### 4.1. Воспроизводимые и невоспроизводимые данные

Воспроизводимые данные можно получить из сохранённой версии проекта, доступных зависимостей и средств развёртывания. Например, Ansible создаёт описанную конфигурацию заново.

Невоспроизводимые данные требуют сохранённого содержимого. Установка той же программы не возвращает её прежнюю базу, историю или уникальную идентичность. Политика резервирования определяет, какие данные и с какими гарантиями сохраняются.

### 4.2. Рабочее состояние, снимок и резервная копия

Рабочее состояние используется службой сейчас. Снимок фиксирует прежнее состояние для быстрого возврата. Независимая резервная копия позволяет восстановить содержимое после потери рабочего хранилища.

Это различие объясняет назначение средств защиты; обязательные требования к независимости и составу копий находятся в политике резервирования.
