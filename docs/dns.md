# DNS и mDNS

## Основной внутренний DNS-домен

Для управляемых имён домашней инфраструктуры принимается домен:

```text
home.arpa
```

Он используется для серверов, VM/LXC, Home Assistant, MQTT и других постоянных сервисов.

Примеры целевых имён:

```text
pve.home.arpa
ha.home.arpa
mqtt.home.arpa
apps.home.arpa
ai.home.arpa
```

Внутренний DNS должен публиковать стабильные записи для инфраструктуры и по возможности использовать имена вместо жёстко записанных IP-адресов. Это особенно важно во время перехода с `192.168.0.0/16` на `10.0.0.0/16` и при будущем dual stack IPv4/IPv6.

Для IPv4 используются записи `A`, для IPv6 после его включения — также `AAAA`.

## Текущее состояние

На Proxmox-хосте `pve` по состоянию на 2026-09-12 наблюдается:

```text
search home.arpa
nameserver 192.168.1.1
```

То есть текущим DNS-сервером для хоста является Keenetic `192.168.1.1`, а `home.arpa` уже используется как DNS search suffix.

`search home.arpa` не создаёт DNS-зону сам по себе. Он означает, что короткое имя, например:

```text
pve
```

может быть дополнено резолвером до:

```text
pve.home.arpa
```

если соответствующая DNS-запись существует.

После перехода DNS-функций на `101-network-gateway` именно домашний DNS-контур (AdGuard Home / SmartDNS и при необходимости authoritative/local records) должен обслуживать `home.arpa`.

## mDNS

mDNS используется параллельно с обычным DNS и не заменяет `home.arpa`.

Для mDNS используется специальный домен:

```text
.local
```

Примеры:

```text
ha.local
printer.local
esp32-bath.local
```

Целевая модель:

```text
home.arpa  → управляемые постоянные имена инфраструктуры
.local     → автоматическое обнаружение устройств через mDNS
```

Для Proxmox, Home Assistant, MQTT, серверов и других критичных сервисов основным механизмом должен быть обычный DNS в `home.arpa`. На mDNS не следует строить обязательные зависимости инфраструктуры.

## mDNS между VLAN

mDNS по умолчанию рассчитан на локальный L2-сегмент и обычно не маршрутизируется между MAIN, IOT и другими VLAN.

Целевая сеть имеет отдельные сегменты:

```text
MAIN             10.0.0.0/16
IOT / VLAN 20    10.20.0.0/16
CAMERAS / VLAN 30 10.30.0.0/16
```

Если Home Assistant или пользовательские устройства в MAIN должны автоматически находить mDNS-устройства в IOT, на `101-network-gateway` может быть включён mDNS reflector/repeater, например через Avahi или эквивалентный механизм.

Reflection должен включаться только между явно выбранными сегментами и с учётом firewall. Не следует без необходимости отражать mDNS во все VLAN, особенно в CAMERAS.

Обычный DNS `home.arpa` при этом работает через L3-маршрутизацию и не требует mDNS reflection.

## Remote-access VPN

Удалённые клиенты через `101-network-gateway` должны получать домашний DNS и разрешать имена `*.home.arpa`.

mDNS через VPN не считается обязательной частью базовой архитектуры. Если позже понадобится удалённое обнаружение mDNS-устройств, это должно внедряться отдельно и осознанно.
