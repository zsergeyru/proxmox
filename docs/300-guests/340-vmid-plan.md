# План VMID / CTID

**Тип:** спецификация  
**Статус:** проектируется  
**Назначение:** задать единую функциональную нумерацию постоянных VM и LXC проекта.

## 1. Правило номера

Для постоянных гостевых систем используется трёхзначный VMID/CTID:

```text
XYZ

X — функциональная область
Y — сервис внутри области
Z — экземпляр сервиса
```

Основной экземпляр сервиса получает номер с последней цифрой `0`.

Примеры:

```text
210 — основной экземпляр сервиса
211 — второй экземпляр того же сервиса
212 — третий экземпляр того же сервиса
```

Поэтому обычные основные VM/LXC, как правило, имеют VMID/CTID, кратный 10.

Номера `100`, `200`, `300` и другие кратные 100 не используются для обычных гостевых систем. Они обозначают границы функциональных областей.

## 2. Функциональные области

| Диапазон | Назначение |
|---|---|
| `100–190` | сеть и сетевые службы |
| `200–290` | умный дом и домашняя автоматизация |
| `300–390` | приложения и разработка |
| `400–490` | AI и голосовые сервисы |
| `500–590` | видео и наблюдение |
| `600–690` | хранение и резервные копии |
| `700–790` | мониторинг и журналы |
| `800–890` | резерв для будущей функциональной области |
| `900–990` | управление инфраструктурой |

В диапазоне AI закреплён основной управляющий гость:

```text
410 — ai-control
```

Номера `411–419` резервируются для дополнительных или тестовых экземпляров AI Control. Остальные номера диапазона `400–490` распределяются по отдельным AI- и голосовым сервисам по мере их утверждения.

## 3. Управление инфраструктурой

Диапазон `900–990` предназначен не для прикладных сервисов, а для средств, которыми разворачивается и обслуживается сама инфраструктура.

Первым закреплённым объектом этого диапазона является:

```text
910 — infra-manager
```

`910 infra-manager` — постоянный управляющий LXC проекта. Он является основным экземпляром сервиса развёртывания инфраструктуры.

Номера `911–919` резервируются для дополнительных или тестовых экземпляров того же сервиса, если они когда-либо понадобятся.

## 4. Технические объекты

Четырёхзначные технические VMID не входят в функциональную трёхзначную нумерацию постоянных сервисов.

Например:

```text
9000 — базовый Debian VM template
```

Технические VM для сборки, проверки или других временных задач должны получать отдельные номера в техническом диапазоне и не влиять на функциональную нумерацию `100–990`.

## 5. Применение правила

Новая нумерация является целевой для переработанной архитектуры в ветке `infra-iac-redesign`.

Перенумерация существующих каталогов `guests/`, манифестов и фактических VM/LXC выполняется отдельно после утверждения полного соответствия сервисов новым функциональным областям.

До этого данный документ фиксирует именно правило нумерации и назначение диапазонов.
