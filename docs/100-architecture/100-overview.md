# Архитектура проекта Proxmox

**Тип:** обзор  
**Статус:** действующий  
**Назначение:** простое и полное описание того, из каких основных частей состоит система и как они связаны между собой.

Этот документ нужен для первого знакомства с проектом.

Он отвечает на вопрос:

> Как в целом устроен проект Proxmox?

Точные обязанности отдельных частей описываются в `110-system-boundaries.md`, а размещение и источники данных — в `120-state-model.md`.

## 1. Что представляет собой система

### 1.1. Назначение проекта

Проект предназначен для управления домашней серверной инфраструктурой на базе Proxmox VE.

В него входят:

- сам сервер Proxmox;
- виртуальные машины и LXC-контейнеры;
- шаблоны для создания новых гостевых систем;
- средства развёртывания и первоначальной настройки;
- автоматизация через AI Control и Ansible;
- сеть, DNS, VPN и маршрутизация;
- хранилища и резервное копирование;
- средства контроля доступа и безопасности;
- Git-репозиторий, в котором хранится описание требуемого состояния системы.

Главная цель проекта — сделать инфраструктуру понятной, воспроизводимой и управляемой.

### 1.2. Общая схема

Упрощённо система выглядит так:

```text
Git-репозиторий
      │
      ▼
описание требуемого состояния
      │
      ▼
Proxmox VE
      │
      ├── виртуальные машины
      ├── LXC-контейнеры
      └── шаблоны
             │
             ▼
      гостевые операционные системы
             │
             ├── сервисы
             ├── Docker
             └── прикладные приложения

AI Control
      │
      ├── управляет разрешёнными объектами Proxmox
      └── запускает дальнейшую автоматизацию

Ansible
      │
      └── повторяемо настраивает гостевые системы
```

### 1.3. Основные объекты системы

К основным объектам относятся:

- физический сервер Proxmox;
- виртуальные машины;
- LXC-контейнеры;
- шаблоны гостевых систем;
- средства развёртывания;
- AI Control;
- Ansible;
- Git-репозиторий;
- сетевой шлюз;
- DNS;
- VPN;
- хранилища;
- резервные копии;
- технические учётные данные и ключи доступа;
- внешние связанные системы.

## 2. Вычислительная часть

### 2.1. Proxmox VE

Proxmox VE является основной платформой виртуализации.

Он запускает и хранит конфигурацию виртуальных машин и LXC-контейнеров, предоставляет API для управления ими и связывает гостевые системы с сетью и хранилищами.

Сам Proxmox рассматривается как отдельный инфраструктурный уровень.

Управление гостевыми системами и управление самим Proxmox не считаются одной и той же задачей.

### 2.2. Виртуальные машины и LXC-контейнеры

Виртуальные машины и LXC-контейнеры используются для размещения отдельных инфраструктурных и прикладных сервисов.

Каждая гостевая система имеет своё назначение.

Например, отдельные гости могут использоваться для:

- Home Assistant;
- сетевых функций;
- AI Control;
- сервисов автоматизации;
- средств разработки;
- мониторинга;
- видеонаблюдения;
- других домашних сервисов.

Конкретный список гостевых систем и их параметры описываются отдельно.

### 2.3. Шаблоны гостевых систем

Шаблоны используются как подготовленная основа для создания новых гостевых систем.

Основной шаблон Debian имеет VMID `9000`.

Шаблон не является обычным рабочим сервером.

Его задача — содержать минимально подготовленную операционную систему, из которой можно быстро и одинаково создавать новые виртуальные машины.

## 3. Управление и автоматизация

### 3.1. Средство развёртывания

Для создания и изменения гостевых систем используется средство развёртывания.

Оно читает описание требуемого состояния из Git, сравнивает его с текущим состоянием Proxmox и при разрешении применяет необходимые изменения.

Развёртывание должно быть повторяемым: повторный запуск не должен без причины менять уже правильно настроенную систему.

### 3.2. Первоначальная настройка гостевой системы

После создания новой виртуальной машины или контейнера выполняется минимальная первоначальная настройка.

Она нужна, чтобы гостевая система стала пригодной для дальнейшего управления.

На этом этапе могут подготавливаться:

- административный SSH-доступ;
- базовые системные компоненты;
- Git;
- Docker;
- Ansible;
- другие заранее определённые возможности.

После этого более сложная и повторяемая настройка передаётся специализированным средствам.

### 3.3. Ansible

Ansible используется для повторяемой настройки Linux внутри гостевых систем.

Он отвечает за изменения внутри операционной системы и приложений, а не за управление самим Proxmox.

Через Ansible удобно устанавливать пакеты, создавать конфигурационные файлы, запускать сервисы и поддерживать одинаковое состояние серверов.

### 3.4. AI Control

AI Control — отдельная управляющая система для автоматизации инфраструктуры.

Она может выполнять разрешённые действия с виртуальными машинами и контейнерами через Proxmox API, а также использовать SSH и Ansible для работы внутри гостевых систем.

AI Control не должен автоматически получать полный административный доступ ко всему Proxmox-хосту.

Его возможности ограничиваются заранее заданными границами.

### 3.5. Git-репозиторий

Git-репозиторий хранит описание того, как инфраструктура должна быть устроена.

В нём находятся:

- документация;
- описания гостевых систем;
- сценарии настройки;
- шаблоны;
- конфигурационные файлы;
- исходный код средств управления.

Секретные данные в Git не хранятся.

## 4. Инфраструктура

### 4.1. Сеть

Сеть связывает Proxmox, гостевые системы, домашние устройства и внешние сети.

В проекте отдельно рассматриваются:

- административная адресация;
- маршрутизация;
- сетевой шлюз;
- DNS;
- VPN;
- IPv4;
- IPv6.

Сам Proxmox не должен неявно становиться центральным маршрутизатором, если это отдельно не предусмотрено архитектурой.

### 4.2. DNS и VPN

DNS используется для разрешения имён внутри домашней инфраструктуры и для выбора внешних DNS-серверов.

VPN используется для защищённого удалённого доступа и для отдельных сценариев маршрутизации.

Эти функции относятся к сетевой части проекта и подробно описываются в отдельном разделе документации.

### 4.3. Хранилища

Хранилища используются для размещения:

- дисков виртуальных машин;
- файлов контейнеров;
- шаблонов;
- резервных копий;
- постоянных данных сервисов.

Разные типы данных могут храниться в разных местах в зависимости от их назначения и требований к восстановлению.

### 4.4. Резервное копирование

Резервное копирование защищает данные и гостевые системы от потери.

Git не заменяет резервные копии.

Даже если конфигурацию можно восстановить из Git, постоянные данные приложений, базы данных, ключи и другие изменяемые данные требуют отдельного резервного копирования.

## 5. Безопасность и доступ

### 5.1. Разделение доступа

Разные способы управления системой разделяются.

Отдельно рассматриваются:

- доступ к самому Proxmox;
- доступ через Proxmox API;
- SSH-доступ внутрь гостевых систем;
- доступ к Git;
- доступ к секретам и ключам.

Наличие одного вида доступа не должно автоматически означать наличие другого.

### 5.2. Права

Пользователи и автоматизация получают только те права, которые им действительно нужны.

Средство развёртывания, AI Control, Ansible и человек могут использовать разные учётные данные и иметь разные границы доступа.

### 5.3. Секреты и ключи

Пароли, закрытые SSH-ключи, API-токены и другие секреты не хранятся в Git.

Они размещаются в специально предназначенных для этого защищённых местах.

Открытые ключи могут храниться отдельно и использоваться для организации управляемого доступа.

## 6. Связанные системы

### 6.1. Проект квартиры

Физическая инфраструктура квартиры ведётся отдельно от серверной инфраструктуры Proxmox.

К проекту квартиры относятся, например:

- физическая прокладка сети;
- кабели;
- розетки;
- камеры;
- шкафы;
- размещение оборудования;
- другие физические элементы.

Проект Proxmox описывает серверную и программную часть инфраструктуры.

### 6.2. Внешние сервисы

Система может взаимодействовать с внешними сервисами:

- Git-хостингом;
- внешними DNS-серверами;
- VPN-сервисами;
- облачными API;
- другими сетевыми сервисами.

Такие зависимости должны быть явно описаны в соответствующих тематических разделах.
