## 1. Основной принцип

Git-доступ является отдельным контуром доверия.

Credential чтения проекта не используется для административного SSH, PVE API или подписи SSH-сертификатов.

Чтение и запись являются разными полномочиями.

## 2. Рабочий credential

Рабочий доступ к репозиторию проекта использует отдельный GitHub Deploy Key без права записи.

Рабочее секретное представление ключа хранится в OpenBao KV.

Штатные системы получают его только если это разрешено `infrastructure/security/access.yaml` и соответствующей OpenBao policy.

Credential не должен становиться постоянным общим файлом, доступным всем гостям.

При использовании внутри гостя private key материализуется только в защищённом месте на минимально необходимое время либо предоставляется эквивалентным безопасным способом без вывода секрета в журнал.

## 3. Восстановительная копия

Полная потеря OpenBao не должна лишать возможности получить Git-проект, необходимый для восстановления самого управляющего контура.

Поэтому read-only GitHub Deploy Key имеет защищённую восстановительную копию в PVE-only recovery-области.

Эта копия:

- не монтируется постоянно в 910;
- не выдаётся обычным гостям;
- используется первоначальным или восстановительным контуром до запуска OpenBao;
- резервируется вместе с остальными recovery-данными.

Рабочее представление в OpenBao KV и PVE-only recovery-копия должны соответствовать одному зарегистрированному read-only Deploy Key. При его ротации обновляются обе части восстановительного комплекта.

## 4. Выдача гостям

Право читать проект задаётся не флагом `guest.yaml`, а правилом `access.yaml`.

Пример смысла правила:

~~~text
guest:410
→ git
→ project
→ read
~~~

OpenBao policy разрешает такому субъекту получить только read-only credential проекта.

Отсутствие правила означает отсутствие управляемого Git credential.

Установка самой программы Git относится к `provision.yaml`, а не к политике доступа.

## 5. Проверка GitHub

SSH-подключение к GitHub использует строгую проверку server host key.

Неизвестный или неожиданно изменившийся ключ не принимается автоматически.

Git `known_hosts` не смешивается с SSH-доверием к PVE или Linux-гостям.

## 6. Право записи

Право записи не входит в `read` и требует отдельного правила, отдельного credential и отдельного жизненного цикла.

Личный Git credential человека не используется как постоянный credential автоматизации.

## 7. Смена и отзыв

При потере или компрометации Deploy Key создаётся новая пара, новая открытая часть регистрируется в GitHub, а прежняя регистрация удаляется.

Ротация считается завершённой только после обновления:

- рабочего секрета OpenBao KV;
- PVE-only recovery-копии;
- строгой проверки чтения проекта.

Отзыв Git credential не требует менять SSH CA, PVE API credential или recovery SSH key.

## 8. Проверка

Проверка должна подтверждать:

- чтение проекта ожидаемым Deploy Key;
- отсутствие права записи;
- строгую проверку GitHub SSH-сервера;
- отсутствие рабочего Git credential у субъекта без соответствующего правила `access.yaml`;
- отсутствие постоянного распространения recovery-копии;
- соответствие рабочего и восстановительного представления одной зарегистрированной паре.
