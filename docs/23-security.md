# Безопасность инфраструктуры

Этот документ фиксирует общие правила безопасности проекта. Частные ограничения для отдельных виртуальных машин, контейнеров и сервисов описываются в их собственной документации.

## Основные правила

1. Автоматизация управляет только теми виртуальными машинами и контейнерами, для которых это явно разрешено.

2. Сам Proxmox не изменяется автоматикой без отдельного решения. Особенно это относится к:
   - сетевым мостам и физическим сетевым интерфейсам;
   - маршрутам самого сервера;
   - настройкам хранилищ;
   - пользователям, ролям и правам доступа;
   - репозиториям обновлений и сертификатам;
   - сетевому экрану самого Proxmox;
   - выключению и перезагрузке физического сервера.

3. Для Linux-гостей основной административный пользователь — `ops`.

4. Для разных задач можно использовать разные SSH-ключи. SSH — защищённый способ удалённого доступа к Linux-системе. Не нужно создавать отдельного пользователя для каждой задачи без необходимости.

5. Пароли, токены, закрытые ключи и другие секреты не хранятся в Git. В репозитории допускаются только примеры конфигурации без действующих секретов.

6. Перед удалением, откатом или другим опасным изменением необходимо проверить правильность выбранного объекта и наличие способа восстановления: резервной копии, снимка состояния или воспроизводимой конфигурации.

7. После изменения обязательно проверяется результат: состояние гостя, работа нужных служб и журналы ошибок.

8. Действия автоматизации по возможности журналируются. В журнале должно быть понятно, что и над каким объектом было сделано, но секретные значения туда попадать не должны.

9. Для контейнеров используются минимально необходимые привилегии. Если сервису требуются широкие системные права или особый доступ к оборудованию, предпочтительнее отдельная виртуальная машина. Подробные правила Docker внутри LXC описаны в [`32-docker-in-lxc-policy.md`](32-docker-in-lxc-policy.md).

10. Если автоматике не хватает прав, она не должна расширять их самостоятельно. Изменение прав является отдельным инфраструктурным решением.

## Главный принцип

> Автоматизация свободно работает только в заранее разрешённой области. Основа инфраструктуры и права доступа изменяются осознанно и с возможностью восстановления.

Дополнительные правила конкретных подсистем описываются в соответствующих документах и ADR.
