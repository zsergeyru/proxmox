# IPv6

IPv6 в домашней инфраструктуре поддерживается как второй стек параллельно с IPv4. Текущая IPv4-архитектура `10.x.x.x` остаётся основной и обязательной; IPv6 не заменяет её.

## Базовый принцип

Целевая модель — dual stack:

```text
IPv4 + IPv6 одновременно
```

IPv4 продолжает использоваться для понятной статической адресации серверов, VM/LXC, VLAN, VPN и management-доступа. IPv6 добавляется параллельно по мере готовности провайдера и сетевого шлюза.

## Распределение IPv6 по сегментам

Каждый отдельный L2-сегмент/VLAN должен получать собственный IPv6-префикс `/64`.

Логически схема должна соответствовать существующей сегментации:

```text
MAIN          → отдельный /64
IOT / VLAN 20 → отдельный /64
CAMERAS / 30  → отдельный /64
REMOTE-VPN    → отдельный /64 при включении IPv6 в VPN
```

Конкретные глобальные IPv6-префиксы заранее не фиксируются: они зависят от того, какой prefix delegation выдаёт интернет-провайдер новой квартиры.

## Требования к провайдеру

Перед включением IPv6 нужно выяснить:

- поддерживается ли native IPv6;
- поддерживается ли DHCPv6 Prefix Delegation (DHCPv6-PD);
- какой размер префикса выдаётся абоненту: `/64`, `/60`, `/56`, `/48` и т.п.;
- является ли делегированный префикс постоянным или динамическим.

Предпочтительно получить как минимум `/56`, поскольку этого достаточно для большого количества отдельных `/64` сегментов. `/60` также подходит для нескольких сегментов. Один `/64` неудобен для архитектуры с несколькими VLAN, потому что каждый L2-сегмент обычно должен иметь собственный `/64`.

Проверку фактических параметров провайдера выполнить позже на Keenetic Hopper или непосредственно на будущем `101-network-gateway`.

## Роль `101-network-gateway`

`101-network-gateway` должен быть спроектирован с поддержкой IPv6 даже если на первом этапе IPv6 будет выключен.

Нужны:

- IPv6 forwarding;
- получение delegated prefix от провайдера через DHCPv6-PD;
- распределение отдельных `/64` по MAIN и VLAN;
- Router Advertisement (RA) для клиентских сетей;
- IPv6 firewall через `nftables`;
- IPv6-маршрутизация между разрешёнными сегментами;
- поддержка DNS AAAA-записей;
- поддержка IPv6 в remote-access VPN.

## Firewall и NAT

В обычной схеме IPv6 NAT не требуется. Устройства могут получать глобальные IPv6-адреса, а защита входящих соединений обеспечивается stateful firewall на `101-network-gateway`.

Принцип:

```text
Internet
   ↓
IPv6 firewall на 101-network-gateway
   ↓
разрешённые домашние устройства/сервисы
```

Наличие глобального IPv6-адреса у устройства не должно автоматически означать доступность устройства из интернета.

NAT66 не использовать по умолчанию. Он допускается только если позже появится конкретная техническая причина.

## Серверы и DNS

Статическая IPv4-схема VMID остаётся основной и не меняется:

```text
VMID XYZ → 10.0.X.YZ/16
```

IPv6 выдаётся серверу дополнительно. Жёстко кодировать VMID в глобальный IPv6 заранее не требуется, поскольку делегированный провайдером префикс может быть динамическим.

При включённом dual stack внутренний DNS может публиковать оба типа записей:

```text
A     → IPv4
AAAA  → IPv6
```

Клиенты используют IPv6, когда оно доступно и исправно, сохраняя возможность работы по IPv4.

## Remote-access VPN

Remote-access VPN должен в перспективе поддерживать dual stack:

```text
удалённый клиент
      ↓
WireGuard / AmneziaWG
      ↓
IPv4 + IPv6
      ↓
101-network-gateway
```

На первом этапе VPN может работать только по IPv4. Добавление IPv6 не должно быть условием запуска основной VPN-схемы.

## Этап внедрения

Сейчас:

- сохранить IPv4 как основной рабочий стек;
- не менять принятую адресацию `10.x.x.x`;
- учитывать IPv6 при проектировании `101-network-gateway` и firewall;
- не фиксировать публичный IPv6-префикс до проверки провайдера.

Позже, после получения параметров провайдера:

1. проверить DHCPv6-PD;
2. определить реально доступный размер делегированного префикса;
3. выделить отдельные `/64` для MAIN, IOT, CAMERAS и при необходимости REMOTE-VPN;
4. включить RA и IPv6 firewall;
5. проверить DNS, межсегментную маршрутизацию и VPN;
6. только после этого считать IPv6 рабочей частью домашней сети.
