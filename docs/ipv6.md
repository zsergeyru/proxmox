# IPv6

IPv6 вводится как второй стек параллельно с обязательной IPv4-архитектурой. IPv4 `10.x.x.x` остаётся основной management-схемой.

## Базовая модель

```text
IPv4 + IPv6 одновременно
```

Каждый L2-сегмент/VLAN получает собственный `/64`:

```text
MAIN          → отдельный /64
IOT / VLAN 20 → отдельный /64
CAMERAS / 30  → отдельный /64
REMOTE-VPN    → отдельный /64 при необходимости
```

Конкретные глобальные префиксы заранее не фиксируются.

## Требования к провайдеру

Перед включением IPv6 проверить:

- native IPv6;
- DHCPv6 Prefix Delegation;
- размер делегированного префикса;
- стабильность/динамичность префикса.

Предпочтителен `/56`; `/60` также достаточен для нескольких VLAN. Один `/64` неудобен для многосегментной сети.

## Роль OpenWrt

В принятой архитектуре базовый IPv6 L3 локальных VLAN принадлежит физическому edge-router/OpenWrt:

- получение DHCPv6-PD от провайдера;
- распределение отдельных `/64` по локальным сегментам;
- Router Advertisement;
- stateful IPv6 firewall;
- межсегментная маршрутизация по принятой firewall-политике.

Это соответствует IPv4-модели и не делает базовую сеть зависимой от Proxmox/VM 101.

## Роль 101-network-gateway

101 должен поддерживать IPv6 в пределах собственных функций:

- SmartDNS и AAAA;
- исходящие VPN/PBR;
- remote-access VPN;
- sing-box/proxy при необходимости;
- mDNS reflection, если выбранный механизм поддерживает нужные сегменты.

101 не получает DHCPv6-PD и не раздаёт RA локальным VLAN по умолчанию. Изменение этой границы требует отдельного ADR.

## Firewall и NAT

NAT66 по умолчанию не используется. Защита входящих IPv6-соединений обеспечивается stateful firewall на OpenWrt и локальными firewall-политиками сервисов.

Глобальный IPv6-адрес не означает автоматическую доступность устройства из интернета.

## Серверы и DNS

Статическая IPv4-схема сохраняется:

```text
VMID XYZ → 10.0.X.YZ/16
```

IPv6 добавляется отдельно. Кодировать VMID в глобальный IPv6 заранее не требуется.

DNS при dual stack публикует:

```text
A     → IPv4
AAAA  → IPv6
```

## Remote-access VPN

Основной remote-access VPN остаётся на `101-network-gateway`. На первом этапе он может быть только IPv4. IPv6 добавляется позже и не является условием запуска VPN.

## Порядок внедрения

1. проверить параметры IPv6 у провайдера;
2. настроить DHCPv6-PD на OpenWrt;
3. выдать отдельный `/64` каждому VLAN;
4. включить RA и firewall;
5. проверить DNS AAAA и доступность сервисов;
6. при необходимости добавить IPv6 в VPN/PBR на 101;
7. выполнить проверку отказоустойчивости и убедиться, что перезапуск 101 не ломает базовый IPv6 L3 локальной сети.
