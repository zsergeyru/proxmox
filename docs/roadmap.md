# Roadmap

## Ближайшие задачи

1. Зафиксировать фактическую текущую конфигурацию Proxmox-хоста: версия, hostname, management IP, bridge, физический NIC, storage, swap и реально существующие VMID/CTID.
2. Зафиксировать существующий Home Assistant VM 100 как legacy-систему и отделить её от целевой схемы новых гостей.
3. Развернуть и проверить `101-network-gateway` с DNS, исходящими VPN, remote-access VPN, PBR и firewall, сохранив независимый аварийный доступ к Proxmox.
4. Реализовать переходную сетевую схему: текущая `192.168.0.0/16` остаётся рабочей, Keenetic получает будущий gateway `10.0.0.1/16`, а новые серверы сразу используют постоянные `10.0.x.x/16`.
5. Подготовить целевую `301-ai-control` на основе решений, проверенных на текущем bootstrap-узле `320-ai-control`, затем перенести управление и только после проверки выводить 320 из эксплуатации.
6. Определить startup/shutdown order и аварийный путь доступа, не зависящий от `101-network-gateway`.
7. Довести управление гостями через Proxmox MCP + SSH до повторяемого сценария с проверкой результата и безопасным развёртыванием `rootfs/`.
8. Выбрать VM/LXC для `501-frigate` после теста iGPU/OpenVINO.
9. Определить backup storage, retention и расписание, а также необходимость отдельного Proxmox Backup Server.
10. Проверить параметры IPv6 у провайдера новой квартиры: native IPv6, DHCPv6-PD, размер и стабильность префикса; после этого включать dual stack по плану из [`ipv6.md`](ipv6.md).
11. Переносить из `appart-rennovation` только эксплуатационные серверные сведения, не дублируя общий проект квартиры.

## Уже зафиксировано

- целевая VMID/CTID-схема и читаемое соответствие VMID → `10.0.X.YZ`;
- серверы размещаются в MAIN `10.0.0.0/16`, отдельный server VLAN пока не используется;
- IOT и CAMERAS изолируются отдельными VLAN;
- переходная схема `192.168.0.0/16` → `10.0.0.0/16` без массовой перенастройки серверов в день переезда;
- remote-access VPN как часть `101-network-gateway`;
- IPv6 как дополнительный dual-stack, а не замена IPv4;
- структура гостей `README.md + guest.yaml + rootfs/`;
- DevOps и обычные приложения разделены между `311-dev-services` и `321-app-services`;
- `320-ai-control` определён как bootstrap, а `301-ai-control` — как целевой control plane.

Статусы конкретных гостей ведутся в `guest.yaml` и при необходимости в `README.md`/`STATUS.md`. Актуальная нумерация VMID/CTID определяется только [`vmid-plan.md`](vmid-plan.md).
