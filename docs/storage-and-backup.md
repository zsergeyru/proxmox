# Storage и резервное копирование

## Принципы

- snapshot не считается заменой полноценного backup;
- перед рискованными изменениями создавать snapshot/backup по ситуации;
- отдельно сохранять конфигурации Home Assistant, Docker Compose, persistent data, сетевую конфигурацию и данные Git-сервисов;
- storage для Frigate и backup не смешивать без контроля retention и свободного места;
- секреты и backup не хранить в открытом Git.

## Принятое временное решение

На ближайшем этапе основным внешним местом для Proxmox backup планируется обычный компьютер с выделенной SMB/CIFS-папкой.

Схема:

```text
Proxmox
  ├── SMB/CIFS → папка на отдельном компьютере — основная внешняя копия
  └── USB storage `backup`                — дополнительная локальная копия
```

Это решение считается временным и не означает, что SMB storage уже настроен на Proxmox.

Для компьютера с SMB-папкой требуется:

- стабильный IP-адрес;
- отдельная папка для Proxmox backup;
- отдельная учётная запись с правами только на эту папку, если это практически удобно;
- компьютер должен быть включён и доступен по сети во время запланированного backup.

Текущий USB storage сохраняется как дополнительная копия и аварийный вариант. Его фактический automount после перезагрузки Proxmox всё ещё нужно проверить отдельно.

Отдельный NAS и Proxmox Backup Server на этом этапе не вводятся. К PBS можно вернуться позднее, если появится необходимость в дедупликации, более развитом retention, проверке backup и централизованном хранении.

## Открытые вопросы

- настроить и проверить SMB/CIFS storage на компьютере;
- определить расписание backup;
- определить retention отдельно для SMB и USB;
- определить обязательный набор VM/LXC и persistent data;
- выполнить практический тест восстановления из backup;
- проверить восстановление USB storage после reboot;
- позднее решить, нужен ли отдельный NAS или Proxmox Backup Server.
