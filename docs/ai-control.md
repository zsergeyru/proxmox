# AI Control — архитектурные принципы

`ai-control` — отдельная VM управляющего контура. Она не является местом для общих сервисов вроде DNS, Home Assistant, Whisper/TTS или Frigate.

## Назначение

AI-агент должен управлять инфраструктурой через специализированные инструменты:

- Proxmox — через API/MCP;
- Docker — через `deploy-mcp`;
- команды внутри VM/LXC — через SSH, guest agent, `pct exec` или отдельный guest-management слой;
- Home Assistant — через HA API/инструменты;
- сеть — через отдельный управляемый контур.

Локальный Terminal Hermes — терминал контейнера Hermes, а не Proxmox-хоста и не произвольной VM/LXC.

## Границы безопасности

- Hermes не получает Docker socket напрямую.
- Секреты не должны быть доступны Hermes как обычные файлы.
- Критичные сервисы помечаются как protected и не должны изменяться агентом через обычный deploy lifecycle.
- Опасные изменения Proxmox, сети, storage и management-доступа требуют более строгого режима и rollback.
- Повторяемые изменения должны фиксироваться в Git.

## Разделение AI-сервисов

Whisper/STT и TTS размещаются отдельно в `330-ai-services`, чтобы ими могли пользоваться Hermes, Home Assistant, голосовые панели и другие приложения независимо от состояния `ai-control`.

## Длинные задачи

Для состояния конкретного сервиса используется `STATUS.md`, постоянные правила поведения агента хранятся в `AGENTS.md`, а долговечные факты — отдельно от истории сессии.

Подробная текущая документация и история решений находятся в [`../guests/320-ai-control/README.md`](../guests/320-ai-control/README.md).
