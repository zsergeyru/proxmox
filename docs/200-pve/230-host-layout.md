**Тип:** справочник  
**Статус:** действующий

## 1. Назначение документа

### 1.1. Что описывается

Документ описывает локальную структуру проекта на PVE-хосте.

Здесь фиксируются:

- основные каталоги проекта;
- назначение каждого каталога;
- служебные файлы;
- локальное состояние;
- исполняемые сценарии;
- службы и таймеры systemd;
- места размещения данных доступа и доверия на уровне файловой системы;
- временные данные и блокировки.

Документ не определяет правила выдачи прав, жизненный цикл ключей, политику секретов или эксплуатационные процедуры. Для таких тем используются отдельные профильные документы.

### 1.2. Общие принципы размещения

Структура PVE-хоста должна быть предсказуемой и разделять данные по назначению.

Основные принципы:

- исходный код и локальная копия Git-репозитория не смешиваются с изменяемым локальным состоянием;
- постоянная конфигурация отделяется от временных данных;
- секреты и закрытые ключи не хранятся внутри локальной копии Git-репозитория;
- служебное состояние конкретного механизма располагается отдельно от исходного кода;
- временные блокировки и временные данные выполнения не должны использоваться как постоянное состояние;
- каждый каталог должен иметь понятного владельца и назначение.

Точные пути считаются частью технического контракта PVE-хоста и должны изменяться только осознанно.

## 2. Структура каталогов PVE-хоста

### 2.1. Репозиторий проекта

На PVE-хосте существует локальная копия основного Git-репозитория проекта.

Он используется для:

- получения сценариев;
- чтения конфигурации;
- запуска управляемых операций;
- обновления проектного кода.

Локальная копия Git-репозитория является воспроизводимой копией проекта и не должна становиться основным местом хранения изменяемого локального состояния или секретов.

### 2.2. Конфигурация

Постоянная локальная конфигурация размещается отдельно от локальной копии Git-репозитория, если она:

- относится к конкретному PVE-хосту;
- содержит данные, которые нельзя хранить в Git;
- создаётся в процессе первоначальной подготовки или последующей настройки;
- требуется локальным служебным компонентам.

Конфигурационные каталоги должны содержать только данные конфигурации, а не журналы, временные файлы или рабочие копии репозитория.

### 2.3. Служебное состояние

Изменяемое состояние средств управления хранится отдельно от конфигурации и исходного кода.

К нему могут относиться:

- сведения о завершённых этапах;
- локальные реестры;
- технические метаданные;
- данные синхронизации;
- информация, необходимая для безопасного повторного запуска;
- другие данные, которые изменяются во время работы.

Служебное состояние должно переживать перезагрузку, если без него невозможно корректно определить состояние механизма управления.

### 2.4. Исполняемые сценарии и команды

Команды и сценарии проекта, которые должны быть доступны как локальные административные инструменты, размещаются отдельно от изменяемого состояния.

Для каждого такого компонента должно быть понятно:

- откуда он устанавливается;
- является ли он копией файла из Git или создаётся отдельно;
- кто его запускает;
- требуется ли ему локальная конфигурация или служебное состояние.

Исполняемые файлы не должны содержать встроенные секреты.

### 2.5. Временные данные и блокировки

Временные данные используются только на время выполнения операций.

К ним относятся:

- блокировки;
- временные рабочие файлы;
- промежуточные результаты;
- временные данные выполнения;
- временные маркеры процессов.

Они не должны использоваться как единственный источник состояния, который необходимо сохранить после перезагрузки или сбоя.

Постоянное служебное состояние и временные данные должны быть разделены.

## 3. Служебные компоненты

### 3.1. Конфигурационные файлы

Конфигурационный файл должен находиться в каталоге, соответствующем его владельцу и назначению.

В этом документе фиксируется его расположение и краткая роль.

Смысл параметров и правила их изменения описываются в профильной спецификации, а не дублируются здесь.

### 3.2. Реестры и метаданные

Локальные реестры и метаданные используются механизмами проекта для хранения технического состояния.

К ним могут относиться:

- реестры управляемых объектов;
- версии локальной структуры;
- результаты регистрации;
- данные, необходимые для синхронизации;
- другие служебные сведения.

Такие файлы не считаются пользовательской конфигурацией и не должны редактироваться вручную без отдельного правила.

### 3.3. Службы и таймеры systemd

Если компонент проекта должен работать как системная служба или запускаться по расписанию, соответствующие файлы служб и таймеров размещаются в стандартной структуре systemd.

В этом документе фиксируется:

- имя службы;
- её назначение;
- связанный исполняемый файл;
- связанная локальная конфигурация;
- наличие таймера, если он используется.

Логика работы самого сервиса должна описываться в профильном документе.

### 3.4. Ключи и секреты

В структуре PVE необходимо фиксировать места хранения:

- открытых ключей;
- закрытых ключей;
- токенов;
- других локальных данных доверия.

Этот документ описывает только расположение на файловой системе.

Правила создания, выдачи, синхронизации, ротации и удаления ключей и секретов относятся к разделу безопасности.

Закрытые ключи и секреты не должны размещаться внутри локальной копии Git-репозитория.

## 4. Сводная карта размещения

По мере развития PVE-хоста этот раздел должен содержать актуальную карту локальной структуры.

Для каждого объекта указываются:

| Путь | Что хранится | Кто использует | Тип данных | Основной документ |
|---|---|---|---|---|
| Путь к локальной копии Git-репозитория | Копия репозитория проекта | Механизм первоначальной подготовки и средства управления | Воспроизводимые | Конфигурация PVE |
| Каталог локальной конфигурации | Настройки конкретного хоста | Служебные компоненты | Постоянные | Конфигурация PVE |
| Каталог служебного состояния | Реестры, метаданные и состояние операций | Средства управления | Постоянные изменяемые | Профильный документ компонента |
| Каталог локальных команд | Установленные административные команды проекта | Оператор и автоматизация | Воспроизводимые | Профильный документ компонента |
| Каталог временных данных | Блокировки и временные файлы выполнения | Выполняемые процессы | Временные | Профильный документ компонента |
| Каталог данных доступа | Ключи и другие локальные данные доверия | Средства доступа и автоматизация | Защищённые | Раздел безопасности |

Точные пути добавляются в эту таблицу по мере фиксации соответствующих компонентов проекта.

Таблица должна быть основным быстрым справочником по размещению данных на PVE-хосте и не должна превращаться в описание внутренней логики каждого компонента.
