## 1. Назначение документа

Документ является справочником по локальному контуру проекта на PVE-хосте.

Здесь фиксируются:

- постоянные каталоги и файлы;
- локальная каноническая копия Git-репозитория;
- служебное состояние;
- ключи, токены и локальные данные доверия на уровне файловой системы;
- установленные административные команды;
- временные данные и блокировки;
- локальные службы и периодические механизмы, если они существуют;
- основные объекты Proxmox, создаваемые и поддерживаемые проектом.

Документ не описывает:

- алгоритм первоначальной подготовки;
- полный контракт PVE Configuration;
- правила выдачи и ротации доступов;
- внутреннюю логику deploy-guest;
- эксплуатационные процедуры.

Эти темы находятся в профильных документах.

## 2. Общая структура PVE-хоста

Основной локальный контур проекта имеет следующую структуру:

```text
/etc/proxmox-deployer/
├── config.yaml
├── pve-root-ca.pem
├── ssh/
│   ├── github_proxmox_repo_ed25519
│   ├── github_proxmox_repo_ed25519.pub
│   ├── pve_guest_ed25519
│   ├── pve_guest_ed25519.pub
│   ├── config
│   └── known_hosts
└── secrets/
    ├── host-deploy.token
    └── ai-agent-infra.token

/var/lib/proxmox-deployer/
├── repo/
├── state/
│   ├── state.json
│   ├── version
│   ├── last-run.json
│   ├── last-revision
│   └── template-smoke.json
├── cache/
└── public-keys/
    ├── deployer.pub
    ├── <VMID>.pub
    └── management-authorized-keys

/var/lib/pvedeploy/
└── .ssh/
    └── known_hosts

/var/log/proxmox-deployer/
├── configure-pve.log
└── audit/

/var/backups/proxmox-configuration/
/var/backups/proxmox-secrets/

/usr/local/sbin/
├── pve-configuration-status
├── deploy-guest
└── sync-management-keys

/run/lock/
└── proxmox-orchestration.lock
```

Помимо файловой структуры проект управляет отдельными объектами Proxmox: пользователями, API-токенами, ролями, ACL, пулом `managed`, базовым шаблоном VMID `9000` и временной smoke-VM VMID `9099`.

## 3. Файлы и каталоги проекта

### 3.1. `/etc/proxmox-deployer/`

Каталог содержит постоянную локальную конфигурацию и защищённые данные доступа.

| Путь | Назначение | Владелец и группа | Права |
|---|---|---|---|
| `/etc/proxmox-deployer/` | Корень локальной конфигурации проекта | `root:root` | `0755` |
| `config.yaml` | Локальная конфигурация конкретного PVE-хоста | `root:root` | управляется PVE Configuration |
| `pve-root-ca.pem` | Копия публичного CA Proxmox для ограниченного локального контура | `root:pvedeploy` | `0640` |
| `ssh/` | SSH-идентичности и доверие | `root:pvedeploy` | `0750` |
| `secrets/` | Секреты локальных API-токенов | `root:pvedeploy` | `0710` |

`config.yaml` содержит локальный контракт хоста, включая репозиторий, ветку, путь к локальной копии, пул `managed`, PVE-идентичности и VMID базового шаблона.

### 3.2. SSH-данные

| Путь | Назначение | Владелец и группа | Права |
|---|---|---|---|
| `ssh/github_proxmox_repo_ed25519` | Закрытый read-only Deploy Key для GitHub | `root:root` | `0600` |
| `ssh/github_proxmox_repo_ed25519.pub` | Открытая часть Deploy Key | `root:root` | `0644` |
| `ssh/config` | SSH-конфигурация доступа к GitHub | `root:root` | `0600` |
| `ssh/known_hosts` | Доверие к GitHub SSH host key | `root:root` | `0644` |
| `ssh/pve_guest_ed25519` | Закрытый ключ управления гостевыми системами | `pvedeploy:pvedeploy` | `0600` |
| `ssh/pve_guest_ed25519.pub` | Открытая часть ключа управления гостями | `pvedeploy:pvedeploy` | `0644` |

GitHub и гостевые системы используют разные SSH-контуры и разные `known_hosts`.

### 3.3. Секреты API

| Путь | Связанная PVE-идентичность | Назначение | Владелец и группа | Права |
|---|---|---|---|---|
| `secrets/host-deploy.token` | `deployer@pve!host-deploy` | Прямое управление PVE и локальные средства развертывания | `root:pvedeploy` | `0640` |
| `secrets/ai-agent-infra.token` | `ai-agent@pve!infra` | Доступ AI Control к разрешённой области Proxmox | `root:root` | `0600` |

Файлы содержат локально сохранённые значения `token_id` и `token_secret`. Политика доступа и ротации определяется документацией раздела безопасности.

### 3.4. `/var/lib/proxmox-deployer/`

Это основной каталог постоянного служебного состояния проекта.

| Путь | Назначение | Владелец и группа | Права |
|---|---|---|---|
| `/var/lib/proxmox-deployer/` | Корень служебного состояния | `root:pvedeploy` | `0750` |
| `repo/` | Каноническая локальная копия `zsergeyru/proxmox` | `root:root` внутри доверенной границы | группа и остальные без записи |
| `state/` | Машинное состояние PVE Configuration | `root:pvedeploy` | `0750` |
| `cache/` | Изменяемый служебный кэш | `pvedeploy:pvedeploy` | `0750` |
| `public-keys/` | Реестр открытых управляющих ключей | `pvedeploy:pvedeploy` | `0750` |

Каталог `repo/` является доверенной локальной копией Git и не предназначен для ручного редактирования. Локальный drift блокирует управляемые операции, кроме явно разрешённых служебных Python-кэшей.

### 3.5. Состояние PVE Configuration

Основные файлы `/var/lib/proxmox-deployer/state/`:

| Файл | Назначение |
|---|---|
| `state.json` | Последнее машинное состояние PVE Configuration |
| `version` | Версия установленной PVE Configuration |
| `last-run.json` | Метаданные последнего запуска |
| `last-revision` | Git SHA ревизии, принятой как текущая |
| `template-smoke.json` | Состояние последней проверки полного клона базового шаблона |

Сохранённое состояние является снимком результата предыдущего запуска. Для проверки текущего фактического состояния используется `pve-configuration-status --check`.

### 3.6. Реестр управляющих SSH-ключей

Каталог `/var/lib/proxmox-deployer/public-keys/` содержит только открытые ключи.

| Файл | Назначение |
|---|---|
| `deployer.pub` | Канонический открытый ключ PVE для управления гостями |
| `<VMID>.pub` | Индивидуальный управляющий открытый ключ конкретного гостя |
| `management-authorized-keys` | Детерминированно собранный общий набор разрешённых управляющих ключей |

Закрытые ключи в этом каталоге храниться не должны.

### 3.7. `/var/lib/pvedeploy/`

Linux-пользователь локального контура имеет фиксированный контракт:

```text
user:  pvedeploy
group: pvedeploy
home:  /var/lib/pvedeploy
shell: /bin/bash
```

Каталог `/var/lib/pvedeploy/.ssh/` имеет владельца `pvedeploy:pvedeploy` и права `0700`.

`/var/lib/pvedeploy/.ssh/known_hosts` хранит SSH host keys управляемых VM/LXC и не используется для GitHub.

### 3.8. Журналы и аудит

| Путь | Назначение | Владелец и группа | Права |
|---|---|---|---|
| `/var/log/proxmox-deployer/` | Корень журналов проекта | `root:pvedeploy` | `0750` |
| `configure-pve.log` | Журнал выполнения PVE Configuration | локальный системный журнал проекта | внутри защищённого каталога |
| `audit/` | Структурированный аудит служебных операций | `pvedeploy:pvedeploy` | `0750` |

### 3.9. Локальные резервные каталоги

| Путь | Назначение | Владелец и группа | Права |
|---|---|---|---|
| `/var/backups/proxmox-configuration/` | Локальные резервные копии конфигурации | `root:root` | `0700` |
| `/var/backups/proxmox-secrets/` | Локальные резервные копии защищённых данных | `root:root` | `0700` |

Эти каталоги являются частью локальной структуры PVE-хоста, но не заменяют общую политику резервного копирования и восстановления.

### 3.10. Временные данные и блокировки

Общая блокировка управляемых операций:

```text
/run/lock/proxmox-orchestration.lock
```

Её совместно используют Public Bootstrap, PVE Configuration, `deploy-guest` и `sync-management-keys`, чтобы исключить параллельное изменение общего состояния.

Временные файлы, создаваемые через `mktemp`, не являются постоянным состоянием проекта.

## 4. Локальные команды

PVE Configuration устанавливает стабильные административные интерфейсы в `/usr/local/sbin/`.

| Команда | Путь | Запуск | Назначение |
|---|---|---|---|
| `pve-configuration-status` | `/usr/local/sbin/pve-configuration-status` | root / оператор | Просмотр сохранённого состояния и фактическая read-only проверка PVE-хоста |
| `deploy-guest` | `/usr/local/sbin/deploy-guest` | только root | Управляемое развертывание VM/LXC по контракту проекта |
| `sync-management-keys` | `/usr/local/sbin/sync-management-keys` | только root | Синхронизация управляющих SSH-ключей с гостевыми системами |

`deploy-guest` и `sync-management-keys` являются локальными обёртками над исходным кодом из доверенной копии `/var/lib/proxmox-deployer/repo/`.

`pve-configuration-status` устанавливается PVE Configuration как отдельная локальная команда.

## 5. Локальные службы и периодические механизмы

На текущем этапе PVE Configuration не устанавливает обязательные собственные systemd service или timer для проекта.

Основные операции запускаются явно:

- Public Bootstrap;
- PVE Configuration;
- `pve-configuration-status`;
- `deploy-guest`;
- `sync-management-keys`.

Если в дальнейшем появится постоянная служба или периодическая задача проекта, её имя, путь к unit-файлу, исполняемый компонент и назначение должны быть добавлены в этот раздел.

Системные службы самого Proxmox не перечисляются здесь, если проект не создаёт и не изменяет их как часть собственного контракта.

## 6. Объекты Proxmox, управляемые проектом

Эти объекты не являются обычными файлами проекта, но входят в локальную структуру управляемого PVE-хоста.

### 6.1. Пользователи и API-токены

| Тип | Идентификатор | Назначение |
|---|---|---|
| PVE user | `deployer@pve` | Прямое управление PVE и локальные средства развертывания |
| API token | `deployer@pve!host-deploy` | Токен прямого управления PVE |
| PVE user | `ai-agent@pve` | Идентичность AI Control |
| API token | `ai-agent@pve!infra` | Ограниченный инфраструктурный токен AI Control |

Оба API-токена создаются с `privsep=1`.

### 6.2. Роли Proxmox

Проект поддерживает следующие роли:

| Роль | Назначение |
|---|---|
| `AICloneSource` | Доступ к чтению и клонированию источника |
| `AIManagedGuest` | Управление жизненным циклом и конфигурацией разрешённых VM/LXC |
| `AINetworkUse` | Использование разрешённой сети |
| `AIStorage` | Использование разрешённых хранилищ |
| `AIManagedPool` | Работа с управляемым пулом |

Полный состав привилегий и ACL относится к документации безопасности и конфигурации PVE.

### 6.3. Пул `managed`

`managed` — рабочая зона автоматизации проекта Proxmox.

AI Control изменяет только объекты, находящиеся в разрешённой ему области, а `deployer` используется для более широких операций прямого развертывания.

### 6.4. Хранилища и сеть

Проект использует существующие объекты Proxmox:

- `local`;
- `local-lvm`;
- сетевой мост `vmbr0`.

Проект проверяет их доступность и выдаёт необходимое право использования своим PVE-идентичностям, но не рассматривает их как собственные каталоги проекта.

### 6.5. Базовый шаблон

Канонический базовый шаблон:

```text
VMID: 9000
name: tpl-debian13
```

Он создаётся и проверяется PVE Configuration и используется как источник для развертывания гостевых систем.

### 6.6. Smoke VM

Для проверки полного клона используется:

```text
VMID: 9099
```

Это временный объект. После успешной проверки он удаляется и VMID снова становится свободным.

Если проверка прервана или выявлена ошибка, подозрительная smoke-VM может быть намеренно оставлена для диагностики и не удаляется автоматически без подтверждения её происхождения.
