# Постоянное состояние PVE-хоста

**Тип:** спецификация  
**Статус:** проектируется  
**Назначение:** зафиксировать минимальное постоянное состояние самого PVE после переноса развёртывания в `910 infra-deployer`.

## 1. Основной принцип

PVE должен оставаться максимально близким к штатной установке Proxmox VE.

Проект не размещает на PVE постоянный собственный движок развёртывания, закрытый Git-репозиторий или набор инфраструктурных инструментов.

Постоянная проектная схема:

```text
PVE
├─ штатная конфигурация Proxmox
├─ минимальная основа bootstrap
└─ 910 infra-deployer
```

## 2. Обязательное состояние

### 2.1. Системная основа

Должны быть доступны:

- поддерживаемый Proxmox VE;
- рабочая политика APT-репозиториев;
- DNS и исходящий сетевой доступ;
- корректное системное время;
- KVM;
- команды Proxmox, необходимые bootstrap.

Обычная проверка не выполняет полное обновление Debian/Proxmox.

### 2.2. Сеть

На PVE должен существовать основной мост:

```text
vmbr0
```

Имя PVE-узла должно однозначно разрешаться в локальный адрес самого узла.

Общая сетевая архитектура относится к профильному сетевому разделу.

### 2.3. Хранилища

Минимально используются:

```text
local
local-lvm
```

`local` должен позволять хранить LXC templates, необходимые bootstrap.

`local-lvm` используется для root disk `910` и обычных дисков гостей по правилам гостевого контура.

### 2.4. Debian LXC template

На PVE должен быть доступен Debian 13 standard LXC template, достаточный для создания `910`.

Его получение относится к bootstrap.

Это не то же самое, что VM template `9000`: VM template собирается позже из `910` через Packer.

### 2.5. 910 infra-deployer

На PVE должен существовать специальный постоянный LXC:

```text
VMID 910
name infra-deployer
```

Его точные машинные параметры задаёт публичный `zsergeyru/proxmox-bootstrap`; закрытый проект хранит только документацию конкретного гостя.

### 2.6. PVE API identity

Для `910` должна существовать отдельная техническая идентичность:

```text
infra-deployer@pve!automation
```

Она имеет только необходимые права работы с управляемой инфраструктурой и не получает административных прав на сам PVE и модель доступа.

Точные роли и ACL относятся к разделу безопасности.

### 2.7. Управляемая область

Для обычных гостей может использоваться PVE pool:

```text
managed
```

`910` в этот пул не входит.

Пул и права на него относятся к модели доступа Proxmox.

## 3. Чего на PVE быть не должно как обязательной части проекта

Новая архитектура не требует постоянных объектов:

```text
/etc/proxmox-deployer/
/var/lib/proxmox-deployer/
/var/lib/pvedeploy/
/var/log/proxmox-deployer/

pvedeploy
deploy-guest
sync-management-keys
pve-configuration-status
```

Также не требуется постоянная закрытая Git-копия проекта или GitHub Deploy Key проекта на PVE.

Если такие элементы остались от старой реализации, они рассматриваются как наследие и удаляются отдельной осознанной операцией после перехода.

## 4. Источник требуемого состояния

Для самого PVE источником контракта являются документы проекта и публичный bootstrap.

Фактическое состояние объектов Proxmox читается непосредственно из PVE.

OpenTofu внутри `910` не управляет:

- самим физическим PVE;
- объектом `910`;
- собственной PVE-идентичностью `910`;
- базовой конфигурацией APT PVE.

## 5. Проверка

Проверка PVE должна работать без изменения состояния и подтверждать как минимум:

- версию PVE;
- KVM;
- hostname;
- `vmbr0`;
- `local` и `local-lvm`;
- наличие подходящего Debian 13 LXC template;
- существование и признаки принадлежности `910`;
- `protection=1` у `910`;
- наличие технической PVE-идентичности;
- отсутствие у неё запрещённых административных прав.

Проверка обычного состояния гостей, OpenTofu state, Semaphore и Ansible относится к `910` и эксплуатационному контуру.

## 6. Повторное применение

Повторный bootstrap:

- создаёт только отсутствующие однозначно безопасные элементы своего контракта;
- повторно использует корректное состояние;
- не пересоздаёт `910`;
- не ротирует секреты без явной причины;
- останавливается при неизвестном или неоднозначном состоянии.
