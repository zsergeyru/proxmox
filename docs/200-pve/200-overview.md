# Обзор PVE-хоста

**Тип:** обзор  
**Статус:** проектируется  
**Назначение:** описать роль PVE-хоста после переноса постоянного развёртывания в `910 infra-deployer`.

## 1. Роль PVE

PVE является платформой виртуализации проекта и владельцем фактического состояния VM/LXC, хранилищ, виртуальных сетей, пользователей, ролей и ACL Proxmox.

На самом PVE остаётся только минимальная проектная логика, необходимая для создания и восстановления `910 infra-deployer`.

Основная схема:

```text
чистый PVE
→ bootstrap-pve.sh
→ 910 infra-deployer
→ OpenTofu / Ansible / Packer / Semaphore
→ остальные VM/LXC
```

## 2. Что остаётся на PVE

На PVE должны оставаться:

- Proxmox VE и его штатная конфигурация;
- `vmbr0` и используемые storage;
- Debian LXC template, необходимый для создания `910`;
- PVE-идентичность `infra-deployer@pve!automation`;
- проектные роли и ACL, необходимые этой идентичности;
- `910 infra-deployer`;
- локальные резервные копии критичной конфигурации bootstrap;
- временная блокировка bootstrap во время выполнения.

На PVE не требуются:

- постоянная Git-копия `zsergeyru/proxmox`;
- GitHub Deploy Key закрытого проекта;
- пользователь `pvedeploy`;
- `deploy-guest`;
- `sync-management-keys`;
- отдельный механизм `PVE Configuration`;
- собственные `state.json`, `last-run.json` и `last-revision` проекта.

## 3. Роль bootstrap

Публичный `bootstrap-pve.sh` является единственным проектным механизмом, который работает непосредственно на PVE от `root`.

Он не управляет обычными гостями. Его область ограничена:

```text
PVE minimum
+
910 infra-deployer
```

Точный контракт описан в [`210-host-bootstrap.md`](210-host-bootstrap.md).

## 4. Роль 910

`910 infra-deployer` — постоянный специальный LXC, который не входит в собственное OpenTofu state.

В нём находятся Semaphore и инфраструктурный исполнитель с OpenTofu, Ansible и Packer.

Именно `910` получает закрытый Git-репозиторий, инфраструктурные секреты и ограниченный PVE API token.

Описание конкретного гостя находится в [`../../guests/910-infra-deployer/README.md`](../../guests/910-infra-deployer/README.md), а его машинные параметры — в [`../../guests/910-infra-deployer/bootstrap.yaml`](../../guests/910-infra-deployer/bootstrap.yaml).

## 5. Граница с обычными гостями

Обычные VM/LXC описываются в `guests/` и управляются через OpenTofu из `910`.

Повторяемая настройка Linux внутри них выполняется Ansible.

Шаблон Debian VM `9000` собирается Packer из `910` и не является частью bootstrap.

Сам `910` является исключением: его объектом Proxmox владеет только bootstrap.

## 6. Безопасность

`910` не получает root SSH на PVE и не должен иметь права менять пользователей, роли и ACL Proxmox или собственный API token.

PVE создаёт техническую идентичность для `910`, а её секрет передаётся внутрь контейнера только при первоначальной подготовке или явном восстановлении.

Отдельный AI-контур остаётся независимым от разворачивателя.

## 7. Жизненный цикл

```text
установка PVE
→ bootstrap
→ создание 910
→ передача управления 910
→ штатная эксплуатация
```

Повторный bootstrap в нормальном состоянии только проверяет основу и `910` и по возможности ничего не меняет.

Полная потеря `910` обрабатывается отдельным режимом восстановления.
