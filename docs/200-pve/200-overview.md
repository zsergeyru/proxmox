## 1. Роль PVE

PVE остаётся платформой виртуализации. Он запускает VM и LXC, предоставляет сеть и хранилища и хранит фактическое состояние объектов Proxmox.

Постоянные средства развёртывания не устанавливаются на сам PVE. Для этого существует специальный LXC `910 infra-manager`.

Общая схема:

```text
PVE
→ первоначальная подготовка
→ 910 infra-manager
→ управление остальной инфраструктурой
```

## 2. Основные части

В разделе есть три разные области ответственности.

**PVE** хранит объекты Proxmox и постоянные данные, без которых нельзя восстановить управляющий контур.

**990 bootstrap-runner** — временный LXC. Он нужен только тогда, когда `910 infra-manager` ещё не существует или создаётся заново.

**910 infra-manager** — постоянный управляющий LXC. В нём работают Semaphore, OpenTofu, Ansible, Packer, OpenBao и служебный код проекта.

Прикладные службы домашней инфраструктуры в 910 не размещаются.

## 3. Первоначальное создание управляющего контура

Управляющий LXC не может создать сам себя. Поэтому первоначальная подготовка использует временный 990.

Он получает только необходимые временные доступы, создаёт 910 общим механизмом развёртывания и применяет к нему ту же модель настройки, которая используется для остальных Linux-гостей.

После подтверждения готовности 910 временный контейнер и его временные полномочия удаляются.

Объект 910 при этом не включается в постоянное состояние OpenTofu самого 910.

## 4. Штатная работа

После первоначального создания вся обычная работа выполняется из 910.

Из него:

- создаются и изменяются управляемые VM и LXC;
- запускаются задания Semaphore;
- применяется OpenTofu;
- выполняется Ansible;
- собираются базовые шаблоны;
- поддерживается OpenBao и инфраструктурные доступы.

Сам объект Proxmox для 910 остаётся за пределами его собственного постоянного состояния OpenTofu.

## 5. Что сохраняется на PVE

PVE хранит не только объекты Proxmox, но и данные, необходимые для восстановления 910.

Они разделены по уровню доступа:

- данные только для PVE;
- данные PVE, которые 910 может читать;
- постоянное состояние сервисов 910, которое 910 может изменять.

Такое разделение позволяет уничтожить и заново создать корневую файловую систему 910, не потеряв уникальное состояние управляющего контура.

Точные пути и состав каталогов находятся в справочнике структуры PVE-хоста.

## 6. Границы ответственности

На PVE не работают Semaphore, OpenTofu, Ansible, Packer и Docker как постоянный проектный контур.

На стороне PVE остаются только узкие служебные операции, которым необходимы полномочия самого хоста или доступ к данным, намеренно скрытым от 910. Они не образуют отдельную систему развёртывания.

910 является доверенным административным контуром PVE, но его доступы не передаются прикладным гостям или AI Control.

Пошаговые действия оператора относятся к эксплуатационной документации. Правила доступа относятся к разделу безопасности. Точные параметры самого 910 хранятся в его машинных описаниях и паспорте гостя.
