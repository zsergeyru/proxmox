## 1. Назначение PVE-хоста

### 1.1. Роль хоста в проекте

PVE-хост является основой серверной части проекта.

На нём работает Proxmox VE, который предоставляет среду для размещения и управления виртуальными машинами и LXC-контейнерами.

Хост также содержит локальные компоненты проекта, необходимые для подготовки, конфигурации и управления самой платформой Proxmox.

### 1.2. Что относится к PVE-хосту

К PVE-хосту относятся:

- установленная операционная система хоста;
- Proxmox VE;
- локальная конфигурация самого хоста;
- компоненты проекта, работающие непосредственно на PVE;
- локальные служебные сценарии;
- локальное служебное состояние;
- подключение хранилищ;
- средства проверки и обслуживания самого хоста.

Эти элементы составляют управляемую среду PVE-хоста.

### 1.3. Что к нему не относится

К самому PVE-хосту не относятся:

- внутренняя конфигурация гостевых операционных систем;
- приложения внутри VM и LXC;
- прикладные Docker-контейнеры внутри гостей;
- физическая инфраструктура квартиры;
- самостоятельная логика DNS, VPN и маршрутизации, если она размещена в отдельной системе;
- резервные копии как отдельная область управления;
- прикладная автоматизация, которая работает за пределами самого хоста.

Эти темы рассматриваются в других разделах документации.

## 2. Основные части хоста

### 2.1. Proxmox VE

Proxmox VE является основной платформой виртуализации на хосте.

Он предоставляет:

- управление VM и LXC;
- управление виртуальными дисками;
- подключение сетевых интерфейсов;
- управление состоянием запуска;
- снимки;
- API и другие интерфейсы управления;
- базовые механизмы хранения конфигурации виртуализации.

Proxmox VE является центральной частью хоста, но не единственной частью проекта, размещённой на нём.

### 2.2. Локальная конфигурация проекта

На хосте присутствует локальная конфигурация, необходимая для работы компонентов проекта.

Она включает только те данные, которые должны находиться непосредственно на PVE и не могут или не должны существовать только в Git.

Подробно состав конфигурации и требования к её состоянию описываются отдельно.

### 2.3. Служебные сценарии и компоненты

На PVE могут размещаться служебные сценарии и компоненты, необходимые для:

- первоначальной подготовки хоста;
- применения конфигурации;
- проверки состояния;
- синхронизации служебных данных;
- выполнения ограниченных инфраструктурных операций.

Они относятся к инфраструктуре управления самим хостом, а не к прикладным сервисам.

### 2.4. Хранилища, подключённые к хосту

PVE использует хранилища для размещения данных виртуализации.

Через них могут быть доступны:

- виртуальные диски;
- файловые системы контейнеров;
- образы;
- шаблоны;
- снимки;
- другие данные, необходимые Proxmox.

Архитектура хранения и резервного копирования рассматривается отдельно.

### 2.5. Средства управления и проверки

Хост предоставляет точки управления и проверки состояния.

К ним относятся:

- административные интерфейсы Proxmox;
- API;
- локальные команды;
- служебные сценарии проекта;
- средства проверки полноты конфигурации.

Их задача — позволить понять текущее состояние хоста и безопасно применять изменения.

## 3. Как хост связан с остальной системой

### 3.1. Git

Git хранит воспроизводимое описание требуемого состояния проекта.

PVE-хост получает из него конфигурацию, сценарии и другие управляемые материалы, которые затем применяются локально.

Git и сам хост выполняют разные роли:

- Git хранит описание того, как должно быть;
- PVE хранит и исполняет фактическое состояние.

### 3.2. VM и LXC

Виртуальные машины и LXC-контейнеры работают на PVE-хосте, но считаются отдельными объектами системы.

Хост предоставляет им вычислительные ресурсы, виртуальные диски и сетевые подключения.

Внутреннее состояние гостевых операционных систем не является частью конфигурации самого PVE-хоста.

### 3.3. Средства развёртывания

Средства развёртывания используют PVE как платформу для создания и изменения гостевых систем.

Они взаимодействуют с хостом через предусмотренные интерфейсы и применяют требования, описанные в проекте.

Сам механизм развёртывания гостей относится к отдельному разделу документации.

### 3.4. AI Control и Ansible

AI Control может использовать интерфейсы PVE для разрешённых действий с инфраструктурой.

Ansible в основном работает с гостевыми системами после их создания и первоначальной подготовки.

Оба инструмента связаны с PVE, но не являются частью базовой конфигурации самого хоста.

### 3.5. Сеть, хранилища и безопасность

PVE-хост связан с несколькими инфраструктурными областями:

- сеть обеспечивает доступность хоста и гостевых систем;
- хранилища предоставляют место для данных виртуализации;
- безопасность определяет права и способы доступа;
- резервное копирование обеспечивает восстановление.

Эти области взаимодействуют с PVE, но описываются в собственных тематических разделах.

## 4. Жизненный цикл PVE-хоста

### 4.1. Чистая установка

Жизненный цикл начинается с установленного Proxmox VE без проектной конфигурации.

На этом этапе хост ещё не считается подготовленным для работы в рамках проекта.

### 4.2. Первоначальная подготовка

Далее выполняется bootstrap.

Он приводит чистый PVE к минимальному состоянию, необходимому для дальнейшего управляемого использования.

На этом этапе устанавливаются и создаются только те компоненты, которые нужны самому хосту и последующим средствам управления.

### 4.3. Применение конфигурации

После первоначальной подготовки к хосту применяется постоянная конфигурация проекта.

Она определяет, какие управляемые компоненты должны существовать и в каком состоянии.

Точное содержание этой конфигурации описывается отдельно.

### 4.4. Повторное обновление и проверка

Конфигурация должна допускать повторное применение.

Повторный запуск не должен без причины изменять уже корректно настроенный хост.

После изменений состояние проверяется, чтобы убедиться, что хост остаётся подготовленным и соответствует требованиям проекта.

### 4.5. Эксплуатация

После подготовки PVE-хост работает как постоянная инфраструктурная платформа.

В процессе эксплуатации:

- обновляется конфигурация;
- обновляются разрешённые компоненты;
- контролируется состояние;
- создаются и обслуживаются гостевые системы;
- выполняются необходимые инфраструктурные операции.

Подробные эксплуатационные процедуры относятся к отдельному разделу документации.

## 5. Границы раздела

### 5.1. Гостевые системы

Создание, параметры и жизненный цикл VM и LXC относятся к разделу гостевых систем.

В разделе PVE описывается только та часть, которая относится непосредственно к хосту.

### 5.2. Сеть

Адресация, DNS, VPN, маршрутизация и политика сетевого трафика относятся к сетевому разделу.

В документации PVE фиксируется только связь хоста с этими механизмами.

### 5.3. Хранилища и резервное копирование

Общая модель хранения данных, резервного копирования и восстановления описывается отдельно.

PVE-раздел описывает только использование этих ресурсов самим хостом.

### 5.4. Безопасность и доступ

Пользователи, роли, ACL, SSH-ключи, токены и секреты относятся к разделу безопасности.

В PVE-разделе упоминаются только необходимые точки взаимодействия с этими механизмами.

### 5.5. Эксплуатация и диагностика

Подробные процедуры диагностики, устранения неисправностей и текущего обслуживания относятся к эксплуатационной документации.

Раздел PVE определяет только требования к самому хосту и базовым механизмам его подготовки и конфигурации.
