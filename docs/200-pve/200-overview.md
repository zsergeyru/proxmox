## 1. Роль PVE

PVE запускает VM и LXC, управляет их ресурсами и предоставляет хранилища. Постоянный набор средств развёртывания работает не на гипервизоре, а в отдельном госте 910.

На PVE допускаются только небольшие средства, которым необходимы права хоста или доступ к закрытой области данных. Они не заменяют работу 910.

## 2. Три части управления

**PVE** — основа виртуализации и защищённое место хранения уникальных данных управляющего контура.

**910 infra-manager** — постоянный центр управления. Он развёртывает гостей, выполняет задания, обслуживает OpenBao, организует резервирование и обновляет самого себя. В нём разделены веб-панель, исполнитель инфраструктурных операций и независимый от Docker системный уровень завершения обновлений.

**990 bootstrap-runner** — временный установщик. Он создаёт 910 впервые или восстанавливает его системную часть после критического отказа; во всех остальных случаях не нужен. После работы временные права и контейнер удаляются.

Прикладные домашние службы размещаются в отдельных гостях, не внутри 910.

## 3. Первоначальное создание и восстановление

Управляющий гость не может самостоятельно существовать до своей установки. Первоначальный загрузчик создаёт временный 990, который получает проект, создаёт 910 по общим правилам гостей и проверяет его готовность.

При аварии сначала предпринимается безопасное исправление из 910. Если его системная часть уже непригодна, независимая команда PVE запускает временный 990 для пересоздания 910 с сохранением постоянных данных. Существующий 910 нельзя удалять до обязательных проверок.

## 4. Обычная работа

Из 910 создаются и изменяются гости, проверяется инфраструктура, выполняются задания и резервирование. Самообновление 910 завершается системной службой внутри этого же LXC даже после остановки заменяемых Docker-контейнеров.

Единая веб-панель и операторская команда используют общие правила действий, а не две независимые системы заданий. Semaphore не входит в целевое устройство управляющего контура.

990 не участвует в обычных обновлениях. Объект Proxmox самого 910 остаётся вне его постоянного состояния OpenTofu.

## 5. Постоянные данные

Уникальные данные 910 расположены на системном диске PVE в одном защищённом корне и разделены на три области:

- только для PVE;
- для чтения из 910;
- для изменения работающим 910.

Благодаря этому корневую файловую систему 910 можно пересоздать без уничтожения состояния OpenBao, OpenTofu и других невоспроизводимых данных. Но такое размещение не заменяет независимые резервные копии на отдельном SSD и NAS.
