# DNS и mDNS

**Тип:** Спецификация  
**Статус:** Действующий  
**Основной источник:** Да — для правил DNS, `home.arpa`, SmartDNS и mDNS в проекте.

Фактическое состояние DNS на работающем PVE хранится в [`../host/pve/network/README.md`](../host/pve/network/README.md), а не в этом документе.

## Основной внутренний DNS-домен

Для управляемых имён домашней инфраструктуры принят домен:

```text
home.arpa
```

Он используется для серверов, VM/LXC, Home Assistant, MQTT и других постоянных сервисов.

Примеры целевых имён:

```text
pve.home.arpa
ha.home.arpa
mqtt.home.arpa
apps.home.arpa
ai.home.arpa
```

Внутренний DNS должен публиковать стабильные записи для инфраструктуры и по возможности использовать имена вместо жёстко записанных IP-адресов. Это особенно важно во время перехода с `192.168.0.0/16` на `10.0.0.0/16` и при будущем одновременном использовании IPv4 и IPv6.

Для IPv4 используются записи `A`, для IPv6 после его включения — также `AAAA`.

## Принятая архитектура DNS

Основной DNS-сервис на `109-network-gateway` — **SmartDNS**.

Его роль:

- принимать DNS-запросы домашних клиентов;
- использовать несколько внешних DNS-серверов;
- поддерживать DoH/DoT;
- разделять домены по группам;
- при необходимости использовать разные группы внешних DNS через обычного провайдера или VPN;
- обслуживать внутренние имена `home.arpa` совместно с локальными и авторитетными записями.

Фактическая маршрутизация пользовательского трафика не должна выполняться самим DNS-сервисом. После разрешения имени выбор маршрута выполняется отдельным контуром:

```text
SmartDNS
   ↓
адреса назначения / наборы nftables
   ↓
nftables + fwmark
   ↓
ip rule / таблицы маршрутизации
   ├── обычный провайдер
   ├── AmneziaWG
   └── другие VPN и маршруты
```

Дополнительные компоненты:

- **AdGuard Home** — только необязательный интерфейс для статистики и фильтрации, если он понадобится; он не является основным DNS-движком;
- **sing-box** — используется точечно для прокси и сложных исходящих соединений, которые неудобно реализовывать обычной L3-маршрутизацией;
- **keen-pbr** внутри `109-network-gateway` не используется — серверная маршрутизация по правилам реализуется штатными средствами Linux.

Адреса сетевой VM следуют общей формуле VMID → IP:

```text
текущий:  192.168.1.9
целевой:  10.0.1.9
```

На текущем этапе клиенты, переведённые на новый DNS-контур, используют `192.168.1.9` как DNS-сервер. После миграции MAIN-сети постоянным адресом становится `10.0.1.9`.

## `home.arpa` и поисковый суффикс

`search home.arpa` на клиенте не создаёт DNS-зону сам по себе. Он означает только, что короткое имя, например:

```text
pve
```

может быть дополнено резолвером до:

```text
pve.home.arpa
```

если соответствующая DNS-запись существует.

После перехода DNS-функций на `109-network-gateway` SmartDNS и локальные/авторитетные записи должны обслуживать `home.arpa`.

## mDNS

mDNS используется параллельно с обычным DNS и не заменяет `home.arpa`.

Для mDNS используется специальный домен:

```text
.local
```

Примеры:

```text
ha.local
printer.local
esp32-bath.local
```

Целевая модель:

```text
home.arpa  → управляемые постоянные имена инфраструктуры
.local     → автоматическое обнаружение устройств через mDNS
```

Для Proxmox, Home Assistant, MQTT, серверов и других критичных сервисов основным механизмом должен быть обычный DNS в `home.arpa`. На mDNS не следует строить обязательные зависимости инфраструктуры.

## mDNS между VLAN

mDNS по умолчанию рассчитан на локальный L2-сегмент и обычно не маршрутизируется между MAIN, IOT и другими VLAN.

Целевая сеть имеет отдельные сегменты:

```text
MAIN              10.0.0.0/16
IOT / VLAN 20     10.20.0.0/16
CAMERAS / VLAN 30 10.30.0.0/16
```

Если Home Assistant или пользовательские устройства в MAIN должны автоматически находить mDNS-устройства в IOT, на `109-network-gateway` можно включить отражение mDNS между выбранными сегментами, например через Avahi или эквивалентный механизм.

Отражение должно включаться только между явно выбранными сегментами и с учётом межсетевого экрана. Не следует без необходимости распространять mDNS во все VLAN, особенно в CAMERAS.

Обычный DNS `home.arpa` при этом работает через L3-маршрутизацию и не требует отражения mDNS.

## VPN для удалённого доступа

Удалённые клиенты через `109-network-gateway` должны получать домашний DNS и разрешать имена `*.home.arpa`.

Основной DNS для удалённых клиентов — SmartDNS через адрес сетевого шлюза соответствующей туннельной сети.

mDNS через VPN не считается обязательной частью базовой архитектуры. Если позже понадобится удалённое обнаружение mDNS-устройств, это должно внедряться отдельно и осознанно.
