# IPv6

**Тип:** Политика  
**Статус:** Действующий  
**Основной источник:** Да — для политики IPv6, одновременного использования IPv4/IPv6 и границы ответственности OpenWrt ↔ `109-network-gateway`.

IPv6 вводится как второй сетевой стек параллельно с обязательной IPv4-архитектурой. IPv4 `10.x.x.x` остаётся основной схемой административной адресации.

## Базовая модель

```text
IPv4 + IPv6 одновременно
```

Каждый L2-сегмент/VLAN получает собственный `/64`:

```text
MAIN          → отдельный /64
IOT / VLAN 20 → отдельный /64
CAMERAS / 30  → отдельный /64
REMOTE-VPN    → отдельный /64 при необходимости
```

Конкретные глобальные префиксы заранее не фиксируются.

## Требования к провайдеру

Перед включением IPv6 проверить:

- прямую поддержку IPv6 без дополнительных туннелей;
- делегирование префикса через DHCPv6-PD;
- размер делегированного префикса;
- является ли префикс постоянным или меняется.

Предпочтителен `/56`; `/60` также достаточен для нескольких VLAN. Один `/64` неудобен для многосегментной сети.

## Роль OpenWrt

В принятой архитектуре базовая IPv6-маршрутизация локальных VLAN принадлежит физическому пограничному маршрутизатору OpenWrt:

- получение DHCPv6-PD от провайдера;
- распределение отдельных `/64` по локальным сегментам;
- объявления маршрутизатора RA;
- межсетевой экран IPv6 с отслеживанием состояния соединений;
- межсегментная маршрутизация по принятой политике межсетевого экрана.

Это соответствует IPv4-модели и не делает базовую сеть зависимой от Proxmox или VM `109`.

## Роль `109-network-gateway`

VM `109` должна поддерживать IPv6 в пределах собственных функций:

- SmartDNS и записи AAAA;
- исходящие VPN и PBR;
- VPN для удалённого доступа;
- sing-box и прокси при необходимости;
- отражение mDNS между выбранными сегментами, если используемый механизм это поддерживает.

VM `109` не получает DHCPv6-PD и по умолчанию не раздаёт RA локальным VLAN. Изменение этой границы требует отдельного ADR.

## Межсетевой экран и NAT

NAT66 по умолчанию не используется. Защита входящих IPv6-соединений обеспечивается межсетевым экраном OpenWrt с отслеживанием состояния соединений и локальными правилами сервисов.

Глобальный IPv6-адрес не означает автоматическую доступность устройства из интернета.

## Серверы и DNS

Статическая IPv4-схема сохраняется:

```text
VMID XYZ → 10.0.X.YZ/16
```

IPv6 добавляется отдельно. Кодировать VMID в глобальный IPv6 заранее не требуется.

DNS при одновременном использовании IPv4 и IPv6 публикует:

```text
A     → IPv4
AAAA  → IPv6
```

## VPN для удалённого доступа

Основной VPN для удалённого доступа остаётся на `109-network-gateway`. На первом этапе он может работать только по IPv4. IPv6 добавляется позже и не является условием запуска VPN.

## Порядок внедрения

1. проверить параметры IPv6 у провайдера;
2. настроить DHCPv6-PD на OpenWrt;
3. выдать отдельный `/64` каждому VLAN;
4. включить RA и межсетевой экран;
5. проверить записи AAAA и доступность сервисов;
6. при необходимости добавить IPv6 в VPN/PBR на VM `109`;
7. проверить отказоустойчивость и убедиться, что перезапуск `109` не ломает базовую IPv6-маршрутизацию локальной сети.
