# Базовый шаблон Debian 13 для Proxmox

Статус: **скрипт создания реализован**.

Этот шаблон предназначен как универсальная база для Linux VM в Proxmox. Из него создаются отдельные рабочие виртуальные машины, после чего в них устанавливаются только сервисы, соответствующие роли конкретной VM.

## 1. Назначение

Рабочее имя шаблона:

```text
tpl-debian13
```

Рабочий VMID:

```text
9000
```

Базовая ОС: **Debian 13 (Trixie)**.

Основной принцип: шаблон должен быть достаточно удобным для администрирования и восстановления, но не должен содержать прикладные сервисы конкретной VM.

Примеры использования:

```text
tpl-debian13
├── network-vm
├── docker-vm
├── gitea-vm
├── jenkins-vm
└── другие Linux VM
```

Для рабочих машин предпочтительно использовать **Full Clone**, чтобы VM не зависела от диска шаблона.

## 2. Базовые параметры

Планируемые параметры шаблона:

| Параметр | Значение |
|---|---|
| ОС | Debian 13 |
| CPU | 1 vCPU по умолчанию |
| CPU type | `host` |
| RAM | 1 GiB по умолчанию |
| Диск | 16 GiB по умолчанию |
| Контроллер диска | VirtIO SCSI Single |
| Сеть | VirtIO |
| Bridge | `vmbr0` |
| Cloud-Init | да |
| QEMU Guest Agent | да |
| SSH | да |
| Сеть шаблона | DHCP |
| Cloud-Init user | `debian` |

CPU, RAM, размер диска, hostname и IP задаются уже для конкретной VM после клонирования.

## 3. Базовые программы

Размеры ниже ориентировочные и показывают порядок занимаемого места самим установленным пакетом. Они **не являются размером загрузки и не включают все зависимости**. Часть пакетов и библиотек уже присутствует в базовой Debian-системе.

### 3.1. Интеграция с Proxmox и удалённое управление

| Пакет | Назначение | Ориентировочный размер |
|---|---|---:|
| `qemu-guest-agent` | Связь гостевой ОС с Proxmox: получение IP, корректный shutdown, freeze/thaw файловой системы и другие функции | ~3.7 MiB |
| `openssh-server` | Удалённое администрирование VM по SSH | ~3.4 MiB |
| `sudo` | Выполнение административных команд обычным пользователем | ~6.7 MiB |

### 3.2. Работа с файлами и конфигурацией

| Пакет | Назначение | Ориентировочный размер |
|---|---|---:|
| `git` | Клонирование и обновление Git-репозиториев, получение deploy/config файлов | ~49 MiB |
| `mc` | Midnight Commander — удобный двухпанельный файловый менеджер в терминале | ~1.6 MiB |
| `nano` | Простой текстовый редактор для конфигов | ~2.8 MiB |
| `tree` | Вывод структуры каталогов деревом | ~0.1 MiB |
| `acl` | Работа с расширенными правами доступа (`getfacl`, `setfacl`) | ~0.2 MiB |
| `bash-completion` | Автодополнение команд и параметров в Bash | ~2 MiB |

`vim` в обязательный набор не включается: для базового шаблона достаточно `nano` и редактора из `mc`. При необходимости `vim` ставится отдельно.

## 6. Сеть и DNS

| Пакет | Назначение | Ориентировочный размер |
|---|---|---:|
| `dnsutils` | Диагностика DNS: `dig`, `nslookup` и связанные утилиты | ~0.5 MiB + зависимости BIND |
| `iproute2` | Современные сетевые утилиты `ip`, `ss`, `tc` и др. | ~3.8 MiB |
| `iputils-ping` | Команда `ping` | ~0.2 MiB |

## 7. Архивирование и резервное копирование

| Пакет | Назначение | Ориентировочный размер |
|---|---|---:|
| `tar` | Создание и распаковка tar-архивов; обычно уже входит в базовую Debian-систему | ~3.1 MiB |
| `rsync` | Быстрая синхронизация и копирование каталогов, в том числе на удалённые машины | ~0.8 MiB |
| `restic` | Зашифрованные snapshot-backup, дедупликация, инкрементальные копии и восстановление файлов | ~24 MiB |
| `zstd` | Быстрое сжатие архивов, дампов и backup-файлов | ~2.3 MiB |
| `unzip` | Распаковка ZIP-архивов | ~0.4 MiB |

### Стратегия backup

Наличие `restic` внутри шаблона **не заменяет резервное копирование средствами Proxmox**.

Используем три уровня:

```text
1. Proxmox backup
   └── восстановление VM целиком

2. restic / rsync
   └── резервное копирование важных данных внутри VM

3. Git
   └── конфигурации, deploy-файлы, скрипты и инфраструктурный код
```

Основным способом восстановления всей VM остаётся backup на уровне Proxmox. `restic` и `rsync` нужны для независимого файлового резервного копирования важных данных.

Большая часть этого набора не создаёт постоянно работающих тяжёлых процессов. Основными постоянно работающими компонентами будут системные службы, `sshd` и `qemu-guest-agent`.

## 9. Что намеренно не входит в базовый шаблон

В базовый `tpl-debian13` **не устанавливаются**:

- Docker Engine;
- Docker Compose;
- SmartDNS;
- AdGuard Home;
- `sing-box`;
- AmneziaWG / другие VPN-клиенты;
- специальные правила `nftables` и policy routing;
- Gitea;
- Jenkins;
- базы данных;
- reverse proxy;
- любые сервисы, специфичные для конкретной VM.

Причина: базовый шаблон должен оставаться универсальным. В частности, Docker создаёт собственные bridge-интерфейсы, NAT/filter-правила и влияет на сетевую конфигурацию, что нежелательно для машин вроде `network-vm`.

## 10. Docker-шаблон

При необходимости поверх базового шаблона можно создать отдельный производный шаблон:

```text
tpl-debian13
        ↓
tpl-debian13-docker
        ↓
Docker-based VM
```

В `tpl-debian13-docker` уже устанавливаются Docker Engine и Docker Compose plugin. Это позволяет не ставить Docker на VM, которым он не нужен.

## 11. Правила шаблона

1. Не хранить в шаблоне реальные пароли, API-токены, приватные SSH-ключи и другие секреты.
2. Не назначать шаблону постоянный IP рабочей VM — в шаблоне использовать DHCP/Cloud-Init.
3. Перед превращением VM в template очистить machine-specific данные, которые не должны копироваться во все VM.
4. Рабочие VM создавать как Full Clone, если нет отдельной причины использовать Linked Clone.
5. При клонировании сразу задавать hostname, IP, CPU, RAM и необходимый размер диска.
6. Прикладные сервисы устанавливать уже после клонирования либо отдельной автоматизацией/скриптами из репозитория.
7. Параметры и скрипты создания шаблона должны храниться в Git; сам виртуальный диск шаблона в Git не хранится.

## 12. Скрипт создания шаблона

Скрипт находится здесь:

```text
templates/debian13/create-template.sh
```

Он выполняет полный цикл:

1. проверяет, что запущен от `root` на Proxmox VE;
2. проверяет VMID, storage и bridge;
3. скачивает актуальный Debian 13 `genericcloud` QCOW2;
4. скачивает `SHA512SUMS` и проверяет целостность образа;
5. обновляет пакеты внутри образа;
6. устанавливает весь базовый набор программ;
7. включает `qemu-guest-agent` и SSH;
8. очищает apt cache, cloud-init state, machine-id и SSH host keys;
9. сжимает и проверяет итоговый QCOW2;
10. создаёт VM в Proxmox;
11. импортирует системный диск;
12. увеличивает диск до 16 GiB по умолчанию;
13. подключает Cloud-Init;
14. задаёт DHCP и пользователя `debian`;
15. преобразует VM в Proxmox Template.

Скрипт **не перезаписывает существующий VMID**. Если `9000` уже занят, выполнение будет остановлено.

### 12.1. Build-зависимости на хосте Proxmox

Для изменения cloud image используется `virt-customize` из пакета `libguestfs-tools`.

Проверяемые build-зависимости:

```text
libguestfs-tools
dhcpcd-base
curl
qemu-img
sha512sum
```

`dhcpcd-base` нужен для корректной сети `virt-customize` на некоторых установках Proxmox VE 9. Это именно базовый пакет с бинарником, а не постоянно работающий DHCP-клиент `dhcpcd`.

По умолчанию скрипт **не устанавливает build-зависимости на Proxmox-хост автоматически**. Если они отсутствуют, он остановится и покажет команду установки.

Установить их вручную один раз:

```bash
apt-get update
apt-get install -y libguestfs-tools dhcpcd-base curl
```

Либо разрешить скрипту установить недостающие build-зависимости:

```bash
AUTO_INSTALL_BUILD_DEPS=1 ./templates/debian13/create-template.sh
```

## 13. Запуск

На Proxmox-хосте, если репозиторий уже клонирован:

```bash
cd /root/proxmox
git pull
./templates/debian13/create-template.sh
```

Значения по умолчанию:

```text
VMID=9000
VM_NAME=tpl-debian13
STORAGE=local-lvm
BRIDGE=vmbr0
CORES=1
MEMORY=1024
DISK_SIZE=16G
CIUSER=debian
TIMEZONE=Etc/UTC
```

Любое из них можно переопределить без изменения скрипта. Например:

```bash
STORAGE=local-zfs VMID=9100 DISK_SIZE=20G ./templates/debian13/create-template.sh
```

Если в конкретном Proxmox storage называется не `local-lvm`, нужно передать правильное имя через `STORAGE=...`. Список storage:

```bash
pvesm status
```

Рабочие файлы создаются во временном каталоге `/var/tmp/proxmox-debian13-template.*` и удаляются после успешной сборки. При ошибке каталог сохраняется для диагностики.

## 14. После создания

После успешного запуска в Proxmox появится:

```text
9000  tpl-debian13  [Template]
```

Пример создания полноценного независимого клона:

```bash
qm clone 9000 101 --name network-gateway --full 1
```

После клонирования необходимо задать параметры конкретной VM: CPU, RAM, hostname, IP/маршрутизацию, SSH key и размер диска при необходимости.

Следующий этап для проекта — использовать этот шаблон как основу для рабочих Linux VM и отдельно автоматизировать настройку каждой роли.
